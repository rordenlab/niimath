This file provides guidance for AI agents when working with code in this repository.

## Project Overview

niimath is an open-source clone of FSL's `fslmaths` — a general-purpose NIfTI image calculator for neuroimaging. It extends fslmaths with mesh generation (nii2mesh), extra filters, defacing (`-deface`), affine registration (`-allineate`), anatomical QC (`--qc`), zstd compression (.nii.zst), and cross-platform support (Linux, macOS, Windows, WebAssembly).

**Repository:** `rordenlab/niimath` (BSD-2-Clause license)

## Building

### Quick build (Makefile, recommended for development)
```bash
cd src && make          # Standard optimized build (OpenMP enabled by default)
make debug              # Debug build (-g, no optimization)
make ubsan              # UndefinedBehaviorSanitizer (lightweight; retains OpenMP)
make sanitize           # AddressSanitizer (serial on Apple Clang; no leak detection on macOS)
make verbose            # All warnings
make static             # Static binary
```

### Prerequisites
- **macOS**: `brew install libomp zstd`
- **Linux**: `apt install libzstd-dev` (OpenMP built-in with gcc)

### Build variants
```bash
make tiny               # Minimal terminal build (emulates WASM constraints)
make nano               # Without mesh (nii2mesh)
MESH=0 make             # Disable mesh support
AL=0 make               # Disable allineate registration
DTIFIT=0 make           # Disable dtifit
QC=0 make               # Disable anatomical QC (--qc)
ROMEO=0 make            # Disable ROMEO phase unwrapping (-romeo); implies MEDIC=0
MEDIC=0 make            # Disable MEDIC distortion correction (--medic, -unwarp)
GPL=1 make              # Enable optional GPL -spm_coreg (needs git submodule update --init src/GPL)
QWARP=1 make            # Enable -qwarp nonlinear registration; OFF by default; needs allineate (not with AL=0)
ZSTD=0 make             # Disable zstd (.nii.zst)
OMP=0 make              # Single-threaded build
MC=1 make               # New MarchingCubes algorithm (handles ambiguities)
STB=1 make              # STB image library instead of libspng for bitmaps
make wasm               # Emscripten/WebAssembly
make wasm-wasi          # Experimental zlib-free WASI compute backend (needs Zig)
make wasm-emcc-core     # Feature-matched zlib-free Emscripten build (WASI benchmark baseline)
```
zlib: CMake release builds default to zlib-ng (`ZLIB_IMPLEMENTATION=zlib-ng`); plain make uses system `-lz` (`ZLIBNG_ROOT=<path>` links compat zlib-ng without CMake; wasm uses `WASM_ZLIB`).

### CMake build
```bash
mkdir build && cd build && cmake .. && make     # top-level SuperBuild
cmake -DUSE_OPENMP=OFF -DENABLE_QC=OFF ..        # toggles (forwarded by SuperBuild)
```

### Key compile-time flags
- `NII2MESH` / `DNII2MESH` — mesh conversion
- `USE_CLASSIC_CUBES` — oldcubes.h (classic) vs MarchingCubes.h
- `HAVE_FORMATS` — GIfTI, OBJ, VTK, STL mesh output
- `HAVE_BMP` — bitmap/PNG creation
- `HAVE_BUTTERWORTH` — bandpass temporal filtering
- `HAVE_TENSOR` — tensor decomposition
- `HAVE_DTIFIT` — linear diffusion tensor fit (`--dtifit`); needs `HAVE_TENSOR`
- `HAVE_QC` — anatomical QC (`--qc`); no tensor/mesh deps
- `HAVE_ROMEO` — ROMEO phase unwrapping (`-romeo`, romeo.c); ON by default, `ROMEO=0` / `-DENABLE_ROMEO=OFF` disables. Built as a **prebuilt STRICT-FP object** with its own `.romeo_obj_flags` stamp — see the romeo.c entry below
- `HAVE_MEDIC` — MEDIC multi-echo distortion correction (`--medic`, `-unwarp`, medic.c); ON by default, `MEDIC=0` / `-DENABLE_MEDIC=OFF` disables. **Requires `HAVE_ROMEO`** — `ROMEO=0` silently implies `MEDIC=0` in the Makefile, and CMake hard-errors on `ENABLE_MEDIC=ON` with `ENABLE_ROMEO=OFF`. Ordinary FP (NOT a strict-FP object like romeo.c), so it rides the normal source line
- `HAVE_CONFORM` — image conforming to standard space
- `HAVE_ALLINEATE` — affine registration + defacing (allineate.c + powell_newuoa.c + coreg_fast.c + reface.c); release builds use whole-program `-ffast-math` + OpenMP. `reface.c` always compiled in an allineate build (no separate flag).
- `HAVE_QWARP` — `-qwarp` nonlinear registration (qwarp.c, attributed AFNI 3dQwarp port); OFF by default; `QWARP=1 make`; requires allineate/NEWUOA (not with `AL=0`).
- `HAVE_GPL` — optional GPL `-spm_coreg`/`-spm_deface`; OFF by default so builds stay BSD-2. `-spm_coreg` is canonical (`-spmcoreg` a silent alias). Sources in `niimath_gpl` submodule (`src/GPL`); `GPL=1 make` / `cmake -DENABLE_GPL=ON` / `GPL=1 make wasm` (needs `git submodule update --init src/GPL`). A `GPL=1` binary is a GPL-2 combined work (version string ends ` GPL` vs ` BSD`).
- `AL_LPC_MICHO` — adds lpc+ZZ/lpa+ZZ combined cost variant (default: pure lpc/lpa)
- `HAVE_ZSTD` — .nii.zst support (auto-detected; `FSLOUTPUTTYPE=NIFTI_ZST` to write)
- `FSLSTYLE` — FSL-compatible behavior mode

## Source Architecture

### Core computational pipeline
- **niimath.c** — CLI entry point; dispatches to `main32()`/`main64()` by `-dt`. `--dtifit`/`--qc` are self-contained subcommands dispatched before the op loop. Huge-image (>INT_MAX voxel) gate (issue #67): `main32`/`main64` admit a huge working image only for whitelisted ops (fail-closed) — see **Huge image support**.
- **coreFLT.c** (6k lines) — main computational engine, compiled twice via template pattern:
  - **core32.c** — `#define DT32` + include → float32 (SSE 4-wide on x86_64; scalar ARM/WASM)
  - **core64.c** — include without DT32 → float64 (SSE 2-wide on x86_64; scalar ARM/WASM)
  - **Filter kernels.** Gaussian smoothing (`smooth_gauss_blur1d`, used by `-s`/`-dog`/unsharp/registration) uses `blur_row`: a contiguous full-symmetric kernel (`kc[i]`, not `k[abs(i)]`), lane-parallel so clang auto-vectorizes (NEON; SIMD128 in `-msimd128` wasm). `-fmean`/`-fmeanu`, `-dilF`/`-eroF`, binary `-ero` recover kernel extents once, keep checked scalar gathers on borders, evaluate eight adjacent interior outputs per tap for contiguous SIMD loads. O(k³) with independent per-output state, preserving each op's local NaN/±Inf behavior. A separable box-filter experiment was removed (shared running sums / monotonic deques changed those semantics; archived in `noncompliant.md`) — do NOT restore without explicit non-finite conformance tests.
  - **`-dilate <thr> <dx>`** (distance-based grow, `nifti_dilate`, distinct from kernel `-dilF`): binarizes at `thr`, grows the mask by `dx` mm — voxels within `dx` of the surface set to at least `thr` via `fmax(iso, imgIn[i])` (matching `-close`'s fill, so a grown voxel survives a re-threshold at `iso`; `fmax(1.0,..)` is wrong for `iso>1`), beyond-`dx` voxels unchanged (grow-only).
- **core.c** — shared utilities: datatype conversion, kernel creation, Otsu thresholding, resampling filters, NIfTI I/O helpers. **`max_displacement_mm()` gotcha:** returns max corner displacement between two images' world transforms; gates the `-add`/binary-op and `--compare` orientation warnings (0.5 mm) and the `--qc` grid check (0.001 mm). It measures true 3D Euclidean distance AND normalises each transform to mm via `xyz_units` (`xyz_units_to_mm`) so metre/micron headers compare correctly; touch only with that unit scaling in mind.
- **unifize.c** — bias field correction (`-unifize`; adapted from AFNI 3dUnifize, public domain).
- **allineate.c** (~3.9k lines) — affine registration, defacing, skull-stripping. **Shared byte-identically with the standalone allineate project — canonical source; sync any change both ways** (see Shared-code invariant). Cost via `-cost` (Hellinger default, lpc/lpa/ls; `-DAL_LPC_MICHO` adds lpc+ZZ/lpa+ZZ); DOF via `-warp`; interpolation via `-interp`/`-final`. Twopass coarse-to-fine with a full-resolution AFNI-faithful random-startup coarse search and OpenMP-parallel candidate refinement using thread-local histogram/warp/workspace buffers (adapted from AFNI 3dAllineate, public domain) — this thread-local-cost-eval pattern is the template for any spm_coreg OpenMP work. `al_register()` is shared by `nii_allineate()`/`nii_deface()`; `nii_reslice_affine` + `nii_apply_deface_mask` are factored out and reused by `nii_deface` and GPL `-spm_coreg`/`-spm_deface` (interpolation lives once in BSD).
  - **`-deface` is the single mask-based removal command** — the supplied mask, not the command, determines what is removed (brain mask skull-strips, face mask defaces). Defaults to the fast engine (`-cost fast`, like `-allineate`); `-cost hel`/`lpc`/`lpa`/`ls` selects the ordinary AFNI-style engine; `-warp`/`-interp`/`-source_automask`/`-dark_automask` force the ordinary engine (rejected with an explicit `-cost fast`). Fast-deface removed-region Dice vs `-cost hel` ≈ 0.985–0.999 at ~15× speed — broad agreement, NOT byte-stable across builds.
  - **Registration direction (MUST):** register the SUBJECT onto the TEMPLATE (`al_register(input, tmpl)` ordinary; `coreg_fast_estimate(input, tmpl)` fast — base=template, the well-posed direction), then INVERT to pull the template-space mask onto the subject grid: ordinary via `GA_setup_affine`→`nifti_mat44_inverse`→`nii_reslice_affine`; fast passes `nifti_mat44_inverse(res.fixed_to_moving)` to `nii_apply_affine(mask, input, …)`. Registering a brain-only template ONTO a full-head subject (base=subject) converges to a mislocated transform and masks the wrong region — do NOT do it.
  - **`nii_deface` rejects 4D input** (`al_dims_ok`): the face mask covers one volume, so 4D would leave faces in volumes 2..N (privacy failure). **`-allineate`, by contrast, auto-crops a genuine 4D moving image to volume 0** (== `-crop 0 1`, with a warning) in `nifti_allineate_wrap` (after the `-applymat` early-return, so applymat still rejects 4D); a >4D vector/tensor moving image is rejected.
  - **`-fill auto|zero|nan`** (`-allineate` output reslice only, gated at parse time by `AL_CAP_FILL`; **rejected for `-deface`**, whose fill stays the image minimum for mask safety): `auto` (default) zero-fills unless the source's darkest finite voxel is <0 (CT/HU air ≈ -1000), then fills with that minimum so out-of-FOV reads as air not soft tissue (positive-only MRI output stays byte-identical to historical); `zero` always 0; `nan` NaN. Resolved by shared `al_resolve_fillv()` / `al_image_fillv()` (unscaled float32 scanned in place; scaled/non-float32 takes a converting `nii_to_float` copy so AUTO sees negative HU in raw int16 CT), both magnitude-guarded (TU is `-ffast-math`). Fused-warp path (`nii_allineate`/`al_scalar_warpone`) writes 0 then `al_fill_fused_oob()` rewrites only out-of-FOV voxels via the kernel's exact FOV predicate (no-op when fillv==0); `nii_apply_affine` paths (fast, `-master`, `-applymat`) pass the resolved fill directly. Options in `al_opts` (`allineate.h`).
- **coreg_fast.c/.h** — fast affine coreg engine (`-cost fast`/`fastx` → adaptive HEL/CR default; `-cost fasthel` → Hellinger/MI; `-cost fastcr` → correlation-ratio). Clean-room, NOT AFNI/GPL. **Shared with the standalone allineate project** (sync both ways). `coreg_fast_estimate()` does not mutate inputs — returns a world-mm FIXED→MOVING `mat44`; caller applies once. Cost reductions use fixed `CF_CR_NCHUNK=64` disjoint chunks in fixed order → deterministic per team size.
  - **Build gotcha:** coreFLT.c references `coreg_fast_estimate` unconditionally under `HAVE_ALLINEATE`, so every allineate-enabled build MUST link it (native `coreg_fast.o`, wasm `cf_wasm.o`, CMake `ADDITIONAL_SRCS`, notarize `AL_SRCS`). Blurs its pyramid via exported `nifti_smooth_gauss_f32`/`_f64`; multi-volume smoothing passes per-volume dims — **do NOT introduce shared `nx`/`ny`/`nz` here (4D OpenMP race).**
  - **Partial-FOV cost:** HEL/CR form statistics from the image INTERSECTION — out-of-FOV moving samples are excluded (`if(!ok) continue`), NOT filled with `m_bg` (else a partial-coverage moving image distorts toward scale/shear). A floor (`nin < 0.10*ns || nin < 16 → CF_PENALTY`) rejects degenerate tiny overlap; exclusion is inside each fixed chunk so determinism holds; LS keeps the `m_bg` fill.
  - **Initialization:** default/`-cmass` scores the supplied affine and exact-COM starts once at 8 mm, maximizing `(1-cost)×covered_fixed_foreground`, then runs only the winning descent; `-com` forces a recentered header, `-nocmass` forces the supplied affine. Translation guard ±128 mm.
  - **Contract:** fixed 12-DOF schedule; fail-closed rejects `-warp`/`-interp`/`-source_automask`/`-dark_automask`/`-zoom`. The `-com`/`-sym`/`-symd`/`-symb` header seeds ARE honored (dispatch applies them to the moving header before the branch, so `-cost fast -sym` is accepted). `-cost` last-one-wins; both-form-codes-zero input uses the shared pixdim-centered fallback.
  - **Reslice fill safety:** cubic reslicing clamps only in-FOV voxels (`nii_reslice_affine` inline; `al_scalar_warpone` via `al_clip_fused_cubic_infov`) so a positive-only source's out-of-FOV fill stays 0 — clamping it up to source min is a defacing mask-safety hazard.
  - **`-weight <img>` (AFNI-style graded base-space weight, BOTH engines):** optional base(fixed)-space region image (`coreg_fast_opts.weight`; ordinary `al_opts.weight` filename; parsed through shared `al_parse_subopts` under `AL_CAP_WEIGHT` — so `-allineate`/`-reface` accept it, `-deface` rejects it at parse time) whose dims AND world frame must match the base. Normalized to `[0,1]` (÷ max), GRADED per base voxel (weight 0 excluded, near 1 dominates); it is NOT a hard/exclusion mask. **Ordinary engine** (`al_load_user_weight`/`al_scalar_setup`): user weight REPLACES the manufactured autoweight and stays GRADED for EVERY cost including box-mode histogram costs — we never binarize a user `-weight` (only the manufactured autoweight is boxed). **Fast engine:** normalizes over the WHOLE fixed grid, applies the weight ONLY at the finest (2 mm, `lv==2`) level — 8 mm rigid capture, 4 mm global-scale bracket, and seed selection stay UNWEIGHTED/whole-head so a brain-concentrated weight cannot hijack global-scale SELECTION (else a scalp-shrink basin). HEL/CR scale-invariant so max-normalization makes the fit invariant to global weight scaling; **rejected with LS.** **Keep the out-of-ROI head attenuated (nonzero), not zeroed** — masking the cost to the ROI alone leaves global isotropic scale underdetermined (ill-conditioned scalp-shrink collapse). Negatives/NaN/+Inf clamp to 0 at full resolution before the blur; fast engine rejects a weight with no positive support over the fixed foreground (`wmax==0`); weight is sampled by fixed VOXEL INDEX (never resampled) so the 8-corner frame check uses a TIGHT header-rounding tolerance (~1/20 voxel), rejecting even a sub-half-voxel origin shift.
  - **niimath `-allineate` dispatch (`nifti_allineate_wrap`):** `-weight` honored by BOTH engines (ordinary loads via `al_load_user_weight`, fast into `cfo.weight`); preflighted for oversize (both), rejected for stdin (`-`) and with `-applymat`. `-reface` honors it too. When `-weight` is given and the DEFAULT fast engine fails, it DOES fall back to the ordinary Hellinger engine and the fallback HONORS the weight; an explicit `-cost fast`/`fastcr` never falls back. Provenance recorded in `-savemat` JSON (`"weight"` key, omitted when unweighted); unweighted leaves every fast cost ×1.0 → bit-identical to before.
- **Fast-engine multi-start / NMS invariants.** `cf_make_samples()` clears previous arrays/counts/accumulator before rebuilding; any degeneracy or partial-alloc failure leaves an empty consistent state, aborts every remaining strategy, skips winner polish, leaves `*result` unchanged (prevents a later hard-zero strategy combining stale `ns` with partial arrays). Standalone C-API harness fault-injects the 2nd allocation on sample-build call 4. Exploratory angular NMS repeatedly picks the global lowest cost (enumeration order breaks ties) and accepts only candidates ≥20° from every retained basin; non-positive/non-finite separation fails closed. Keep the bounded comparator-free scan for WASM.
- **powell_newuoa.c** (~2.8k lines) — Powell NEWUOA derivative-free optimizer (f2c translation). **Shared with the standalone allineate project.** Thread-safe statics use `AL_THREAD_LOCAL` (`al_thread_local.h`); `powell_newuoa_free_threadlocal()` releases the per-thread `pn_w`, called from `al_register` teardown.
  - **KEY gotcha — `mfac`/`afac` (NEWUOA sampling factors, `powell_set_mfac`) are thread-local**, so a main-thread `powell_set_mfac()` does NOT configure OpenMP workers. Every parallel `powell_newuoa()` loop MUST capture factors via `powell_get_mfac()` before the region, re-apply `powell_set_mfac()` inside the body, and restore the worker's prior factors afterward — else workers use stale `npt`, results become thread-count-dependent, or caller config leaks into persistent workers.
  - Direct-call `ndim` and sampling factors checked with `size_t` before NEWUOA's quadratic f2c workspace expressions; oversized shape returns `-8` before allocation/callback. **Fail-closed OOM:** `pn_w` alloc failure returns `-7` (never calls `newuoa_` with NULL); propagates — `al_scalar_optim()` returns it (`-3` on its own `wpar` calloc failure), `al_register()` aborts via `goto al_cleanup` (no "Registration complete", no result), and parallel candidate loops mark a failed optim `AL_BIGVAL`. Cost path also fail-closed: `GA_get_warped_values()` returns 1 on thread-local buffer OOM, `GA_scalar_fitter()` returns `AL_BIGVAL` rather than scoring a stale `avm`; `al_scalar_setup()` leaves `stup->setup=0` on image-buffer OOM, which the three `al_register` sites verify (`stup.setup != AL_SMAGIC → goto al_cleanup`). An optimizer/setup OOM is a clean error exit, never a silent unrefined registration.
- **reface.c/.h** — **`-reface <tmpl> <shell> <weight>`: anonymization by face replacement** (clean-room emulation of AFNI `afni_refacer2 -mode_reface`; no AFNI source copied). Dispatched from coreFLT.c (`nifti_reface_wrap`, DT32 only). Registers the SUBJECT (moving) onto the TEMPLATE (fixed, same well-posed direction as `-deface`) with EITHER engine, back-projects the signed template-space `shell` onto the ORIGINAL subject grid (NN, so -/0/+ labels survive; via `nii_apply_affine` with the inverse matrix), despeckles (`reface_isola` = AFNI `3dcalc -isola`), then composites in place (`reface_apply`): shell>0 → shell × brightness-match `ifac = mean(subject over shell>0 & subject≠0) / mean(shell over shell>0)`; shell==0 → `max(subject,0)`; shell<0 → 0; then a normalized Gaussian blur (FWHM 2.666 mm) INSIDE the shell>0 mask (niimath's own `nifti_smooth_gauss_f32`, NOT AFNI's GPL `3dBlurInMask`). Output stays on the subject grid.
  - **`weight` is REQUIRED** (3rd positional arg, reused as the registration `-weight`). niimath FAILS CLOSED for privacy (refuses to write output) if <10% of the shell face volume mapped into the subject FOV. Coverage fraction uses each image's `|det(coded transform)|` physical voxel volume (`reface_voxvol_mm3`, `xyz_units`-normalized), NOT the pixdim product. **This coverage gate (metric + <10% threshold) is duplicated, non-shared, in the standalone allineate's `do_reface` (main.c) — keep the two semantically byte-aligned when either changes.** `reface_apply` is fail-atomic (bad/mismatched/non-float input, empty overlap, non-finite `ifac`, alloc/blur failure → nonzero, `*result=NULL`, `nim` unchanged) and serial/bit-identical at `-p 1` vs `-p N`. **Shared byte-identically with the standalone**; `reface.o` in `ALOBJS` (no separate flag).
- **qwarp.c/.h** — **`-qwarp <base>`: nonlinear (deformable) registration** — ATTRIBUTED public-domain PORT of AFNI `3dQwarp -blur 0 3` (Robert W. Cox / NIMH, pinned AFNI rev 506e48403), NOT clean-room. AFNI GPL/MCW utilities on this path (`edt_blur.c`, `edt_buildmask.c`, `cs_qmed.c`) are NOT ported — supplied by niimath's own BSD/public-domain code; nothing taken from any GPL AFNI file or `src/GPL/`. Optimizer is Powell NEWUOA. Scope: the nonlinear STAGE ONLY (`qwarp_run`) — `moving` must ALREADY be unifized + skull-stripped + affine-aligned + share the stationary grid (equal dims, agreeing voxel→world; validated tightly, fails hard otherwise). Input and padded volumes must fit both `INT_MAX` and `AL_SIZE_MAX/sizeof(float)`. Equivalent (not bit-identical) to AFNI (Pearson 0.98–0.996). Serial-safe but non-reentrant (NEWUOA process-global context — do not overlap `qwarp_run()` across host threads); OpenMP inside. Dispatched from coreFLT.c (`nifti_qwarp_wrap`, DT32) as an ORDINARY chain op taking a single `<base>` (further ops may follow; NOT terminal). `QWARP=1` only, OFF by default, REQUIRES allineate (not `AL=0`). `QW_VERB=1` per-level trace. **Shared byte-identically with the standalone.**

### Supporting modules
- **dtifit.c** — `--dtifit`: linear diffusion tensor fit emulating FSL `dtifit`. Self-contained TU dispatched early in `main()`, FSL-identical flags (`-k/-m/-r/-b/-o`, `-xflip 0|1|auto`). 7-param log-linear OLS (fit math from AFNI 3dDWItoDT linear path, public domain), reuses `EIG_tsfunc` (tensor.c) for FA/MD/L*/V*. Emulates FSL's determinant-based bvec x-flip. Writes `<base>_{FA,MD,L1,L2,L3,V1,V2,V3,S0,MO,tensor}`; `--wls`/`--kurt` error clearly. **Gotchas:** tensor buffer must use NIfTI planar (volume-major) layout; validate V* with `|cos angle|` not Pearson r (eigenvector sign arbitrary).
- **romeo.c/.h** — **`-romeo <mag|none> [opts]`: ROMEO phase unwrapping**, a faithful MIT-licensed C port of [ROMEO.jl](https://github.com/korbinian90/ROMEO.jl) v1.4.0 (git `60d83fb`) plus the `MriResearchTools.jl` v3.5.0 helpers its CLI app uses (`readphase` rescaling, `robustmask`, the `gaussiansmooth3d` box filter, `sample`/type-7 `quantile`, `voxelquality`), plus Julia Base's `rem2pi` range reduction. Upstream notices live in `src/romeo.LICENSE`. Dispatched from coreFLT.c (`nifti_romeo_wrap`, **DT32 only**) as an ORDINARY chain op — further ops may follow. Self-contained: no niimath internals beyond `core.h` (which supplies `nifti_io.h`), plus the C standard library. `-no-rescale` is a silent alias of `-no-phase-rescale`; `-t` is REQUIRED for multi-echo input and optional for a single echo; bare `-w romeo` resolves to `romeo3` with a magnitude and `romeo4` without; `-Q` skips any of the six maps that is uniformly 1.0 in the interior, and `<out>_mask` is written only when a mask actually exists. Rejects >INT_MAX-voxel images (NOT in `kHugeSafeOps`); auxiliaries go through `nii_reject_oversize_aux`. Side outputs use `nifti_save` postfixes on the OUTPUT name (`<out>_mask`, `<out>_quality[_1..6]`), never `fin`.
  - **STRICT FP IS LOAD-BEARING, not a style preference.** ROMEO's growth order is decided by 8-bit integer edge weights from `rescale(w)=max(round(Int,(1-w)*255),1)`. Measured three ways against the pinned Julia oracle: `-fno-fast-math -ffp-contract=off` (shipped) passes the FULL parity suite 602/602; FMA contraction (`-ffp-contract=fast`) is bit-identical on the 76×76×46 validation volume but fails 9 checks on the full corpus (1-ULP `readphase` differences on the `line_x`/`plane_xy` fixtures, and the pre-rescale weights drifting past the 4 ULP limit); the repo-wide `-ffast-math` changes **360/797088 weight bytes and leaves 66 voxels off by a full 2π** — reassociation pushes a weight past 1.0 and `rescale()` then returns bin 0, dropping the edge from the graph entirely. Runtime is 0.02 s of compute either way (0.07 s wall including gzip output), so contraction buys nothing measurable. **Never re-evaluate the FP policy on a single volume** — run `test/romeo_compare.py --weights-all`. Every FULL build inventory compiles romeo separately: Makefile `romeo.o` (+ per-target `romeo_{dbg,verb,ubsan,asan,static,noomp}.o`), CMake `set_source_files_properties`, `notarize.sh` per-arch object, `rm_wasm.o`/`romeo_wasi.o`/`romeo_emcc.o`. `tiny`/`nano` omit ROMEO entirely, like the other optional features.
  - **Non-default target objects MUST NOT be named `romeo.o`** — writing e.g. UBSan-instrumented code there leaves `make all` with an object newer than romeo.c and an unchanged flag stamp, so it skips the rebuild and fails to link on `__ubsan_handle_*`.
  - **Numeric-type audit (romeo.c header).** Julia's promotion is NOT uniform across the six weight terms: `phasecoherence` and `magcoherence` are Float32, `phasegradientcoherence`/`magweight`/`magweight2`/the `getweight` accumulator are Float64, and `phaselinearity` is **data-dependent** — Float32 for the interior product, Float64 on its `isnan → 0.5` and boundary-`0.9` branches. Each row is confirmed by `typeof(...)` under the pin. Rounding is round-half-to-**even** (`nearbyint`/`rint`, never `round`/`lround`).
  - **`rem2pi` is ported, not approximated.** Julia's `rem2pi` uses an infinitely precise 2π, so libc `remainder(x, 6.283185307179586)` is NOT equivalent. `rem_pio2_kernel` (Cody-Waite + Payne-Hanek, with a portable 128-bit emulation so MSVC/wasm match) is ported literally; `rem2pi(Float32)` is `Float32(rem2pi(Float64(x)))`.

- **medic.c/.h** — **`--medic`: MEDIC multi-echo distortion correction** and **`-unwarp`**, a clean-room emulation of the workflow in Van et al., *Imaging Neuroscience* 4 (2026), doi:10.1162/IMAG.a.1262. No Warpkit implementation, test, build product or debug symbol was read; every convention the paper leaves open was measured through the public executables and recorded, with its experiment, in `test/medic_reference_manifest.md` — **that manifest is the source of truth for the conventions and the numbers; do not restate a figure here that contradicts it.** Guarded by `HAVE_MEDIC` (`MEDIC=0` / `-DENABLE_MEDIC=OFF`), **requires `HAVE_ROMEO`** — it calls `romeo_unwrap_frame()`/`romeo_robustmask()` and owns no unwrapping code. Ordinary FP: unlike romeo.c nothing here is reassociation-sensitive, so medic.c rides the normal source line. `--medic` is a **terminal subcommand** parsed by `nii_medic()` and dispatched from `main()` before the op loop (like `--dtifit`/`--qc`); `-unwarp` is an **ordinary chain op** (`nifti_unwarp_wrap`, coreFLT.c, **DT32 only** — `-dt double` rejects it), so further ops may follow. Neither is huge-image-safe: both reject >INT_MAX voxels explicitly, `-unwarp` is absent from `kHugeSafeOps`, and its map goes through `nii_reject_oversize_aux`. stdin (`-`) is rejected for `--medic` (several synchronized inputs).
  - **Pipeline** (manifest §3.12). Per frame: readphase rescale → MCPC-3D-S phase offset → multi-echo ROMEO unwrap → magnitude-weighted regression `ω = Σ m²·t·φ / Σ m²·t²`, `Hz = ω/2π`, `t` in **seconds**. Across frames: temporal 2π correction → rank-10 truncation → `_fieldmaps_native` → scalar fixed-point inversion → `_fieldmaps` → `× −TRT × pixdim_PE` → `_displacementmaps`. All three outputs are **float32, unscaled** (the reference writes uint16+`scl`; niimath deliberately does not, because every gate is stated in physical units). `md_write()` borrows the echo-1 phase header and temporarily points `fname` at `<prefix>.nii` so `nifti_save`'s postfix mechanism produces the three names.
  - **`-unwarp <map> <axis>` axis rule is MEASURED and counter-intuitive** (manifest §3.5): the letter names a **voxel index axis** (`i`/`x`→0, `j`/`y`→1, `k`/`z`→2), but the displacement applied is a physical vector along the **canonical world axis that voxel axis is most aligned with** — *not* along the image's own column direction. With `u = A[:,m]/|A[:,m]|`, `w = argmax|u|`, `σ = sign(u[w])` and `κ = (−1,−1,+1)` (the RAS→LPS sign of world axis `w`): `δ_RAS = d·σ·κ[w]·e_w`, `s = A⁻¹δ_RAS`, `out(v) = in(v+s)`. Recovered from a 10-grid × 3-letter sweep (all 30 rows exact) and confirmed on real oblique data at **nrmse 3.5e-5**, versus 4.3e-2 for the image's own column direction. The map is in **millimetres by contract**, so `A` is normalised to mm via `xyz_units_to_mm()` before inversion — a mm header (every real neuroimaging NIfTI) scales by exactly 1.0 and stays bit-identical, a metre/micron header would otherwise be off by 1000×. (This is a local fix; the registration code still has the unnormalised behaviour — Known Remaining Issue 7.) **On `-unwarp` a trailing `-`/`+` on the axis is accepted and IGNORED** — the sign already lives in the stored map (the `× −TRT × pixdim_PE` of the pipeline above carries it); negating again double-corrects. **`--medic --phase-encoding-direction` is the opposite: its `-` suffix IS honoured** (see the inversion bullet), so the two arguments deliberately treat the same suffix differently. Interpolation is **Lanczos-windowed sinc, radius 5, UNNORMALIZED**, applied **separably in 3D** (the offset has components on all three voxel axes for oblique data) — fit to 1.3e-8 against the reference impulse response; the weights sum to **0.998746** at a half-voxel offset and that 0.13 % dip is part of the convention, so **do NOT normalise it**. Out-of-FOV fill is **zero** (not clamped, not edge-replicated), there is **no Jacobian modulation**, and the output is not clipped to the input range. The map may be 3D (broadcast over frames) or 4D with the input's frame count, and must share the input's dims and world transform.
  - **The inversion and the resampling run along DIFFERENT axes, deliberately.** `md_invert` solves the scalar fixed point `f_u(y) = f_native(y + s·f_u(y)·TRT)` along the **voxel PE axis** with **linear** interpolation and edge clamping (measured: linear p95 0.041 Hz, cubic 2.05, nearest 4.07 — manifest §3.4), while `md_pull` resamples along the **canonical world axis** as above (manifest §3.5). The two were measured separately and disagree on oblique data; **do not "fix" this by unifying them.** niimath iterates the fixed point to convergence (cap 64, tol 1e-6 Hz) where the reference's inverter is iteration-limited and slightly overshoots — a deliberate, quantified divergence (§3.4) that still passes the displacement gate with 8× margin.
  - **PE polarity `s` (`c.pe_sign`, +1 for `j`, −1 for `j-`) is load-bearing in `--medic`,** in the inversion and again in the Hz→mm scaling. The reference returns an identical *native* field for `j` and `j-` but an inverted field that differs (corr 0.918) and a displacement map that is very nearly negated (corr −0.918, median ratio −0.973); getting it wrong on a `j-` acquisition doubles the distortion instead of correcting it. Verified for both polarities as a **convention check** (the polarity-aware model fed the reference's own native field, sbref 1 frame) at displacement p95 0.045 mm (`j`) / 0.024 mm (`j-`); the **end-to-end** `--medic` figures against the reference, with the reference mask supplied, are p95 0.059 mm (`j`) / 0.029 mm (`j-`) — different measurements, both quoted with their attribution in manifest §5.4. **The two stages are measured separately and recorded separately: manifest §3.5b is the estimate stage (`wk-medic` HONOURS the suffix), manifest §3.5 is the apply stage (`wk-apply-warp` IGNORES it). Both `md_axis_index()` callers are commented at the source; do not "unify" them.** The supplied three-echo dataset is acquired `j-`, and every M0 experiment used `j` only — which is why the black-box coverage had a hole here.
  - **MCPC-3D-S** is `offset = wrap(φ₁ − TE₁/(TE₂−TE₁)·ROMEO_unwrap(angle(m₁m₂·e^{i(φ₂−φ₁)}), mag=|hip|))`, subtracted from every echo, with **no spatial smoothing** — measured exact against the reference's own `phase_offset0` (residual 4.6e-5 rad at p95 against a 9.6e-5 rad quantum); a smoothed offset could not match. Monopolar/coil-combined only; bipolar and 5D multi-channel are out of scope. `--phase-offset none` disables the stage. Patent analysis in `prior_art.md`: US10605885B2 claim 1 requires multi-channel coil data, `TE₁:TE₂ = n:(n+1)` and an integer n-fold subtraction with **no** unwrapping — this implementation has none of those, and MCPC-3D-S itself predates the 2016 priority date.
  - **ROMEO weights default to `romeo4`, not ROMEO's own default** (which resolves to romeo3 when a magnitude is present) — measured as the fraction of in-mask voxels on the reference's own 2π branch: romeo4 0.9976, romeo6 0.9817, romeo3 0.9301, romeo2 0.8791. The reference uses romeo4 at **both** unwrapping stages, and the two stages **share ONE mask per frame**. `--weights` therefore applies to both, the MCPC-3D-S phase-difference unwrap included — do NOT re-hard-wire `RM_W_ROMEO4` inside `md_mcpc3ds()`, which would make `--weights` a half-measure.
  - **`--mask <file>` is used VERBATIM** (single 3D volume on the input grid), for every frame and both unwrapping stages, in place of the default per-frame `robustmask` of that frame's first-echo magnitude. **The in-mask test is `>= 1`, NOT "nonzero"** — the measured reference contract (manifest §3.7), since `masks.nii` is a 3-level integer image and the reference unwraps exactly on `mask >= 1`. Consequences, all deliberate and all in `medic.c`: a fractional probability map is **not** a mask (0.9 is *out*; threshold first, `niimath p.nii -thr 0.5 -bin m.nii`), NaN fails the comparison and is excluded (the safe direction), and a mask with no voxel `>= 1` is a hard error naming that remedy rather than a silently all-zero output set. Do not "relax" this to `!= 0`. It exists because the reference's mask is the one thing not reproduced, and supplying the same mask to both tools is what makes an exact cross-comparison possible (it is also how a user supplies a *better* brain mask than either tool's heuristic).
  - **Known gap — the mask, and it is NOT to be chased.** The reference's 3-level `masks.nii` construction is not reproduced; every hypothesis in manifest §3.7/§4.3 was rejected (level 2 ≈ `robustmask(|hip|)` at dice 0.975/exact 0.988, but level ≥1 is a looser region no dilation of level 2 matches). **Per an explicit user directive this is closed, not open work: `--mask` is the answer.** Given the reference mask, `_fieldmaps_native` matches to **p99 = 0.0027 Hz** (corr 0.988) — i.e. the regression, MCPC, unwrapping, rescaling and echo handling are all correct. With the shipping `robustmask` default it is **p95 ≈ 46 Hz**, because a fraction of in-mask voxels (§4.3 measured 8–18 % across mask variants) land on a different 2π branch, which the inversion then smears along the PE line.
  - **Second open item:** on the real 170-frame run the reference's `_fieldmaps_native` is rank-10 **plus a broadband residual** three orders above its own quantization floor, while niimath's output is strictly rank 10. Candidate explanations (per-group truncation, residual add-back, truncation before a later full-rank stage) are named in manifest §5.2 and **deliberately not guessed**. `--rank 0` disables the filter. The truncation itself is **UNCENTERED** (measured §3.8) via the T×T Gram matrix and a Jacobi eigensolve, so memory is O(T²) independent of voxel count.
  - **Temporal correction** (`--temporal-correction 0|1`, default 1) groups frames by first-echo magnitude correlation ≥ 0.98 and moves each frame's first echo to the 2π branch nearest its group mean, then each later echo to the branch predicted by the paper's Eq. 6 — a through-origin fit over the echoes **already corrected**, `φ_n = t_n·Σ_{i<n}(φ_i·t_i)/Σ_{i<n}(t_i²)`, which collapses to `φ₁·t_n/t₁` only for `n = 2` (so two-echo data cannot distinguish it from the naive form; three-or-more-echo data can). Group means come from an **immutable snapshot** of the first-echo series: correcting in place while reading would make the result depend on traversal order. The **behaviour** is measured (§3.9, a uniform per-frame shift); the 0.98 threshold and the tie/empty-group handling are **paper-specified, not black-box-measured** — the one parameter the reference would not reveal. `--noise-frames N` (`-f`) **drops N trailing frames from the outputs entirely** (measured §3.10), so the output frame count is `T = frames − N`.
  - **Memory is in-RAM by design, and that is a decided position, not an omission** — a 4D `.nii.gz` cannot be seeked, so every tool (the reference included) holds whole volumes in RAM anyway; the requirement is to be fast and honest about the cost. The **work arrays** are `phase + mag + fields + fu + disp` = `n3 × T × (2·echoes + 3) × 4` bytes, and that is what is printed to stderr at startup (1.18 GiB on the 170-frame two-echo demo). **The banner is the work-array budget, and the ordering that keeps it close to the truth is load-bearing:** every input is validated from its HEADER alone (`md_read_hdr`), so **no payload is resident when the five work arrays are allocated**, and the repack loop then loads, rescales and frees **one echo pair at a time** (`md_read_f32` inside the loop). The transient overshoot is therefore one echo pair regardless of echo count, plus `md_write()`'s per-output copy. An earlier revision read all `2·echoes` payloads during validation and freed them only during the repack — i.e. *after* the work allocation — so the true peak was `(4·echoes + 3)` series while the banner said `(2·echoes + 3)`; **do not move the payload reads back above the allocation.** Measured peak RSS on the 170-frame two-echo run: **2.04 GB** single-threaded and **2.24 GB** at 8 threads writing uncompressed, **2.35 GB** gzipped, against the reference's **3.40 GB** (manifest §5.3 is authoritative; do not quote a MEDIC timing or memory figure that contradicts it). **Those peaks were measured BEFORE the per-echo-loading change and have not been re-run**, so they are upper bounds on the current binary, not fresh measurements. **Phase is unwrapped IN PLACE** — the separate unwrapped-phase series was deleted during the audit, taking the gzipped peak from 2.53 to 2.35 GB, so do not reintroduce a `uw` buffer. The work arrays grow linearly with frames × echoes — roughly 10 GiB for 5 echoes × 600 frames at this resolution, and **wasm32's 4 GiB address space (plus `-DFORCE_INT32_MAX` on every wasm target) is why `--medic` is native-scale-only while `-unwarp` is browser-friendly**.
  - **Failure semantics (plan §10, preserve these).** Headers are preflighted before payloads (`md_read_f32` reads header-only first, so an oversized/malformed image is rejected before decompression and allocation). `md_same_grid` compares dims exactly plus core.c's own **`max_displacement_mm()` at the 0.001 mm gate `--qc` uses** — true 3D corner displacement, `xyz_units`-normalised, so rotation, scale, origin AND units are covered in one call. The hand-rolled 3×3 comparison it replaced would have accepted a translated grid and silently paired different anatomical locations; do not reintroduce a local copy. A float32 input carrying a non-trivial `scl_slope`/`scl_inter` is still run through the datatype conversion (`md_read_f32` converts when the type differs **or** scaling is present), or a scaled displacement map would be used raw. Non-finite or absurd (`|v| > 1e9`) displacements and sample positions are treated as out-of-FOV and zero-filled rather than cast to `int` (undefined). Allocation products go through `nii_mul_size()`. Per-frame status is recorded in a **per-frame array**, not a shared `failed` flag written from several threads (a race, and reading it to skip work would make the result thread-count-dependent). Low-rank scratch is preflighted **before** `F` is mutated — a mid-way OOM used to leave a silently half-filtered series and still return success. **A non-finite field series is a hard error, gated on the SERIES itself (`md_all_finite`) right after the regression — NOT inside `md_lowrank()`, and this placement is load-bearing.** The original bug: one NaN voxel anywhere in the phase makes one field frame NaN, poisons `G = FᵀF`, makes every eigenvalue NaN, makes every `w[k] > …` test false at `k == 0` — so the numerical rank came out `0`, the code built the **zero projector**, multiplied the whole series by it and **exited 0** with three identically-zero outputs and no diagnostic. Gating it inside `md_lowrank()` was still wrong, because that function returns early whenever `rank >= T` (default rank 10 with `T ≤ 10`) and whenever `--rank 0` is given, so a NaN sailed straight through to the outputs; the check therefore runs unconditionally on `fields`. Inside `md_lowrank()`, `r <= 0` on a known-finite series can only mean a genuinely degenerate spectrum (an all-zero field) and is a **no-op**, not an error. All finiteness tests use magnitude guards (`v >= -FLT_MAX && v <= FLT_MAX`), not `isfinite()`, because this TU is `-ffast-math`. A `--save-intermediates` write failure is an error (it was an explicit request). The three final writes are published as a **RECOVERABLE transaction — deliberately NOT called atomic**, because a crash between two renames still leaves a mixed set. All computation finishes first; then each output is written under a `<prefix>.medictmp<pid>` prefix by **`md_write_temp()`**; then any pre-existing finals are renamed aside to `<final>.medicbak<pid>`; then the three temporaries are renamed in. **On any failure the backups are renamed back and our own publishes and temporaries are removed**, so the caller keeps either a clean old set or a clean new one — never the mixed set (new file 1, old files 2 and 3) that a plain rename loop produced, which is worse than either because it looks usable. Destinations are **preflighted with `stat`**: a final path occupied by anything that is not a regular file is refused, not renamed out of the way (moving a user's directory aside is a surprising side effect and a non-empty one cannot be cleaned up). `md_write_temp()` **removes all three extension candidates before writing and then probes for the one that appeared**, because `nifti_save()` picks the extension from `gzMode`/`FSLOUTPUTTYPE` and it is not knowable in advance — probing for the first *existing* candidate without the pre-removal let a stale temp from a crashed run that reused the PID be renamed into place as the result. A temp that cannot be located after its write counts as a failure — do not weaken that to a best-effort skip. The final extension is taken **by offset** (`strlen(tmppfx) + strlen(suffix)`), never by searching for `.nii`, or an `--out-prefix out.nii` leaks the temp prefix and PID into the user-visible name. `remove(final)` before each `rename` is for MSVC, whose `rename()` will not replace an existing destination.
  - **Validation, and what is NOT claimed.** **No equivalence with the reference tool is claimed anywhere, and bit identity is an explicit non-goal** (plan §11). `-unwarp` **passes its M3 gate outright**: fed the reference's own `_displacementmaps`, it reproduces the reference's corrected magnitudes at nrmse **3.5e-5 / 4.7e-5**, corr **0.999999999**, **zero** non-finite, on data ranging to 41 482 (the residual is the reference map's uint16 quantization). **`--medic` does not match end to end.** Given a shared mask the native field agrees to p99 **0.0027 Hz** — the regression, MCPC, unwrapping, rescaling and echo handling are right — but the current end-to-end displacement is p95 **0.059 mm** for `j`, which **misses** the plan's 0.05 mm M5 gate (`j-` is at 0.029 mm and meets it), and with the shipping `robustmask` default it is 2.40 mm. Say this plainly rather than quoting the passing convention checks (§3.4/§3.5b) as if they were pipeline results. CI coverage is `exercise_medic()` in `release_smoke.py` — data-free analytic properties, not exit statuses: a ramp pulled by a constant N-voxel map must come back shifted by exactly −N in the interior (catches sign flip, wrong axis, wrong length unit, broken kernel), out-of-FOV must read exactly 0, and a synthetic `wrap(2π·f·TE)` field must be recovered by the regression to 5 % in least-squares slope and intercept. It self-skips when `--medic` is absent from `--help`.
  - **medic.py** is a stdlib-only BIDS front end (argparse/json/os/pathlib/re/shutil/subprocess/sys — no numpy/nibabel/pybids); niimath does all NIfTI I/O, medic.py never opens an image. It groups `*_echo-<N>_part-{mag,phase}_bold.nii*` into runs, reads TEs/`TotalReadoutTime`/`PhaseEncodingDirection` from the sidecars, then calls `--medic` once per run and `-unwarp` once per magnitude echo. v1 reads **exact** sidecars only — no BIDS inheritance.
  - **Two invariants worth stating because breaking them was expensive.** (1) `md_xform3()` MUST use the same transform precedence as core.c's `xform()` (sform *unless* `sform_code < qform_code`), because `md_same_grid()` validates through `max_displacement_mm()` which uses `xform()` — a different rule in the two places let two maps with disagreeing sform/qform both pass the grid check and then produce OPPOSITE corrections. (2) Output publication is sibling-temp-plus-`rename` with a `.medicbak<pid>` backup/restore step, and the temp candidates are removed before each write — probing for the first *existing* candidate let a stale temp from a crashed run with the same PID be renamed into place as the result. Three renames are atomic individually but NOT as a set, so the scheme is described as **recoverable, not atomic**: a failed rename restores the backups instead of leaving a mixed set, but a crash between renames can still leave one.
  - **The unwrapped phase is zeroed outside the mask before anything reads it** (regression, temporal grouping, SVD, and the `--save-intermediates` write). ROMEO constrains which voxels it VISITS but leaves the rest holding wrapped values; gating them matches the measured reference and improved displacement agreement 3.3× (p95 0.197 → 0.059 mm for `j`). Do not move this below the intermediates write — the saved diagnostic must match the pipeline that consumed it.
  - **Non-finite input fails loudly**, and the check lives on the field series (`md_all_finite`) immediately after the regression, NOT inside `md_lowrank()` — that function returns early when `rank >= T`, which made the guard frame-count dependent and let a NaN reach the outputs at T ≤ 10.

### AFNI-fidelity note (allineate coarse search)
The coarse random+grid search (`al_scalar_ransetup`, port of AFNI `mri_genalign_scalar_ransetup`) is deliberately AFNI-faithful, matching values verbatim: `PARAM_MAXTRIAL=29`, `NKEEP=3*PARAM_MAXTRIAL+1=88`, the `nrand≥NKEEP+13=101` floor, `DEFAULT_TBEST=5`/`DEFAULT_TBEST_LPA=17`, and the `vol_src>1.3*vol_base→tbest=PARAM_MAXTRIAL` largeness branch. AFNI runs this full 88/101 coarse search **regardless of `tbest`** (tbest only controls how many candidates get refined) at full resolution — the dominant runtime. This cost IS AFNI fidelity — do NOT shrink `NKEEP`/`nrand` for the default case. `PARAM_MAXTRIAL+2` sizes the candidate arrays; max `tfdone` is `tbest+1=30`, so 31 has headroom. Two branches (`al_shift_range_mm` padded-FOV expansion; largeness `tbest=29`) fire only for edge geometries (off-center subject; source FOV >1.3× base) and lack committed CI fixtures (manual + UBSan verified).

## Memory Management

- **Use plain `malloc`/`calloc`/`free` everywhere.** Do NOT reintroduce `_mm_malloc`/`_mm_free` or `arm_malloc.h` — the 64-byte alignment was never load-bearing (SSE-only 128-bit unaligned loads; malloc's 16-byte alignment already prevents cache-line splits; memory-bandwidth-bound).
- **`nim->data` ownership invariant:** any buffer assigned to `nim->data` MUST come from plain `malloc`/`calloc`, because `nifti_image_free()` and core.c's datatype conversion release it with plain `free()`. On MSVC `_mm_malloc` → `_aligned_malloc`, which `free()` cannot release — plain `free()` on it corrupts the heap (STATUS_HEAP_CORRUPTION 0xC0000374 at teardown). Use **`nii_calloc(count, size)`** (core.c/core.h) for `nim->data`: a fail-closed allocator running `count`×`size` through checked-multiply `nii_mul_size()` and `exit(EXIT_FAILURE)` on overflow/NULL. **`nii_malloc(count, size)`** is the UN-zeroed sibling (same check + exit, plain `malloc`) for a `nim->data` buffer the caller FULLY overwrites before any read (datatype-conversion output loops); use `nii_calloc` if any voxel could be left unwritten (RGB/complex convert buffers stay `calloc`). Callers still pre-compute overflow-prone products with `nii_mul_size()`.
- Kernel arrays: 4-int-per-voxel layout (offset, x, y, weight); plain `malloc`.
- NIfTI images: managed by `nifti_image_free()`.
- MarchingCubes.c: constructor/destructor (`MarchingCubes()`/`FreeMarchingCubes()`) with `clean_all()`.

## Huge image support (> INT_MAX voxels, issue #67)

The core calculator processes images whose 3D `nx·ny·nz` or total 4D `nvox` exceeds `INT_MAX` (≈2.15 G voxels ≈8.6 GB float32) instead of rejecting them.

- **`nvox_t` (core.h)** is the voxel count/index type: **signed** `int64_t` by default (neighborhood/kernel/reverse loops need negative intermediates that unsigned `size_t` would wrap), or `int32_t` under `-DFORCE_INT32_MAX`. `size_t` stays for byte-size allocation only.
- **Scope.** Converted (nvox_t/`size_t`-safe): scalar & image binary ops, per-voxel unary math, temporal reductions (`nifti_dim_reduce`), robust-range percentile, Gaussian smoothing. Everything else — kernel morphology `-fmean`/`-ero`/`-dilF`, `-edge`/`-index`/`-rank`/`-pval`, EDT/tfce/resize/subsamp, allineate/deface/mesh/dtifit/qc/bwlabel/bmp/fdr — keeps int indexing and is **guarded** (rejected on huge input).
- **Fail-closed admission.** A huge image runs only if its op is an exact `strcmp` member of `kHugeSafeOps[]`. `nii_admit_file_before_load()` gates before the payload read (resolving the real first op past output/`-odt`, the RGB ×3/×4 effective count, pass-through/conversion-only); `nii_admit_current_op()` re-checks at the top of every op-loop iteration against the CURRENT image (catches `-restart`, a binary op adopting a huge operand, RGB expansion). stdin/`.nii.zst` skip the pre-read gate and are caught post-load. `nii_reject_oversize_aux()` header-rejects an oversized auxiliary (reslice mask/base, deface template/mask, `-allineate -weight`, bitmap) before its load — EXCEPT a `.nii.zst` auxiliary (no bounded header-only path; caught post-load — accepted limitation). Robust-range/Otsu reject an intensity span their histogram cannot represent (avoids undefined `(int)NaN`). **To promote a guarded op: make its kernel `nvox_t`-clean AND add a `test/huge_smoke.py` case.**
- **`nii_nvox_classify()` (core.c)** is the single geometry validator → {invalid, INT-safe, huge}; `nii_nvox3d_int`/`nii_nvox3d` are its narrow/wide adapters.
- **`-DFORCE_INT32_MAX` on every 32-bit/wasm build (MUST).** wasm32 has a 4 GB ceiling; the `tiny`/`wasm`/`wasm-wasi`/`wasm-emcc-core` Makefile targets and CMake `tiny`/32-bit set it; every huge image is rejected there. Core ops are byte-identical to the pre-#67 build at ≤INT_MAX sizes.
- **Testing.** `test/huge_smoke.py <binary>` — opt-in/manual (~9 GB RAM; not in CI): sparse >INT_MAX NIfTIs. Allocation-free reject cases run in `make test` via `release_smoke.py`.
- **Reach goals (deferred).** (1) Re-add `-Tstd/-Tmedian/-Tperc/-Tar1` to `kHugeSafeOps` (scratch already hoisted per actual OpenMP worker; only a huge_smoke oracle missing). (2) Convert the neighborhood/morphology kernels. Non-goals: registration/mesh/tfce/resize; streaming `.nii.zst` + >2 GB Win64 offsets. `-uthrP` uses the established 1000-bin robust-range approximation (FSL-exact on discrete data) — a separate compatibility decision.

### MEDIC head-to-head benchmarks (`test/medic_experiments/`)
Two scripts, both on the 170-frame two-echo workload (76×76×46, `demo/run170.sh`), measured on Apple Silicon. **The manifest §5.3 tables are authoritative for every figure below.**

- **`bench_threads.py` — like for like**, both tools writing UNCOMPRESSED `.nii`, so it compares compute rather than gzip, at 1 and 8 threads. 1 thread: `wk-medic` 44.37 s wall / 53.29 s CPU / 3.40 GB vs **`niimath --medic` 14.38 s / 13.96 s / 2.04 GB** (**3.09× faster**). 8 threads: `wk-medic` 15.23 s / 65.51 s / 3.40 GB vs **niimath 4.15 s / 14.91 s / 2.24 GB** (**3.67× faster**). Thread scaling 1→8 is 3.47× for niimath and 2.91× for the reference — the reference's higher parallel efficiency is recovering its own overhead, not winning work (53 s of CPU to do single-threaded what niimath does in 14.0 s).
- **`bench170.py` — the shipping-default comparison** (niimath gzipping its output), plus the apply stage. Estimate at 8 threads: **10.64 s wall / 19.95 s CPU / 2.35 GB** (`--gz 0`: 4.29 s / 13.39 s) vs `wk-medic` 15.63 s / 65.07 s / 3.40 GB. Apply: **`-unwarp` 4.68 s / 17.47 s / 0.59 GB** vs `wk-apply-warp` 50.72 s / 485.62 s / 1.14 GB. These rows were measured **before** the mask-retention change, so the `--gz 0` peak reads 2.19 GB where the like-for-like table above (current revision, same configuration) reads 2.24 GB — quote 2.24 GB.

niimath writes float32 (172 MB/series) against the reference's uint16 (86 MB/series). Neither tool streams; both hold every series in RAM (see the medic.c entry).

**Two build traps invalidate any timing claim if ignored** (the first already cost one full bogus benchmark):
- **Verify OpenMP is actually linked.** `./src/niimath <img> -p 8 -s 1 out.nii` MUST print `Using 8 threads`. A stale object left behind by an earlier `make OMP=0` / `ROMEO=0` / `MEDIC=0` build silently yields a **serial** binary; the first run of this benchmark measured 1.0× parallelism for exactly that reason and had to be discarded.
- **Build against zlib-ng, not system zlib.** Plain `make` links system `-lz`; use `make -C src ZLIBNG_ROOT=<path>` or the CMake release path (which defaults to zlib-ng). Output gzip is the dominant serial tail — system zlib gives 16.21 s where zlib-ng gives 10.64 s, so a system-zlib build understates niimath by ~35 %. `--gz 0` isolates it at 4.29 s, which is why `bench_threads.py` runs BOTH tools uncompressed: the reference writes uncompressed `.nii`, so that is the only like-for-like compute comparison.

2. **Build feature-list drift** — the feature source/define inventory is duplicated across `src/Makefile` (incl. the zlib-free `WASI_SRCS`/`wasm-emcc-core` lists), `src/CMakeLists.txt`, `src/notarize.sh`, and `SuperBuild/SuperBuild.cmake` (which forwards each feature's option to `src/CMakeLists.txt` — a new feature needs its `ENABLE_*` option declared+forwarded here; `OPENMP_XCODE` MUST default to `${USE_OPENMP}` so the Apple universal build's `-DOPENMP_XCODE=OFF` still disables OpenMP). Adding a feature requires touching all of them (a new compute-feature TU also belongs in `WASI_SRCS` and the `wasm-emcc-core` list). **ROMEO sharpens this:** `romeo.c` must be compiled strict-FP, so it cannot ride a shared fast-math source line — EVERY recipe needs its own `romeo*.o` compile step (Makefile `all` plus the six non-default targets plus the three wasm/wasi targets, CMake `set_source_files_properties`, `notarize.sh` per architecture), not merely an entry in a source list. **MEDIC's inventory, for reference:** `medic.c` (`-DHAVE_MEDIC`, the Makefile's `MEDICFLAGS`) reaches Makefile `all` + `native-noomp`/`static`/`debug`/`verbose`/`ubsan`/`sanitize`, the Emscripten `wasm` target (via its own `MEDIC_WASM`, deliberately NOT folded into `QC_WASM`, so `QC=0 make wasm` does not silently drop it), `src/CMakeLists.txt`, `SuperBuild.cmake`, and `notarize.sh`'s `SRCS`+`DFLAGS`. It is **deliberately absent** from `WASI_SRCS` and the feature-matched `wasm-emcc-core` line (the WASI reactor is a lean zlib-free compute backend), and from `tiny`/`nano` like every other optional feature — that exclusion is documented at `MEDIC_WASM` in the Makefile, together with the reason `--medic` is of limited use in wasm at all: wasm32 is a 4 GiB space with `-DFORCE_INT32_MAX`, while `--medic` holds the whole run resident (measured peak 2.0–2.4 GB for the 170-frame two-echo demo, manifest §5.3), so estimate natively and apply `-unwarp` in wasm. **The comment at `MEDIC_WASM` in `src/Makefile` still carries the pre-audit formula `(3*echoes + 1)` and "~2.5 GB" — both superseded by `(2·echoes + 3)` and the measured peaks above; that file is out of scope for a docs pass.**
3. **Whole-program `-ffast-math` (all build systems).** Make, CMake (non-MSVC `CMAKE_C_FLAGS`), notarize.sh, and wasm compile the entire program `-ffast-math -fno-finite-math-only`; MSVC stays strict. **One standing exception:** `romeo.c` is compiled strict-FP (`-fno-fast-math -ffp-contract=off`; MSVC `/fp:precise`) in every build system and linked as a separate object — its 8-bit edge weights are reassociation-sensitive, and fast-math leaves 66 voxels off by a full 2π (see the romeo.c entry). Registration must round like the standalone/fslmaths goldens (shared `nifti_io` mat44 helpers run during the fit); scoping it to registration TUs made CMake/notarize/wasm diverge. Also covers core ops, GPL `-spm_coreg`, dtifit/tensor — re-validate the SPM golden and dtifit/tensor if you touch those. `-fno-finite-math-only` preserves NaN/Inf detection; fast-math-sensitive finiteness checks use magnitude guards (e.g. `v >= -DBL_MAX && v <= DBL_MAX`).
4. **Prebuilt-object flag stamp.** `allineate.o`/`powell_newuoa.o`/`coreg_fast.o` depend on a flag-signature stamp (`.al_obj_flags` = `CNAME|CFLAGS|AFLAGS`) so `make` → `make OMP=0 all` relinks cleanly with no `make -B` — else a stale object fails to link on `__kmpc_*`/`omp_*`. Extend `AL_OBJ_SIG` for a new object-affecting flag outside `CFLAGS`. `romeo.o` has its OWN independent stamp (`.romeo_obj_flags` = `CNAME|CFLAGS|ROMEOFLAGS|ROMEO_STRICT_FP`, Makefile `ROMEO_OBJ_SIG`) because it must rebuild on a flag change even in an `AL=0` build where `.al_obj_flags` is unused; and the non-default targets MUST write `romeo_<target>.o`, never `romeo.o`, or `make all` finds an instrumented object newer than the source with an unchanged stamp and fails to link.
5. **Output-write failures propagate.** `nifti_image_write_status` returns 0/1 (open, short header/data write, compressor/close/pclose errors incl. disk-full at close); `void nifti_image_write` remains a compatibility wrapper. `nifti_save` uses the status API; main dispatch, pass-through, and intermediate `-save` sites propagate it; multi-output `--dtifit`/`-tensor_decomp` OR every status. Preserve — a failed/partial write must report failure, not exit 0.
6. **`nifti_io.c` upstream debt** — LLP64 builds still use `long` in the internal seek wrapper, limiting >2 GiB Windows offsets; a future upstream sync should move that to the platform's 64-bit seek API. Crafted payload-size multiplication, NIfTI-2 header probing, stdin polling, and piped-input cleanup are already hardened locally; preserve those on upgrade.
7. **Registration mislabels metre/micron coordinates as mm.** `al_image_xform`/`al_image_xform_or_pixdim` (allineate.c) return raw NIfTI sform/qform/pixdim coordinates in the header's `xyz_units`, but the registration schedules (translation guards, blur mm), the fast engine bounds, and `-savemat` (`"units":"mm"`) all treat them as world-mm. A legal metre (or micron) image thus gets a 1000× (or 0.001×) physical schedule and a false-unit saved matrix. Practical exposure is ~nil (neuroimaging NIfTIs are mm), which is why this is deferred, NOT that it's unimportant. **The fix is a COORDINATED change, not a one-line seam scale:** reface already normalizes independently via `reface_voxvol_mm3(…, xyz_units)`, so scaling the transform at the seam would DOUBLE-normalize the privacy-critical reface coverage gate — the seam normalization and the reface `reface_voxvol_mm3` de-normalization must land together, be mirrored to `codex/allineate` (both the shared seam and the standalone's own `do_reface`), and ship with a mm/metre/micron equivalence test (the `release_smoke.py` `nifti_header(scale=, xyz_units=)` helper already supports it). mm images must stay byte-identical (factor 1.0).

### macOS universal release (zstd)
The AppVeyor macOS job builds a universal binary from separate x86_64 + arm64 slices via `lipo`. Homebrew ships only the runner's native arch of libzstd, so the job builds a **universal static `libzstd.a` from source** (`-arch x86_64 -arch arm64`) and points both slices at it via `PKG_CONFIG_PATH` (also self-contained, no runtime `libzstd.dylib`). `src/CMakeLists.txt` resolves the pkg-config result to a full library path. The universal build also passes `-DOPENMP_XCODE=OFF` — hence `OPENMP_XCODE` must remain a consumed, override-able option.

## Optimization Constraints

- Voxel ops are lean, SIMD-optimized, mostly memory-bandwidth limited. OpenMP is **not the primary optimization target** for core ops (typical usage runs one subject per thread across many subjects). zlib-ng (CMake release baseline, `ZLIB_IMPLEMENTATION=zlib-ng`, ZLIB_COMPAT) gives ~2× `.nii.gz` I/O over stock zlib (correct on MSVC where Cloudflare is not). The Emscripten `wasm` target links it via `WASM_ZLIB`.
- **Allineate reproducibility:** `-allineate` is byte-reproducible **across thread counts** (nt=1/2/4/8) — preserved by the `mfac` thread-local re-apply rule. It is **NOT bit-reproducible across builds**: NEWUOA + `-ffast-math` means a codegen change can flip the optimizer to a neighboring equally-valid optimum (sub-voxel parameter shift, ~1% in a few edge voxels). Quality unchanged (cost and base-correlation match to 4+ digits) — do NOT treat `-allineate` output as a byte-stable golden across versions. `gpl-build.yml` gates registration by QUALITY (correlation floor + improvement-over-baseline via `reg_quality.py`, fails closed on empty/constant/non-finite), not a byte diff. `-deface`/`-spm_deface` reslice via `nii_reslice_affine` (not the fused path) and stay byte-stable.

### WASM performance pitfalls (two hard-won rules)
1. **No `qsort`+comparator on large or per-voxel arrays in WASM-targeted code.** emscripten/musl `qsort` calls the comparator via `call_indirect` per comparison (~100× slower than native — can make the WASM build appear to hang). Use comparator-free: **quickselect** for a single value (`al_select_rank`, `select_kth_flt`, `uf_select`), **insertion sort** for genuinely small fixed N only (NOT a per-voxel neighborhood — O(n²) per voxel), or **heapsort** for a full order on large arrays (`heapsort_sortIdx`). The only remaining `qsort` is `qsort_floatint` on ~46-element lists.
2. **WASM allineate MUST be compiled `-ffast-math` (matching native)**, or the cost-function reduction rounds differently and NEWUOA/Powell converges to a worse optimum (`-deface` masked 37% vs 60% native). The `wasm:` target and its prebuilt `al_wasm.o`/`pn_wasm.o`/`cf_wasm.o` use whole-program `-ffast-math -fno-finite-math-only`. (`-msimd128` adds only ~3% — not worth the golden-match risk.)

## Code Conventions
- C99 with extensive `#ifdef` for conditional compilation.
- Template pattern: coreFLT.c compiled as both float32 and float64 via macro inclusion.
- Naming: `nifti_*` for NIfTI operations, `nii_*` for internal helpers.
- Explicit SIMD (Intel intrinsics via `immintrin.h`) only on `__x86_64__`; ARM/WASM use scalar fallbacks (clang `-O3` auto-vectorizes to NEON just as fast; memory-bandwidth bound). No `sse2neon.h` shim.
- Error returns: `EXIT_SUCCESS`/`EXIT_FAILURE`.
