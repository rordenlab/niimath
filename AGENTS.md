This file provides guidance for AI agents when working with code in this repository.

## Project Overview

niimath is an open-source clone of FSL's `fslmaths` — a general-purpose NIfTI image calculator for neuroimaging. It extends fslmaths with mesh generation (nii2mesh), extra filters, defacing (`-deface`), affine registration (`-allineate`), anatomical QC (`--qc`), zstd compression (.nii.zst), and cross-platform support (Linux, macOS, Windows, WebAssembly).

**Repository:** `rordenlab/niimath` (BSD-2-Clause license)

## Building

### Quick build (Makefile, recommended for development)
```bash
cd src && make          # Standard optimized build (OpenMP enabled by default)
make debug              # Debug build (-g, no optimization)
make ubsan              # UndefinedBehaviorSanitizer (lightweight; retains OpenMP)
make sanitize           # AddressSanitizer (serial on Apple Clang; no leak detection on macOS)
make verbose            # All warnings
make static             # Static binary
```

### Prerequisites
- **macOS**: `brew install libomp zstd`
- **Linux**: `apt install libzstd-dev` (OpenMP built-in with gcc)

### Build variants
```bash
make tiny               # Minimal terminal build (emulates WASM constraints)
make nano               # Without mesh (nii2mesh)
MESH=0 make             # Disable mesh support
AL=0 make               # Disable allineate registration
DTIFIT=0 make           # Disable dtifit
QC=0 make               # Disable anatomical QC (--qc)
ROMEO=0 make            # Disable ROMEO phase unwrapping (-romeo); implies MEDIC=0
MEDIC=0 make            # Disable MEDIC distortion correction (--medic, -unwarp)
MOCO=0 make             # Disable motion correction (-moco)
GPL=1 make              # Enable optional GPL -spm_coreg (needs git submodule update --init src/GPL)
QWARP=1 make            # Enable -qwarp nonlinear registration; OFF by default; needs allineate (not with AL=0)
ZSTD=0 make             # Disable zstd (.nii.zst)
OMP=0 make              # Single-threaded build
MC=1 make               # New MarchingCubes algorithm (handles ambiguities)
STB=1 make              # STB image library instead of libspng for bitmaps
make wasm               # Emscripten/WebAssembly
make wasm-wasi          # Experimental zlib-free WASI compute backend (needs Zig)
make wasm-emcc-core     # Feature-matched zlib-free Emscripten build (WASI benchmark baseline)
```
zlib: CMake release builds default to zlib-ng (`ZLIB_IMPLEMENTATION=zlib-ng`); plain make uses system `-lz` (`ZLIBNG_ROOT=<path>` links compat zlib-ng without CMake; wasm uses `WASM_ZLIB`).

### CMake build
```bash
mkdir build && cd build && cmake .. && make     # top-level SuperBuild
cmake -DUSE_OPENMP=OFF -DENABLE_QC=OFF ..        # toggles (forwarded by SuperBuild)
```

### Key compile-time flags
- `NII2MESH` / `DNII2MESH` — mesh conversion
- `USE_CLASSIC_CUBES` — oldcubes.h (classic) vs MarchingCubes.h
- `HAVE_FORMATS` — GIfTI, OBJ, VTK, STL mesh output
- `HAVE_BMP` — bitmap/PNG creation
- `HAVE_BUTTERWORTH` — bandpass temporal filtering
- `HAVE_TENSOR` — tensor decomposition
- `HAVE_DTIFIT` — linear diffusion tensor fit (`--dtifit`); needs `HAVE_TENSOR`
- `HAVE_QC` — anatomical QC (`--qc`); no tensor/mesh deps
- `HAVE_ROMEO` — ROMEO phase unwrapping (`-romeo`, romeo.c); ON by default, `ROMEO=0` / `-DENABLE_ROMEO=OFF` disables. Built as a **prebuilt STRICT-FP object** with its own `.romeo_obj_flags` stamp — see the romeo.c entry below
- `HAVE_MEDIC` — MEDIC multi-echo distortion correction (`--medic`, `-unwarp`, medic.c); ON by default. **Requires `HAVE_ROMEO`** — `ROMEO=0` silently implies `MEDIC=0` in the Makefile, and CMake hard-errors on `ENABLE_MEDIC=ON` with `ENABLE_ROMEO=OFF`. Ordinary FP (NOT a strict-FP object like romeo.c), so it rides the normal source line
- `HAVE_MOCO` — rigid-body motion correction (`-moco`, moco.c); `MOCO=0` / `-DENABLE_MOCO=OFF` disables. **`MOCOFLAGS` is platform-gated to Apple Silicon macOS** (`MOCO_SUPPORTED` in the Makefile — a VALIDATION gate, not a portability one; moco.c itself is portable) and `MOCO_WASM` is deliberately EMPTY, so no other platform advertises `-moco` until its numerical gates are recorded. Ordinary FP, rides the normal source line
- `HAVE_CONFORM` — image conforming to standard space
- `HAVE_ALLINEATE` — affine registration + defacing (allineate.c + powell_newuoa.c + coreg_fast.c + reface.c); release builds use whole-program `-ffast-math` + OpenMP. `reface.c` always compiled in an allineate build (no separate flag).
- `HAVE_QWARP` — `-qwarp` nonlinear registration (qwarp.c, attributed AFNI 3dQwarp port); OFF by default; `QWARP=1 make`; requires allineate/NEWUOA (not with `AL=0`).
- `HAVE_GPL` — optional GPL `-spm_coreg`/`-spm_deface`; OFF by default so builds stay BSD-2. Sources in `niimath_gpl` submodule (`src/GPL`); `GPL=1 make` / `cmake -DENABLE_GPL=ON` / `GPL=1 make wasm` (needs `git submodule update --init src/GPL`). A `GPL=1` binary is a GPL-2 combined work (version string ends ` GPL` vs ` BSD`).
- `AL_LPC_MICHO` — adds lpc+ZZ/lpa+ZZ combined cost variant (default: pure lpc/lpa)
- `HAVE_ZSTD` — .nii.zst support (auto-detected; `FSLOUTPUTTYPE=NIFTI_ZST` to write)
- `FSLSTYLE` — FSL-compatible behavior mode

## Source Architecture

### Core computational pipeline
- **niimath.c** — CLI entry point; dispatches to `main32()`/`main64()` by `-dt`. `--dtifit`/`--qc` are self-contained subcommands dispatched before the op loop. Huge-image (>INT_MAX voxel) gate (issue #67): `main32`/`main64` admit a huge working image only for whitelisted ops (fail-closed) — see **Huge image support**.
- **coreFLT.c** (6k lines) — main computational engine, compiled twice via template pattern:
  - **core32.c** — `#define DT32` + include → float32 (SSE 4-wide on x86_64; scalar ARM/WASM)
  - **core64.c** — include without DT32 → float64 (SSE 2-wide on x86_64; scalar ARM/WASM)
  - **Filter kernels.** Gaussian smoothing (`smooth_gauss_blur1d`, used by `-s`/`-dog`/unsharp/registration) uses `blur_row`: a contiguous full-symmetric kernel (`kc[i]`, not `k[abs(i)]`), lane-parallel so clang auto-vectorizes. `-fmean`/`-fmeanu`, `-dilF`/`-eroF`, binary `-ero` are O(k³) with independent per-output state, preserving each op's local NaN/±Inf behavior. A separable box-filter experiment was removed (shared running sums / monotonic deques changed those semantics; archived in `noncompliant.md`) — do NOT restore without explicit non-finite conformance tests.
  - **`-dilate <thr> <dx>`** (distance-based grow, `nifti_dilate`, distinct from kernel `-dilF`): binarizes at `thr`, grows the mask by `dx` mm — voxels within `dx` of the surface set to at least `thr` via `fmax(iso, imgIn[i])` (matching `-close`'s fill, so a grown voxel survives a re-threshold at `iso`; `fmax(1.0,..)` is wrong for `iso>1`), beyond-`dx` voxels unchanged (grow-only).
- **core.c** — shared utilities: datatype conversion, kernel creation, Otsu thresholding, resampling filters, NIfTI I/O helpers. **`max_displacement_mm()` gotcha:** returns max corner displacement between two images' world transforms; gates the `-add`/binary-op and `--compare` orientation warnings (0.5 mm) and the `--qc` grid check (0.001 mm). It measures true 3D Euclidean distance AND normalises each transform to mm via `xyz_units` (`xyz_units_to_mm`) so metre/micron headers compare correctly; touch only with that unit scaling in mind.
- **unifize.c** — bias field correction (`-unifize`; adapted from AFNI 3dUnifize, public domain).
- **allineate.c** (~3.9k lines) — affine registration, defacing, skull-stripping. **Shared byte-identically with the standalone allineate project — canonical source; sync any change both ways** (see Shared-code invariant). Twopass coarse-to-fine with a full-resolution AFNI-faithful coarse search and OpenMP-parallel candidate refinement over thread-local buffers (adapted from AFNI 3dAllineate, public domain). `al_register()` is shared by `nii_allineate()`/`nii_deface()`; `nii_reslice_affine` + `nii_apply_deface_mask` are factored out and reused by `nii_deface` and GPL `-spm_coreg`/`-spm_deface` (interpolation lives once in BSD).
  - **`-deface` is the single mask-based removal command** — the supplied mask, not the command, determines what is removed (brain mask skull-strips, face mask defaces). `-warp`/`-interp`/`-source_automask`/`-dark_automask` force the ordinary engine (rejected with an explicit `-cost fast`). Fast-deface removed-region Dice vs `-cost hel` ≈ 0.985–0.999 at ~15× speed — broad agreement, NOT byte-stable across builds.
  - **Registration direction (MUST):** register the SUBJECT onto the TEMPLATE (`al_register(input, tmpl)` ordinary; `coreg_fast_estimate(input, tmpl)` fast — base=template, the well-posed direction), then INVERT to pull the template-space mask onto the subject grid: ordinary via `GA_setup_affine`→`nifti_mat44_inverse`→`nii_reslice_affine`; fast passes `nifti_mat44_inverse(res.fixed_to_moving)` to `nii_apply_affine(mask, input, …)`. Registering a brain-only template ONTO a full-head subject (base=subject) converges to a mislocated transform and masks the wrong region — do NOT do it.
  - **`nii_deface` rejects 4D input** (`al_dims_ok`): the face mask covers one volume, so 4D would leave faces in volumes 2..N (privacy failure). **`-allineate`, by contrast, auto-crops a genuine 4D moving image to volume 0** (== `-crop 0 1`, with a warning) in `nifti_allineate_wrap` (after the `-applymat` early-return, so applymat still rejects 4D); a >4D vector/tensor moving image is rejected.
  - **`-fill auto|zero|nan`** (`-allineate` output reslice only, gated at parse time by `AL_CAP_FILL`; **rejected for `-deface`**, whose fill stays the image minimum for mask safety): `auto` (default) zero-fills unless the source's darkest finite voxel is <0 (CT/HU air ≈ -1000), then fills with that minimum so out-of-FOV reads as air not soft tissue (positive-only MRI output stays byte-identical to historical); `zero` always 0; `nan` NaN. Resolved by shared `al_resolve_fillv()` / `al_image_fillv()` (scaled/non-float32 takes a converting `nii_to_float` copy so AUTO sees negative HU in raw int16 CT), both magnitude-guarded (TU is `-ffast-math`). The fused-warp path writes 0 then `al_fill_fused_oob()` rewrites only out-of-FOV voxels via the kernel's exact FOV predicate; `nii_apply_affine` paths pass the resolved fill directly.
- **coreg_fast.c/.h** — fast affine coreg engine (see the authoritative selector mapping under Shared-code invariant). Clean-room, NOT AFNI/GPL. **Shared with the standalone allineate project** (sync both ways). `coreg_fast_estimate()` does not mutate inputs — returns a world-mm FIXED→MOVING `mat44`; caller applies once. Cost reductions use fixed `CF_CR_NCHUNK=64` disjoint chunks in fixed order → deterministic per team size.
  - **Build gotcha:** coreFLT.c references `coreg_fast_estimate` unconditionally under `HAVE_ALLINEATE`, so every allineate-enabled build MUST link it (native `coreg_fast.o`, wasm `cf_wasm.o`, CMake `ADDITIONAL_SRCS`, notarize `AL_SRCS`). Blurs its pyramid via exported `nifti_smooth_gauss_f32`/`_f64`; multi-volume smoothing passes per-volume dims — **do NOT introduce shared `nx`/`ny`/`nz` here (4D OpenMP race).**
  - **Partial-FOV cost:** HEL/CR form statistics from the image INTERSECTION — out-of-FOV moving samples are excluded (`if(!ok) continue`), NOT filled with `m_bg` (else a partial-coverage moving image distorts toward scale/shear). A floor (`nin < 0.10*ns || nin < 16 → CF_PENALTY`) rejects degenerate tiny overlap; exclusion is inside each fixed chunk so determinism holds; LS keeps the `m_bg` fill.
  - **Initialization:** default/`-cmass` scores the supplied affine and exact-COM starts once at 8 mm, then runs only the winning descent; `-com` forces a recentered header, `-nocmass` forces the supplied affine. Translation guard ±128 mm.
  - **Contract:** fixed 12-DOF schedule; fail-closed rejects `-warp`/`-interp`/`-source_automask`/`-dark_automask`/`-zoom`. The `-com`/`-sym`/`-symd`/`-symb` header seeds ARE honored (dispatch applies them to the moving header before the branch, so `-cost fast -sym` is accepted). `-cost` last-one-wins; both-form-codes-zero input uses the shared pixdim-centered fallback.
  - **Reslice fill safety:** cubic reslicing clamps only in-FOV voxels (`nii_reslice_affine` inline; `al_scalar_warpone` via `al_clip_fused_cubic_infov`) so a positive-only source's out-of-FOV fill stays 0 — clamping it up to source min is a defacing mask-safety hazard.
  - **`-weight <img>` (AFNI-style graded base-space weight, BOTH engines):** optional base(fixed)-space region image (parsed through shared `al_parse_subopts` under `AL_CAP_WEIGHT` — `-allineate`/`-reface` accept it, `-deface` rejects it at parse time) whose dims AND world frame must match the base. Normalized to `[0,1]` (÷ max), GRADED per base voxel; it is NOT a hard/exclusion mask. **Ordinary engine:** user weight REPLACES the manufactured autoweight and stays GRADED for EVERY cost including box-mode histogram costs — we never binarize a user `-weight` (only the manufactured autoweight is boxed). **Fast engine:** normalizes over the WHOLE fixed grid, applies the weight ONLY at the finest (2 mm, `lv==2`) level — 8 mm rigid capture, 4 mm global-scale bracket, and seed selection stay UNWEIGHTED/whole-head so a brain-concentrated weight cannot hijack global-scale SELECTION (else a scalp-shrink basin); **rejected with LS.** **Keep the out-of-ROI head attenuated (nonzero), not zeroed** — masking the cost to the ROI alone leaves global isotropic scale underdetermined (ill-conditioned scalp-shrink collapse). Negatives/NaN/+Inf clamp to 0 at full resolution before the blur; fast engine rejects a weight with no positive support over the fixed foreground (`wmax==0`); weight is sampled by fixed VOXEL INDEX (never resampled) so the 8-corner frame check uses a TIGHT header-rounding tolerance (~1/20 voxel), rejecting even a sub-half-voxel origin shift.
  - **niimath `-allineate` dispatch (`nifti_allineate_wrap`):** `-weight` honored by BOTH engines; preflighted for oversize, rejected for stdin (`-`) and with `-applymat`. `-reface` honors it too. When `-weight` is given and the DEFAULT fast engine fails, it DOES fall back to the ordinary Hellinger engine and the fallback HONORS the weight; an explicit `-cost fast`/`fastcr` never falls back. Provenance recorded in `-savemat` JSON (`"weight"` key, omitted when unweighted); unweighted leaves every fast cost ×1.0 → bit-identical to before.
- **Fast-engine multi-start / NMS invariants.** `cf_make_samples()` clears previous arrays/counts/accumulator before rebuilding; any degeneracy or partial-alloc failure leaves an empty consistent state, aborts every remaining strategy, skips winner polish, leaves `*result` unchanged (prevents a later hard-zero strategy combining stale `ns` with partial arrays). Exploratory angular NMS repeatedly picks the global lowest cost (enumeration order breaks ties) and accepts only candidates ≥20° from every retained basin; non-positive/non-finite separation fails closed. Keep the bounded comparator-free scan for WASM.
- **powell_newuoa.c** (~2.8k lines) — Powell NEWUOA derivative-free optimizer (f2c translation). **Shared with the standalone allineate project.** Thread-safe statics use `AL_THREAD_LOCAL` (`al_thread_local.h`); `powell_newuoa_free_threadlocal()` releases the per-thread `pn_w`, called from `al_register` teardown.
  - **KEY gotcha — `mfac`/`afac` (NEWUOA sampling factors, `powell_set_mfac`) are thread-local**, so a main-thread `powell_set_mfac()` does NOT configure OpenMP workers. Every parallel `powell_newuoa()` loop MUST capture factors via `powell_get_mfac()` before the region, re-apply `powell_set_mfac()` inside the body, and restore the worker's prior factors afterward — else workers use stale `npt`, results become thread-count-dependent, or caller config leaks into persistent workers.
  - Direct-call `ndim` and sampling factors checked with `size_t` before NEWUOA's quadratic f2c workspace expressions; oversized shape returns `-8` before allocation/callback. **Fail-closed OOM:** `pn_w` alloc failure returns `-7` (never calls `newuoa_` with NULL) and propagates through `al_scalar_optim()` (`-3` on its own `wpar` failure) to `al_register()`, which aborts via `goto al_cleanup`; parallel candidate loops mark a failed optim `AL_BIGVAL`. The cost path is fail-closed too (`GA_get_warped_values()`, `GA_scalar_fitter()` returning `AL_BIGVAL` rather than scoring a stale `avm`, and `al_scalar_setup()` leaving `stup->setup=0`, verified at the three `al_register` sites) — an optimizer/setup OOM is a clean error exit, never a silent unrefined registration.
- **reface.c/.h** — **`-reface <tmpl> <shell> <weight>`: anonymization by face replacement** (clean-room emulation of AFNI `afni_refacer2 -mode_reface`; no AFNI source copied). Dispatched from coreFLT.c (`nifti_reface_wrap`, DT32 only). Registers the SUBJECT (moving) onto the TEMPLATE (fixed, same well-posed direction as `-deface`) with EITHER engine, back-projects the signed template-space `shell` onto the ORIGINAL subject grid (NN, so -/0/+ labels survive), despeckles (`reface_isola` = AFNI `3dcalc -isola`), then composites in place (`reface_apply`): shell>0 → shell × a brightness-match factor `ifac`; shell==0 → `max(subject,0)`; shell<0 → 0; then a normalized Gaussian blur INSIDE the shell>0 mask (niimath's own `nifti_smooth_gauss_f32`, NOT AFNI's GPL `3dBlurInMask`). Output stays on the subject grid.
  - **`weight` is REQUIRED** (3rd positional arg, reused as the registration `-weight`). niimath FAILS CLOSED for privacy (refuses to write output) if <10% of the shell face volume mapped into the subject FOV. Coverage fraction uses each image's `|det(coded transform)|` physical voxel volume (`reface_voxvol_mm3`, `xyz_units`-normalized), NOT the pixdim product. **This coverage gate (metric + <10% threshold) is duplicated, non-shared, in the standalone allineate's `do_reface` (main.c) — keep the two semantically byte-aligned when either changes.** `reface_apply` is fail-atomic (bad/mismatched/non-float input, empty overlap, non-finite `ifac`, alloc/blur failure → nonzero, `*result=NULL`, `nim` unchanged) and serial/bit-identical at `-p 1` vs `-p N`. **Shared byte-identically with the standalone**; `reface.o` in `ALOBJS` (no separate flag).
- **qwarp.c/.h** — **`-qwarp <base>`: nonlinear (deformable) registration** — ATTRIBUTED public-domain PORT of AFNI `3dQwarp -blur 0 3` (Robert W. Cox / NIMH, pinned AFNI rev 506e48403), NOT clean-room. AFNI GPL/MCW utilities on this path (`edt_blur.c`, `edt_buildmask.c`, `cs_qmed.c`) are NOT ported — supplied by niimath's own BSD/public-domain code; nothing taken from any GPL AFNI file or `src/GPL/`. Optimizer is Powell NEWUOA. Scope: the nonlinear STAGE ONLY (`qwarp_run`) — `moving` must ALREADY be unifized + skull-stripped + affine-aligned + share the stationary grid (equal dims, agreeing voxel→world; validated tightly, fails hard otherwise). Input and padded volumes must fit both `INT_MAX` and `AL_SIZE_MAX/sizeof(float)`. Serial-safe but non-reentrant (NEWUOA process-global context — do not overlap `qwarp_run()` across host threads); OpenMP inside. Dispatched from coreFLT.c (`nifti_qwarp_wrap`, DT32) as an ORDINARY chain op taking a single `<base>` (further ops may follow; NOT terminal). `QWARP=1` only, OFF by default, REQUIRES allineate (not `AL=0`). `QW_VERB=1` per-level trace. **Shared byte-identically with the standalone.**

### Mesh code (nii2mesh — unique to niimath)
- **meshify.c** — main mesh pipeline: smoothing → marching cubes → welding → degenerate removal → export
- **MarchingCubes.c/.h** — newer implementation with ambiguity resolution
- **oldcubes.c/.h** — classic marching cubes (`USE_CLASSIC_CUBES`)
- **quadric.c** — mesh simplification via quadric error metrics
- **meshtypes.h** — `vec3d`, `vec3i` structs

### Supporting modules
- **dtifit.c** — `--dtifit`: linear diffusion tensor fit emulating FSL `dtifit`. Self-contained TU dispatched early in `main()`. 7-param log-linear OLS (fit math from AFNI 3dDWItoDT linear path, public domain), reuses `EIG_tsfunc` (tensor.c) for FA/MD/L*/V*. Emulates FSL's determinant-based bvec x-flip; `--wls`/`--kurt` error clearly. **Gotchas:** tensor buffer must use NIfTI planar (volume-major) layout; validate V* with `|cos angle|` not Pearson r (eigenvector sign arbitrary).
- **romeo.c/.h** — **`-romeo <mag|none> [opts]`: ROMEO phase unwrapping**, a faithful MIT-licensed port of [ROMEO.jl](https://github.com/korbinian90/ROMEO.jl) v1.4.0 plus the `MriResearchTools.jl` helpers its CLI uses, and Julia Base's `rem2pi`. Notices in `src/romeo.LICENSE`. Ordinary chain op, **DT32 only**, `HAVE_ROMEO` (`ROMEO=0` disables, and implies `MEDIC=0`). `-B` computes a B0 map without MCPC-3D-S; out-of-scope options are **rejected at parse time**, never silently ignored.
  - **STRICT FP IS LOAD-BEARING, not style.** Growth order is decided by 8-bit integer edge weights; the repo-wide `-ffast-math` reassociates a weight past a bin boundary and a whole region shifts by 2π. Shipped `-fno-fast-math -ffp-contract=off`; compute is 0.02 s either way. **Never re-evaluate the FP policy on a single volume** — that shortcut once produced a wrong "FMA is clean" claim; run the full parity suite.
  - **Every build inventory compiles romeo separately**, and **non-default targets MUST NOT write `romeo.o`** (an instrumented object newer than the source with an unchanged flag stamp makes `make all` skip the rebuild and fail to link). `romeo.o` has its OWN flag stamp (`.romeo_obj_flags`), independent of `.al_obj_flags`.
  - **The porting traps are documented in romeo.c at the point of use, in more depth than belongs here** — Julia's non-uniform Float32/Float64 promotion across the six weight terms, round-half-to-**even**, the ported (not approximated) `rem2pi`, the pinned registry `Statistics` quantile, `unwrapedge!`'s two `unwrapvoxel` methods, `Base.minmax` propagating NaN to BOTH endpoints, mask truth evaluated in the STORED width, and the single-seed shortcut that only holds while `-max-seeds` is 1. Read that header before touching any of it; several are invisible to the oracle.
  - **Not reusable despite looking similar:** `nifti_smooth_gauss` vs `robustmask`'s asymmetric box filter; `nifti_robust_range`/`nifti_otsu` vs exact type-7 quantiles; `bwlabel.c` vs the local 6-connected `imfill`. Substituting any of them changes the mask.
  - **`romeo_unwrap_frame()` / `romeo_robustmask()`** are the in-memory entry points used by `--medic`; they share ONE body (`rm_core_run`) with `romeo_run()`, so the CLI and MEDIC cannot drift. Validation (602 checks vs a pinned Julia oracle) lives in **`medic_bench`**.
- **medic.c/.h** — **`--medic`: MEDIC multi-echo distortion correction** (terminal subcommand, parses its own argv) and **`-unwarp <map> <axis>`** (ordinary chain op, resamples through a scalar displacement map in mm). `HAVE_MEDIC`, which **requires `HAVE_ROMEO`** — `ROMEO=0` silently implies `MEDIC=0` in the Makefile and CMake hard-errors on the combination. DT32 only. Ordinary FP (measured — it does NOT need romeo.c's strict-FP treatment), so it rides the normal source line.
  - Clean-room emulation of the published MEDIC workflow; no warpkit source was read. Phase unwrapping calls `romeo_unwrap_frame()` in memory — MEDIC does not duplicate ROMEO and does not shell out per frame.
  - **Conventions and open questions are in `medic_bench`'s `test/medic_reference_manifest.md`.** The traps worth knowing before touching it: the phase-encoding polarity suffix is load-bearing (ignoring `-` corrects `j-` data backwards); the finiteness gate belongs on the field series AFTER regression, not inside the low-rank filter (else a NaN silently zeroes every output at exit 0); output publication is a backup/restore transaction and is **recoverable, not atomic**; and the low-rank stage is labelled EXPERIMENTAL (`--rank 0` disables it) because one residual could not be reproduced.

- **moco.c/.h** — **`-moco [-1Dfile <path.1D>]`: rigid-body motion correction** of a 4D series onto volume 0 (`niimath bold -moco out`). Ordinary chain op, **DT32 only**, 4D with `nt > 1` only, guarded (deliberately NOT in `kHugeSafeOps`), ordinary FP. **Default-ON only on Apple Silicon macOS** — `MOCO=1` / `-DENABLE_MOCO=ON` opts in elsewhere; the gate is about VALIDATION, not portability, and CMake keys it off `CMAKE_OSX_ARCHITECTURES` when set (it does NOT change `CMAKE_SYSTEM_PROCESSOR`, so a universal build would otherwise ship the feature in the x86_64 slice).
  - **Clean-room, and the licence boundary is the point.** Implements Cox & Jesmanowicz 1999 (MRM 42:1014-1018). AFNI's `3dvolreg.c`, `mri_3dalign.c`, `thd_rot3d.c`, `thd_shear3d.c` are ALL **MCW GPL-2** and were used only as black-box oracles, never read — in contrast to `mri_genalign.c` (no MCW header, public domain), which is why `allineate.c` could be adapted. Do not open those four files.
  - **Every measured convention, and the experiment behind it, is in `moco_bench`'s `test/moco_reference_manifest.md`** — read it before changing any constant. The ones that silently corrupt results if lost: heptic 8-tap Lagrange default (no FFT anywhere); `-clipit` on by default, clipping each output sub-brick to its own INPUT range; angles compose as `Ry(yaw)·Rx(pitch)·Rz(roll)`; rotation about the grid centre `(n−1)/2` in mm; sform **obliquity ignored** (storage axes, nearest-axis snapping); the weight is a blurred base with a 5% `-edging` border and a 2.5%-of-max clip; the estimator linearizes about **IDENTITY** (warp the MOVING volume back, never the base forward); and it fits a **seventh parameter, an intensity scale** — without it a run whose volumes are dimmer than the base folds the brightness step into the motion.
  - **`-1Dfile` must end in `.1D`** (enforced at parse time, so a parameter file can never name a NIfTI output and be silently replaced by the image writer), and it is published BEFORE the image, so a later image-write failure leaves a valid `.1D` with no image. Do not restate this as unconditional fail-atomicity.
- **qc.c** — `--qc`: MRIQC-style anatomical IQMs from a T1 + hard integer segmentation, written as a wide TSV. (2) `cnr_noair` drops MRIQC's `σ_bg²` → biased high, not comparable to MRIQC norms (renamed to flag it). (3) `efc_brain` excludes zero voxels from its support. ### AFNI-fidelity note (allineate coarse search)
The coarse random+grid search (`al_scalar_ransetup`, port of AFNI `mri_genalign_scalar_ransetup`) is deliberately AFNI-faithful, matching values verbatim: `PARAM_MAXTRIAL=29`, `NKEEP=3*PARAM_MAXTRIAL+1=88`, the `nrand≥NKEEP+13=101` floor, `DEFAULT_TBEST=5`/`DEFAULT_TBEST_LPA=17`, and the `vol_src>1.3*vol_base→tbest=PARAM_MAXTRIAL` largeness branch. ## Memory Management

- **Use plain `malloc`/`calloc`/`free` everywhere.** Do NOT reintroduce `_mm_malloc`/`_mm_free` or `arm_malloc.h` — the 64-byte alignment was never load-bearing (SSE-only 128-bit unaligned loads; malloc's 16-byte alignment already prevents cache-line splits; memory-bandwidth-bound).
- **`nim->data` ownership invariant:** any buffer assigned to `nim->data` MUST come from plain `malloc`/`calloc`, because `nifti_image_free()` and core.c's datatype conversion release it with plain `free()`. On MSVC `_mm_malloc` → `_aligned_malloc`, which `free()` cannot release — plain `free()` on it corrupts the heap (STATUS_HEAP_CORRUPTION 0xC0000374 at teardown). Use **`nii_calloc(count, size)`** (core.c/core.h) for `nim->data`: a fail-closed allocator running `count`×`size` through checked-multiply `nii_mul_size()` and `exit(EXIT_FAILURE)` on overflow/NULL. **`nii_malloc(count, size)`** is the UN-zeroed sibling (same check + exit, plain `malloc`) for a `nim->data` buffer the caller FULLY overwrites before any read (datatype-conversion output loops); use `nii_calloc` if any voxel could be left unwritten (RGB/complex convert buffers stay `calloc`). Callers still pre-compute overflow-prone products with `nii_mul_size()`.
- Kernel arrays: 4-int-per-voxel layout (offset, x, y, weight); plain `malloc`.
- NIfTI images: managed by `nifti_image_free()`.
- MarchingCubes.c: constructor/destructor (`MarchingCubes()`/`FreeMarchingCubes()`) with `clean_all()`.

## Huge image support (> INT_MAX voxels, issue #67)

The core calculator processes images whose 3D `nx·ny·nz` or total 4D `nvox` exceeds `INT_MAX` (≈2.15 G voxels ≈8.6 GB float32) instead of rejecting them.

- **`nvox_t` (core.h)** is the voxel count/index type: **signed** `int64_t` by default (neighborhood/kernel/reverse loops need negative intermediates that unsigned `size_t` would wrap), or `int32_t` under `-DFORCE_INT32_MAX`. `size_t` stays for byte-size allocation only.
- **Scope.** Converted (nvox_t/`size_t`-safe): scalar & image binary ops, per-voxel unary math, temporal reductions (`nifti_dim_reduce`), robust-range percentile, Gaussian smoothing. Everything else — kernel morphology `-fmean`/`-ero`/`-dilF`, `-edge`/`-index`/`-rank`/`-pval`, EDT/tfce/resize/subsamp, allineate/deface/mesh/dtifit/qc/bwlabel/bmp/fdr — keeps int indexing and is **guarded** (rejected on huge input).
- **Fail-closed admission.** A huge image runs only if its op is an exact `strcmp` member of `kHugeSafeOps[]`. `nii_admit_file_before_load()` gates before the payload read (resolving the real first op past output/`-odt`, the RGB ×3/×4 effective count, pass-through/conversion-only); `nii_admit_current_op()` re-checks at the top of every op-loop iteration against the CURRENT image (catches `-restart`, a binary op adopting a huge operand, RGB expansion). stdin/`.nii.zst` skip the pre-read gate and are caught post-load. `nii_reject_oversize_aux()` header-rejects an oversized auxiliary (reslice mask/base, deface template/mask, `-allineate -weight`, bitmap) before its load — EXCEPT a `.nii.zst` auxiliary (no bounded header-only path; caught post-load — accepted limitation). Robust-range/Otsu reject an intensity span their histogram cannot represent (avoids undefined `(int)NaN`). **To promote a guarded op: make its kernel `nvox_t`-clean AND add a `test/huge_smoke.py` case.**
- **`nii_nvox_classify()` (core.c)** is the single geometry validator → {invalid, INT-safe, huge}; `nii_nvox3d_int`/`nii_nvox3d` are its narrow/wide adapters.
- **`-DFORCE_INT32_MAX` on every 32-bit/wasm build (MUST).** wasm32 has a 4 GB ceiling; the `tiny`/`wasm`/`wasm-wasi`/`wasm-emcc-core` Makefile targets and CMake `tiny`/32-bit set it; every huge image is rejected there. Core ops are byte-identical to the pre-#67 build at ≤INT_MAX sizes.
- **Testing.** `test/huge_smoke.py <binary>` — opt-in/manual (~9 GB RAM; not in CI): sparse >INT_MAX NIfTIs. Allocation-free reject cases run in `make test` via `release_smoke.py`.
- **Reach goals (deferred).** Re-add `-Tstd/-Tmedian/-Tperc/-Tar1` to `kHugeSafeOps` (only a huge_smoke oracle missing); convert the neighborhood/morphology kernels. Non-goals: registration/mesh/tfce/resize; streaming `.nii.zst` + >2 GB Win64 offsets.

## Known Remaining Issues

1. **NULL checks** — ~26 unchecked malloc/calloc calls remain in MarchingCubes.c (6), oldcubes.c (3), quadric.c (17); meshify.c largely fixed.
2. **Build feature-list drift** — the feature source/define inventory is duplicated across `src/Makefile` (incl. the zlib-free `WASI_SRCS`/`wasm-emcc-core` lists), `src/CMakeLists.txt`, `src/notarize.sh`, and `SuperBuild/SuperBuild.cmake` (which forwards each feature's `ENABLE_*` option; `OPENMP_XCODE` MUST default to `${USE_OPENMP}` so the Apple universal build's `-DOPENMP_XCODE=OFF` still disables OpenMP). Adding a feature means touching all of them. **ROMEO sharpens this:** `romeo.c` must be compiled strict-FP, so it cannot ride a shared fast-math source line — EVERY recipe needs its own `romeo*.o` compile step, not merely a source-list entry. **MEDIC** (`MEDICFLAGS`) reaches Makefile `all`/`native-noomp`/`static`/`debug`/`verbose`/`ubsan`/`sanitize`, the Emscripten `wasm` target via its own `MEDIC_WASM` (deliberately not folded into `QC_WASM`, so `QC=0 make wasm` cannot silently drop it), CMake, SuperBuild and `notarize.sh`; it is **deliberately absent** from `WASI_SRCS`, `wasm-emcc-core`, `tiny` and `nano`. **MOCO** (`MOCOFLAGS`, `MOCO_WASM`, `ENABLE_MOCO`) reaches the Makefile targets, the Emscripten `wasm` target, CMake, SuperBuild and `notarize.sh`; like MEDIC it is **deliberately absent** from `WASI_SRCS`, `wasm-emcc-core`, `tiny` and `nano`. Its help line in `niimath.c` is `#ifdef`-paired, so a `MOCO=0` build still advertises how to re-enable it.
3. **Whole-program `-ffast-math` (all build systems).** Make, CMake (non-MSVC `CMAKE_C_FLAGS`), notarize.sh, and wasm compile the entire program `-ffast-math -fno-finite-math-only`; MSVC stays strict. **One standing exception:** `romeo.c` is compiled strict-FP (`-fno-fast-math -ffp-contract=off`; MSVC `/fp:precise`) in every build system and linked as a separate object (see the romeo.c entry). Registration must round like the standalone/fslmaths goldens (shared `nifti_io` mat44 helpers run during the fit); scoping it to registration TUs made CMake/notarize/wasm diverge. Also covers core ops, GPL `-spm_coreg`, dtifit/tensor — re-validate the SPM golden and dtifit/tensor if you touch those. `-fno-finite-math-only` preserves NaN/Inf detection; fast-math-sensitive finiteness checks use magnitude guards (e.g. `v >= -DBL_MAX && v <= DBL_MAX`).
4. **Prebuilt-object flag stamp.** `allineate.o`/`powell_newuoa.o`/`coreg_fast.o` depend on a flag-signature stamp (`.al_obj_flags` = `CNAME|CFLAGS|AFLAGS`) so `make` → `make OMP=0 all` relinks cleanly with no `make -B` — else a stale object fails to link on `__kmpc_*`/`omp_*`. Extend `AL_OBJ_SIG` for a new object-affecting flag outside `CFLAGS`. `romeo.o` has its OWN independent stamp (`.romeo_obj_flags` = `CNAME|CFLAGS|ROMEOFLAGS|ROMEO_STRICT_FP`, Makefile `ROMEO_OBJ_SIG`) because it must rebuild on a flag change even in an `AL=0` build where `.al_obj_flags` is unused; and the non-default targets MUST write `romeo_<target>.o`, never `romeo.o`, or `make all` finds an instrumented object newer than the source with an unchanged stamp and fails to link.
5. **Output-write failures propagate.** `nifti_image_write_status` returns 0/1 (open, short header/data write, compressor/close/pclose errors incl. disk-full at close); `void nifti_image_write` remains a compatibility wrapper. `nifti_save` uses the status API; main dispatch, pass-through, and intermediate `-save` sites propagate it; multi-output `--dtifit`/`-tensor_decomp` OR every status. Preserve — a failed/partial write must report failure, not exit 0.
6. **`nifti_io.c` upstream debt** — LLP64 builds still use `long` in the internal seek wrapper, limiting >2 GiB Windows offsets; a future upstream sync should move that to the platform's 64-bit seek API. Crafted payload-size multiplication, NIfTI-2 header probing, stdin polling, and piped-input cleanup are already hardened locally; preserve those on upgrade.
7. **Registration mislabels metre/micron coordinates as mm.** `al_image_xform`/`al_image_xform_or_pixdim` (allineate.c) return raw NIfTI sform/qform/pixdim coordinates in the header's `xyz_units`, but the registration schedules (translation guards, blur mm), the fast engine bounds, and `-savemat` (`"units":"mm"`) all treat them as world-mm. A legal metre (or micron) image thus gets a 1000× (or 0.001×) physical schedule and a false-unit saved matrix; deferred only because practical exposure is ~nil (neuroimaging NIfTIs are mm). **The fix is a COORDINATED change, not a one-line seam scale:** reface already normalizes independently via `reface_voxvol_mm3(…, xyz_units)`, so scaling the transform at the seam would DOUBLE-normalize the privacy-critical reface coverage gate — the seam normalization and the reface `reface_voxvol_mm3` de-normalization must land together, be mirrored to `codex/allineate` (both the shared seam and the standalone's own `do_reface`), and ship with a mm/metre/micron equivalence test (the `release_smoke.py` `nifti_header(scale=, xyz_units=)` helper already supports it). mm images must stay byte-identical (factor 1.0).

## Optimization Constraints

- Voxel ops are lean, SIMD-optimized, mostly memory-bandwidth limited. OpenMP is **not the primary optimization target** for core ops (typical usage runs one subject per thread across many subjects). zlib-ng (CMake release baseline, `ZLIB_IMPLEMENTATION=zlib-ng`, ZLIB_COMPAT) gives ~2× `.nii.gz` I/O over stock zlib (correct on MSVC where Cloudflare is not). The Emscripten `wasm` target links it via `WASM_ZLIB`.
- **Allineate reproducibility:** `-allineate` is byte-reproducible **across thread counts** (nt=1/2/4/8) — preserved by the `mfac` thread-local re-apply rule. It is **NOT bit-reproducible across builds**: NEWUOA + `-ffast-math` means a codegen change can flip the optimizer to a neighboring equally-valid optimum (sub-voxel parameter shift, ~1% in a few edge voxels). Quality unchanged (cost and base-correlation match to 4+ digits) — do NOT treat `-allineate` output as a byte-stable golden across versions. `gpl-build.yml` gates registration by QUALITY (correlation floor + improvement-over-baseline via `reg_quality.py`, fails closed on empty/constant/non-finite), not a byte diff. `-deface`/`-spm_deface` reslice via `nii_reslice_affine` (not the fused path) and stay byte-stable.

### WASM performance pitfalls (two hard-won rules)
1. **No `qsort`+comparator on large or per-voxel arrays in WASM-targeted code.** emscripten/musl `qsort` calls the comparator via `call_indirect` per comparison (~100× slower than native — can make the WASM build appear to hang). Use comparator-free: **quickselect** for a single value (`al_select_rank`, `select_kth_flt`, `uf_select`), **insertion sort** for genuinely small fixed N only (NOT a per-voxel neighborhood — O(n²) per voxel), or **heapsort** for a full order on large arrays (`heapsort_sortIdx`). The only remaining `qsort` is `qsort_floatint` on ~46-element lists.
2. **WASM allineate MUST be compiled `-ffast-math` (matching native)**, or the cost-function reduction rounds differently and NEWUOA/Powell converges to a worse optimum (`-deface` masked 37% vs 60% native). The `wasm:` target and its prebuilt `al_wasm.o`/`pn_wasm.o`/`cf_wasm.o` use whole-program `-ffast-math -fno-finite-math-only`. (`-msimd128` adds only ~3% — not worth the golden-match risk.)

## Code Conventions
- C99 with extensive `#ifdef` for conditional compilation.
- Template pattern: coreFLT.c compiled as both float32 and float64 via macro inclusion.
- Naming: `nifti_*` for NIfTI operations, `nii_*` for internal helpers.
- Explicit SIMD (Intel intrinsics via `immintrin.h`) only on `__x86_64__`; ARM/WASM use scalar fallbacks (clang `-O3` auto-vectorizes to NEON just as fast; memory-bandwidth bound). No `sse2neon.h` shim.
- Error returns: `EXIT_SUCCESS`/`EXIT_FAILURE`.
