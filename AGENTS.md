This file provides guidance for AI agents when working with code in this repository.

## Project Overview

niimath is an open-source clone of FSL's `fslmaths` — a general-purpose NIfTI image calculator for neuroimaging. It extends fslmaths with mesh generation (nii2mesh), extra filters, defacing (`-deface`), affine registration (`-allineate`), anatomical QC (`--qc`), zstd compression (.nii.zst), and cross-platform support (Linux, macOS, Windows, WebAssembly).

**Repository:** `rordenlab/niimath` (BSD-2-Clause license)

## Building

### Quick build (Makefile, recommended for development)
```bash
cd src && make          # Standard optimized build (OpenMP enabled by default)
make debug              # Debug build (-g, no optimization)
make ubsan              # UndefinedBehaviorSanitizer (lightweight; retains OpenMP)
make sanitize           # AddressSanitizer (serial on Apple Clang; no leak detection on macOS)
make verbose            # All warnings
make static             # Static binary
```

### Prerequisites
- **macOS**: `brew install libomp zstd`
- **Linux**: `apt install libzstd-dev` (OpenMP built-in with gcc)

### Build variants
```bash
make tiny               # Minimal terminal build (emulates WASM constraints)
make nano               # Without mesh (nii2mesh)
MESH=0 make             # Disable mesh support
AL=0 make               # Disable allineate registration
DTIFIT=0 make           # Disable dtifit
QC=0 make               # Disable anatomical QC (--qc)
ROMEO=0 make            # Disable ROMEO phase unwrapping (-romeo); implies MEDIC=0
MEDIC=0 make            # Disable MEDIC distortion correction (--medic, -unwarp)
MOCO=0 make             # Disable motion correction (-moco)
STC=0 make              # Disable slice-time correction (-stc)
SKULLSTRIP=1 make       # Enable AFNI-style surface skull stripping (-skullstrip); OFF by default, 64-bit native only
GPL=1 make              # Enable copyleft payload: -spm_coreg/-spm_deface (needs git submodule update --init src/GPL)
QWARP=1 make            # Enable -qwarp nonlinear registration; OFF by default; needs allineate (not with AL=0)
ZSTD=0 make             # Disable zstd (.nii.zst)
OMP=0 make              # Single-threaded build
MC=0 make               # Classic table-only marching cubes (oldcubes.c) instead of the default Lewiner
Q2=1 make               # Build the half-edge reference simplifier (-mesh -n 1, quadric2.c); OFF by default everywhere
STB=1 make              # STB image library instead of libspng for bitmaps
make wasm               # Emscripten/WebAssembly
make wasm-wasi          # Experimental zlib-free WASI compute backend (needs Zig)
make wasm-emcc-core     # Feature-matched zlib-free Emscripten build (WASI benchmark baseline)
```
zlib: CMake release builds default to zlib-ng (`ZLIB_IMPLEMENTATION=zlib-ng`); plain make uses system `-lz` (`ZLIBNG_ROOT=<path>` links compat zlib-ng without CMake; wasm uses `WASM_ZLIB`).

### CMake build
```bash
mkdir build && cd build && cmake .. && make     # top-level SuperBuild
cmake -DUSE_OPENMP=OFF -DENABLE_QC=OFF ..        # toggles (forwarded by SuperBuild)
```

### Key compile-time flags
- `NII2MESH` / `DNII2MESH` — mesh conversion
- `USE_CLASSIC_CUBES` — oldcubes.c (classic tables) instead of the default MarchingCubes.c (Lewiner). **Lewiner became the default for every build on 2026-09-06**; `notarize.sh` had shipped it all along while `make`, CMake and wasm built oldcubes, so CI was testing one contouring and macOS users were getting the other. Validated before the flip: UBSan and `leaks` clean through the full `-mesh` pipeline; identical output on sphere/torus/two-sphere phantoms; on ambiguous cells Lewiner resolves against the trilinear interpolant where the classic tables apply a fixed convention (MNI: 143 vs 199 components). `-mesh -o 1` selects the classic table inside Lewiner; in an oldcubes build `-o` is silently ignored.
- `HAVE_QUADRIC2` — quadric2.c, the half-edge reference simplifier behind `-mesh -n 1`; **OFF by default in every build** (`Q2=1 make` / `-DENABLE_QUADRIC2=ON`; absent from `notarize.sh`; `Q2=1 make wasm` would include it, nothing shipped does). Without it `-n 1` fails at parse time with a message naming the flag.
- `HAVE_FORMATS` — GIfTI, OBJ, VTK, STL mesh output
- `HAVE_BMP` — bitmap/PNG creation
- `HAVE_TENSOR` — tensor decomposition
- `HAVE_DTIFIT` — linear diffusion tensor fit (`--dtifit`); needs `HAVE_TENSOR`
- `HAVE_QC` — anatomical QC (`--qc`); no tensor/mesh deps
- `HAVE_ROMEO` — ROMEO phase unwrapping (`-romeo`, romeo.c); ON by default, `ROMEO=0` / `-DENABLE_ROMEO=OFF` disables. Built as a **prebuilt STRICT-FP object** with its own `.romeo_obj_flags` stamp — see the romeo.c entry below
- `HAVE_MEDIC` — MEDIC multi-echo distortion correction (`--medic`, `-unwarp`, medic.c); ON by default. **Requires `HAVE_ROMEO`** — `ROMEO=0` silently implies `MEDIC=0` in the Makefile, and CMake hard-errors on `ENABLE_MEDIC=ON` with `ENABLE_ROMEO=OFF`. Ordinary FP (NOT a strict-FP object like romeo.c), so it rides the normal source line
- `HAVE_MOCO` — rigid-body motion correction (`-moco`, moco.c); ON for every target including WASM, `MOCO=0` / `-DENABLE_MOCO=OFF` disables. Ordinary FP, rides the normal source line
- `HAVE_STC` — slice-time correction (`-stc`, stc.c); ON for every target including WASM, `STC=0` / `-DENABLE_STC=OFF` disables. Ordinary FP, rides the normal source line
- `HAVE_SKULLSTRIP` — AFNI-style surface skull stripping (`-skullstrip`, skullstrip.c, which `#include`s `skullstrip_kernel.h` twice); **OFF by default**, `SKULLSTRIP=1` / `-DENABLE_SKULLSTRIP=ON` enables it, and only on a 64-bit native target — Makefile, CMake and SuperBuild each `$(error)`/`FATAL_ERROR` on a 32-bit, wasm, tiny or nano request rather than build a binary without the op and report success. Ordinary FP, rides the normal source line; deliberately absent from `notarize.sh`
- `HAVE_CONFORM` — image conforming to standard space
- `HAVE_ALLINEATE` — affine registration + defacing (allineate.c + powell_newuoa.c + coreg_fast.c + reface.c); release builds use whole-program `-ffast-math` + OpenMP. `reface.c` always compiled in an allineate build (no separate flag).
- `HAVE_QWARP` — `-qwarp` nonlinear registration (qwarp.c, attributed AFNI 3dQwarp port); OFF by default; `QWARP=1 make`; requires allineate/NEWUOA (not with `AL=0`).
- `HAVE_GPL` — optional copyleft payload: `-spm_coreg`/`-spm_deface` (SPM, **GPL-2-or-later**); OFF by default so builds stay BSD-2. Sources in `niimath_gpl` submodule (`src/GPL`); `GPL=1 make` / `cmake -DENABLE_GPL=ON` / `GPL=1 make wasm` (needs `git submodule update --init src/GPL`). A `GPL=1` binary is a combined copyleft work under SPM's own terms — **GPL-2 or later** (version string ends ` GPL` vs ` BSD`). It was briefly GPL-3, when the payload also carried Exstrom's LGPL-3 `bw.c` for `-bandpass`; that op was RETIRED and `bw.c` deleted, so LGPL-3 is out of the project entirely. `release_smoke.py` asserts BOTH directions on `-spm_coreg` — a BSD binary carrying it fails the gate.
- `AL_LPC_MICHO` — adds lpc+ZZ/lpa+ZZ combined cost variant (default: pure lpc/lpa)
- `HAVE_ZSTD` — .nii.zst support (auto-detected; `FSLOUTPUTTYPE=NIFTI_ZST` to write)
- `FSLSTYLE` — FSL-compatible behavior mode

## Source Architecture

### Core computational pipeline
- **niimath.c** — CLI entry point; dispatches to `main32()`/`main64()` by `-dt`. `--dtifit`/`--qc` are self-contained subcommands dispatched before the op loop. Huge-image (>INT_MAX voxel) gate (issue #67): `main32`/`main64` admit a huge working image only for whitelisted ops (fail-closed) — see **Huge image support**.
- **coreFLT.c** (~8.6k lines) — main computational engine, compiled twice via template pattern. **Op-loop gotcha for any op that takes a sub-option:** `argc` is decremented before the loop so the LAST argv is the output filename — a sub-option parser using `ac + 1 < argc` silently misses a trailing flag, which then becomes the output name — a since-removed op did exactly that: it ran a full inference and wrote a file named after its own flag at exit 0. Peek one past (`ac + 1 <= argc`; `argv[argc]` is still the valid `fout`):
  - **core32.c** — `#define DT32` + include → float32 (SSE 4-wide on x86_64; scalar ARM/WASM)
  - **core64.c** — include without DT32 → float64 (SSE 2-wide on x86_64; scalar ARM/WASM)
  - **Filter kernels.** Gaussian smoothing (`smooth_gauss_blur1d`, used by `-s`/`-dog`/unsharp/registration) uses `blur_row`: a contiguous full-symmetric kernel (`kc[i]`, not `k[abs(i)]`), lane-parallel so clang auto-vectorizes. `-fmean`/`-fmeanu`, `-dilF`/`-eroF`, binary `-ero` are O(k³) with independent per-output state, preserving each op's local NaN/±Inf behavior. A separable box-filter experiment was removed (shared running sums / monotonic deques changed those semantics; archived in `noncompliant.md`) — do NOT restore without explicit non-finite conformance tests.
  - **`-dilate <thr> <dx>`** (distance-based grow, `nifti_dilate`, distinct from kernel `-dilF`): binarizes at `thr`, grows the mask by `dx` mm — voxels within `dx` of the surface set to at least `thr` via `fmax(iso, imgIn[i])` (matching `-close`'s fill, so a grown voxel survives a re-threshold at `iso`; `fmax(1.0,..)` is wrong for `iso>1`), beyond-`dx` voxels unchanged (grow-only).
- **core.c** — shared utilities: datatype conversion, kernel creation, Otsu thresholding, resampling filters, NIfTI I/O helpers. **`max_displacement_mm()` gotcha:** returns max corner displacement between two images' world transforms; gates the `-add`/binary-op and `--compare` orientation warnings (0.5 mm) and the `--qc` grid check (0.001 mm). It measures true 3D Euclidean distance AND normalises each transform to mm via `xyz_units` (`xyz_units_to_mm`) so metre/micron headers compare correctly; touch only with that unit scaling in mind.
- **unifize.c** — bias field correction (`-unifize`; adapted from AFNI 3dUnifize, public domain).
- **allineate.c** (~5.5k lines) — affine registration, defacing, skull-stripping. **Shared byte-identically with the standalone allineate project — canonical source; sync any change both ways** (see Shared-code invariant). Twopass coarse-to-fine with a full-resolution AFNI-faithful coarse search and OpenMP-parallel candidate refinement over thread-local buffers (adapted from AFNI 3dAllineate, public domain). `al_register()` is shared by `nii_allineate()`/`nii_deface()`; `nii_reslice_affine` + `nii_apply_deface_mask` are factored out and reused by `nii_deface` and GPL `-spm_coreg`/`-spm_deface` (interpolation lives once in BSD).
  - **`-deface` is the single mask-based removal command** — the supplied mask, not the command, determines what is removed (brain mask skull-strips, face mask defaces). `-warp`/`-interp`/`-source_automask`/`-dark_automask` force the ordinary engine (rejected with an explicit `-cost fast`). Fast-deface removed-region Dice vs `-cost hel` ≈ 0.985–0.999 at ~15× speed — broad agreement, NOT byte-stable across builds.
  - **Registration direction (MUST):** register the SUBJECT onto the TEMPLATE (`al_register(input, tmpl)` ordinary; `coreg_fast_estimate(input, tmpl)` fast — base=template, the well-posed direction), then INVERT to pull the template-space mask onto the subject grid: ordinary via `GA_setup_affine`→`nifti_mat44_inverse`→`nii_reslice_affine`; fast passes `nifti_mat44_inverse(res.fixed_to_moving)` to `nii_apply_affine(mask, input, …)`. Registering a brain-only template ONTO a full-head subject (base=subject) converges to a mislocated transform and masks the wrong region — do NOT do it.
  - **`nii_deface` rejects 4D input** (`al_dims_ok`): the face mask covers one volume, so 4D would leave faces in volumes 2..N (privacy failure). **`-allineate`, by contrast, auto-crops a genuine 4D moving image to volume 0** (== `-crop 0 1`, with a warning) in `nifti_allineate_wrap` (after the `-applymat` early-return, so applymat still rejects 4D); a >4D vector/tensor moving image is rejected.
  - **`-fill auto|zero|nan`** (`-allineate` output reslice only, gated at parse time by `AL_CAP_FILL`; **rejected for `-deface`**, whose fill stays the image minimum for mask safety): `auto` (default) zero-fills unless the source's darkest finite voxel is <0 (CT/HU air ≈ -1000), then fills with that minimum so out-of-FOV reads as air not soft tissue (positive-only MRI output stays byte-identical to historical); `zero` always 0; `nan` NaN. Resolved by shared `al_resolve_fillv()` / `al_image_fillv()` (scaled/non-float32 takes a converting `nii_to_float` copy so AUTO sees negative HU in raw int16 CT), both magnitude-guarded (TU is `-ffast-math`). The fused-warp path writes 0 then `al_fill_fused_oob()` rewrites only out-of-FOV voxels via the kernel's exact FOV predicate; `nii_apply_affine` paths pass the resolved fill directly.
  - **The BLOK set MUST be built serially before every parallel candidate loop.** `al_scalar_setup()` ENDS by destroying it (`allineate.c:2818`), and `al_ensure_blokset()` is an unsynchronised check-then-write (`allineate.c:2186-2192`) reached from `GA_pearson_local` — i.e. from inside the workers. The serial warm-up eval that used to cover this is gated on `need_hist_setup`, which `al_scalar_setup` sets to `hist_cost` — **true only for Hellinger/NMI** (`allineate.c:2643-2644`; the `AL_LPC_MICHO` extension is defined by NO build system). So for `-cost lpc`/`lpa` no thread ever built it serially and N workers raced. MEASURED on a 64^3 pair: 1 thread 0 B, 2 threads 1.99 MB, 8 threads **13.08 MB leaked**, default Hellinger cost 0 B — the leak scales with team size and vanishes at `-p 1`, which is what identifies it as a race rather than a plain leak. Worse tail: a losing `create_GA_BLOK_set()` publishes NULL, after which every evaluation returns `AL_BIGVAL` and a WORSE registration ships at exit 0. Fixed by hoisting `al_ensure_blokset(&stup)` before the loops at `allineate.c:4289` and `:4414`, mirroring the coarse pass (`:2948`, `:3024`). **Do not remove those hoists**, and if you add another parallel candidate loop, hoist there too. Numerics unchanged (set contents are deterministic); `leaks` now reports 0 B.
- **coreg_fast.c/.h** — fast affine coreg engine (see the authoritative selector mapping under Shared-code invariant). Clean-room, NOT AFNI/GPL. **Shared with the standalone allineate project** (sync both ways). `coreg_fast_estimate()` does not mutate inputs — returns a world-mm FIXED→MOVING `mat44`; caller applies once. Cost reductions use fixed `CF_CR_NCHUNK=64` disjoint chunks in fixed order → deterministic per team size.
  - **Build gotcha:** coreFLT.c references `coreg_fast_estimate` unconditionally under `HAVE_ALLINEATE`, so every allineate-enabled build MUST link it (native `coreg_fast.o`, wasm `cf_wasm.o`, CMake `ADDITIONAL_SRCS`, notarize `AL_SRCS`). Blurs its pyramid via exported `nifti_smooth_gauss_f32`/`_f64`; multi-volume smoothing passes per-volume dims — **do NOT introduce shared `nx`/`ny`/`nz` here (4D OpenMP race).**
  - **Partial-FOV cost:** HEL/CR form statistics from the image INTERSECTION — out-of-FOV moving samples are excluded (`if(!ok) continue`), NOT filled with `m_bg` (else a partial-coverage moving image distorts toward scale/shear). A floor (`nin < 0.10*ns || nin < 16 → CF_PENALTY`) rejects degenerate tiny overlap; exclusion is inside each fixed chunk so determinism holds; LS keeps the `m_bg` fill.
  - **Initialization:** default/`-cmass` scores the supplied affine and exact-COM starts once at 8 mm, then runs only the winning descent; `-com` forces a recentered header, `-nocmass` forces the supplied affine. Translation guard ±128 mm.
  - **Contract:** fixed 12-DOF schedule; fail-closed rejects `-warp`/`-interp`/`-source_automask`/`-dark_automask`/`-zoom`. The `-com`/`-sym`/`-symd`/`-symb` header seeds ARE honored (dispatch applies them to the moving header before the branch, so `-cost fast -sym` is accepted). `-cost` last-one-wins; both-form-codes-zero input uses the shared pixdim-centered fallback.
  - **Reslice fill safety:** cubic reslicing clamps only in-FOV voxels (`nii_reslice_affine` inline; `al_scalar_warpone` via `al_clip_fused_cubic_infov`) so a positive-only source's out-of-FOV fill stays 0 — clamping it up to source min is a defacing mask-safety hazard.
  - **`-weight <img>` (AFNI-style graded base-space weight, BOTH engines):** optional base(fixed)-space region image (parsed through shared `al_parse_subopts` under `AL_CAP_WEIGHT` — `-allineate`/`-reface` accept it, `-deface` rejects it at parse time) whose dims AND world frame must match the base. Normalized to `[0,1]` (÷ max), GRADED per base voxel; it is NOT a hard/exclusion mask. **Ordinary engine:** user weight REPLACES the manufactured autoweight and stays GRADED for EVERY cost including box-mode histogram costs — we never binarize a user `-weight` (only the manufactured autoweight is boxed). **Fast engine:** normalizes over the WHOLE fixed grid, applies the weight ONLY at the finest (2 mm, `lv==2`) level — 8 mm rigid capture, 4 mm global-scale bracket, and seed selection stay UNWEIGHTED/whole-head so a brain-concentrated weight cannot hijack global-scale SELECTION (else a scalp-shrink basin); **rejected with LS.** **Keep the out-of-ROI head attenuated (nonzero), not zeroed** — masking the cost to the ROI alone leaves global isotropic scale underdetermined (ill-conditioned scalp-shrink collapse). Negatives/NaN/+Inf clamp to 0 at full resolution before the blur; fast engine rejects a weight with no positive support over the fixed foreground (`wmax==0`); weight is sampled by fixed VOXEL INDEX (never resampled) so the 8-corner frame check uses a TIGHT header-rounding tolerance (~1/20 voxel), rejecting even a sub-half-voxel origin shift.
  - **niimath `-allineate` dispatch (`nifti_allineate_wrap`):** `-weight` honored by BOTH engines; preflighted for oversize, rejected for stdin (`-`) and with `-applymat`. `-reface` honors it too. When `-weight` is given and the DEFAULT fast engine fails, it DOES fall back to the ordinary Hellinger engine and the fallback HONORS the weight; an explicit `-cost fast`/`fastcr` never falls back. Provenance recorded in `-savemat` JSON (`"weight"` key, omitted when unweighted); unweighted leaves every fast cost ×1.0 → bit-identical to before.
- **Fast-engine multi-start / NMS invariants.** `cf_make_samples()` clears previous arrays/counts/accumulator before rebuilding; any degeneracy or partial-alloc failure leaves an empty consistent state, aborts every remaining strategy, skips winner polish, leaves `*result` unchanged (prevents a later hard-zero strategy combining stale `ns` with partial arrays). Exploratory angular NMS repeatedly picks the global lowest cost (enumeration order breaks ties) and accepts only candidates ≥20° from every retained basin; non-positive/non-finite separation fails closed. Keep the bounded comparator-free scan for WASM.
- **powell_newuoa.c** (~2.5k lines) — Powell NEWUOA derivative-free optimizer (f2c translation). **Shared with the standalone allineate project.** Thread-safe statics use `AL_THREAD_LOCAL` (`al_thread_local.h`); `powell_newuoa_free_threadlocal()` releases the per-thread `pn_w`, called from `al_register` teardown.
  - **KEY gotcha — `mfac`/`afac` (NEWUOA sampling factors, `powell_set_mfac`) are thread-local**, so a main-thread `powell_set_mfac()` does NOT configure OpenMP workers. Every parallel `powell_newuoa()` loop MUST capture factors via `powell_get_mfac()` before the region, re-apply `powell_set_mfac()` inside the body, and restore the worker's prior factors afterward — else workers use stale `npt`, results become thread-count-dependent, or caller config leaks into persistent workers.
  - Direct-call `ndim` and sampling factors checked with `size_t` before NEWUOA's quadratic f2c workspace expressions; oversized shape returns `-8` before allocation/callback. **Fail-closed OOM:** `pn_w` alloc failure returns `-7` (never calls `newuoa_` with NULL) and propagates through `al_scalar_optim()` (`-3` on its own `wpar` failure) to `al_register()`, which aborts via `goto al_cleanup`; parallel candidate loops mark a failed optim `AL_BIGVAL`. The cost path is fail-closed too (`GA_get_warped_values()`, `GA_scalar_fitter()` returning `AL_BIGVAL` rather than scoring a stale `avm`, and `al_scalar_setup()` leaving `stup->setup=0`, verified at the three `al_register` sites) — an optimizer/setup OOM is a clean error exit, never a silent unrefined registration.
- **reface.c/.h** — **`-reface <tmpl> <shell> <weight>`: anonymization by face replacement** (clean-room emulation of AFNI `afni_refacer2 -mode_reface`; no AFNI source copied). Dispatched from coreFLT.c (`nifti_reface_wrap`, DT32 only). Registers the SUBJECT (moving) onto the TEMPLATE (fixed, same well-posed direction as `-deface`) with EITHER engine, back-projects the signed template-space `shell` onto the ORIGINAL subject grid (NN, so -/0/+ labels survive), despeckles (`reface_isola` = AFNI `3dcalc -isola`), then composites in place (`reface_apply`): shell>0 → shell × a brightness-match factor `ifac`; shell==0 → `max(subject,0)`; shell<0 → 0; then a normalized Gaussian blur INSIDE the shell>0 mask (niimath's own `nifti_smooth_gauss_f32`, NOT AFNI's GPL `3dBlurInMask`). Output stays on the subject grid.
  - **`weight` is REQUIRED** (3rd positional arg, reused as the registration `-weight`). niimath FAILS CLOSED for privacy (refuses to write output) if <10% of the shell face volume mapped into the subject FOV. Coverage fraction uses each image's `|det(coded transform)|` physical voxel volume (`reface_voxvol_mm3`, `xyz_units`-normalized), NOT the pixdim product. **This coverage gate (metric + <10% threshold) is duplicated, non-shared, in the standalone allineate's `do_reface` (main.c) — keep the two semantically byte-aligned when either changes.** `reface_apply` is fail-atomic (bad/mismatched/non-float input, empty overlap, non-finite `ifac`, alloc/blur failure → nonzero, `*result=NULL`, `nim` unchanged) and serial/bit-identical at `-p 1` vs `-p N`. **Shared byte-identically with the standalone**; `reface.o` in `ALOBJS` (no separate flag).
- **qwarp.c/.h** — **`-qwarp <base>`: nonlinear (deformable) registration** — ATTRIBUTED public-domain PORT of AFNI `3dQwarp -blur 0 3` (Robert W. Cox / NIMH, pinned AFNI rev 506e48403), NOT clean-room. The MCW-copyrighted AFNI utilities on this path (`edt_blur.c`, `edt_buildmask.c`, `cs_qmed.c` — GPL-2 when qwarp.c was written, CC BY 4.0 since the 2026 relicense) are NOT ported and stay unported either way, so the tree carries no attribution obligation; their function is supplied by niimath's own BSD/public-domain code, and nothing is taken from any MCW-copyrighted AFNI file or from `src/GPL/`. Optimizer is Powell NEWUOA. Scope: the nonlinear STAGE ONLY (`qwarp_run`) — `moving` must ALREADY be unifized + skull-stripped + affine-aligned + share the stationary grid (equal dims, agreeing voxel→world; validated tightly, fails hard otherwise). Input and padded volumes must fit both `INT_MAX` and `AL_SIZE_MAX/sizeof(float)`. Serial-safe but non-reentrant (NEWUOA process-global context — do not overlap `qwarp_run()` across host threads); OpenMP inside. Dispatched from coreFLT.c (`nifti_qwarp_wrap`, DT32) as an ORDINARY chain op taking a single `<base>` (further ops may follow; NOT terminal). `QWARP=1` only, OFF by default, REQUIRES allineate (not `AL=0`). `QW_VERB=1` per-level trace. **Shared byte-identically with the standalone.**
  - **`-qwarp` is NOT byte-reproducible across thread counts, and it is the ONLY op here that isn't.** `qw_incor_addto` (`qwarp.c:896`, `:911`) and `qw_load_energy` (`:689`) use plain `reduction(+:)` on doubles, and they sit directly under the NEWUOA callback (`qw_scalar_costfun` -> `qw_incor_eval`), so the summation order changes with team size and the optimizer lands on a neighbouring optimum. MEASURED on a 96x128x128 pair: p1 vs p8 differ on **345,161 of 1,572,864 voxels (21.9%)**, max abs diff 434 of a 1500 range — but the same team size reruns BYTE-IDENTICAL, and quality is unaffected (`r(out,base)` 0.97597 / 0.97560 / 0.97605 at p1/p4/p8 against 0.89970 for the input). The spread grows as the cost landscape flattens: on an ill-posed cross-modality pair, 15.6% of voxels and `r(p1,p8) = 0.920`. So the cost is REPRODUCIBILITY, not accuracy — a `-qwarp` result cannot be reproduced from the command line and input alone, you also need `-p`. **This is called out because a reader will generalise from the ops around it:** `-allineate`, `-stc` and `-skullstrip` are all documented as byte-reproducible across thread counts, and `-skullstrip`'s own bullet states the rule (`max` is exact, `+` on doubles is not, use `coreg_fast.c`'s fixed-chunk `CF_CR_NCHUNK` pattern). `-qwarp` violates that rule. Nothing gates it — AppVeyor only checks `-qwarp` dispatch/rejection and never runs a warp. `QWARP=1` is off by default, so this blocks nothing today; the fixed-chunk pattern in those two functions is the fix, and it MUST land before `-qwarp` is promoted or documented as reproducible.

### Mesh code (nii2mesh — unique to niimath)
- **meshify.c** — main mesh pipeline: smoothing → marching cubes → welding → degenerate removal → export. `mesh_report()` prints the `-v 1` quality line (components, Euler/genus, boundary edges, holes = boundary loops, non-manifold edges/vertices, self-intersecting triangles; coplanar overlap is deliberately NOT counted). Genus is `n/a` on a non-manifold mesh; self-intersections `n/a` when the scan cannot run (no memory, or a non-finite coordinate). `mesh_tri_tri` (Möller 1997) and `mesh_self_intersections` (uniform grid, ≤257³ cells, OpenMP over cells with atomic hit writes, order-independent) are the ONE copy used by both simplifiers' guards and by guarded smoothing. It runs after marching cubes, after `-s` smoothing and after simplification — MEASURED: HC smoothing at `-s 5` on MNI introduces 2 self-intersections on a clean mesh, so the smoothed line is not redundant.
- **MarchingCubes.c/.h** — newer implementation with ambiguity resolution
- **oldcubes.c/.h** — classic marching cubes (`USE_CLASSIC_CUBES`, `MC=0 make`); no longer the default

- **moco.c/.h** — **`-moco [-ref <n|image>] [-1Dfile <path.1D>] [-relative]` (sub-options in any order): rigid-body motion correction** of a 4D series onto volume 0 by default (`niimath bold -moco out`). Ordinary chain op, **DT32 only**, 4D with `nt > 1` only, guarded (deliberately NOT in `kHugeSafeOps`), ordinary FP. ON for every target including WASM.
  - **Clean-room, and the licence boundary is the point.** Implements Cox & Jesmanowicz 1999 (MRM 42:1014-1018). AFNI's `3dvolreg.c`, `mri_3dalign.c`, `thd_rot3d.c`, `thd_shear3d.c` are all **MCW** files and were used only as black-box oracles, never read — in contrast to `mri_genalign.c` (no MCW header, public domain), which is why `allineate.c` could be adapted. **The bar has since moved: MCW relicensed its 1994-2000 AFNI code from GPL-2 to CC BY 4.0 on 2026-05-12** (see the AFNI relicense entry below), so those four are no longer off-limits and the "do not open" rule is lifted. Nothing here needs to change: the clean-room implementation is not merely legal but attribution-free, which adapting CC BY code would not be.
  - **Every measured convention, and the experiment behind it, is in `moco_bench`'s `test/moco_reference_manifest.md`** — read it before changing any constant. The ones that silently corrupt results if lost: heptic 8-tap Lagrange default (no FFT anywhere); `-clipit` on by default, clipping each output sub-brick to its own INPUT range; angles compose as `Ry(yaw)·Rx(pitch)·Rz(roll)`; rotation about the grid centre `(n−1)/2` in mm; sform **obliquity ignored** (storage axes, nearest-axis snapping); the weight is a blurred base with a 5% `-edging` border and a 2.5%-of-max clip; the estimator linearizes about **IDENTITY** (warp the MOVING volume back, never the base forward); and it fits a **seventh parameter, an intensity scale** — without it a run whose volumes are dimmer than the base folds the brightness step into the motion.
  - **`NE` is probed ONCE PER BASE, inside `moco_base_setup()`, and the op fails CLOSED if it is singular (return code 3, mapped to an error by BOTH `nii_moco` and `nii_moco_relative`) — do not soften this to a warning.** The 6x6 normal matrix is built from the base geometry alone, so if it cannot be factored EVERY fit against that base fails on iteration 0. The probe lives in the shared setup precisely so that `-relative`, which rebuilds `NE` per pair, cannot lose it: the first `-ref`/`-relative` draft put it in `nii_moco` only, and `-relative` published an all-zero `.1D` at exit 0 on the singleton phantom. The reachable case is a singleton spatial dimension (`nz==1`, or `nx`/`ny`): `shift_row`'s +/-`MOCO_DELTA` warps land on mirror-image Lagrange taps with bit-identical weights, so that translation derivative is IDENTICALLY zero and the pivot is an exact zero. Before the guard this fell through to the per-frame "no step for N of N volumes" warning, which FAILS OPEN — measured on a 40x40x1x8 phantom with a known 1.47-voxel shift: output **bit-identical to the input**, `.1D` all zeros, **exit 0**, while the same phantom at `nz==2` recovered it. That is six silent zero regressors for any pipeline using the `.1D` as nuisance. The per-frame warning path is for per-frame data problems (non-finite voxel, empty frame) and must not be reused for geometric degeneracy.
  - **`-1Dfile` must end in `.1D`** (enforced at parse time, so a parameter file can never name a NIfTI output and be silently replaced by the image writer), and it is published BEFORE the image, so a later image-write failure leaves a valid `.1D` with no image. Do not restate this as unconditional fail-atomicity.
  - **`-relative` is a MEASUREMENT-ONLY mode** for QC: it fits every sub-brick onto its PREDECESSOR, writes those parameters, and writes **NO image** — no reference registration happens, so `-ref` and `-1Dfile` are rejected with it at parse time. It is a FLAG, not a path: the trailing positional that niimath would otherwise write the image to IS the parameter file, and is required to end in `.1D` so an image name there is refused rather than silently producing a `.1D` called `out.nii.gz`. Suppressing the write needed one new concept in the op loop — `no_image_out`, set by the op and checked at the single final `nifti_save` — because otherwise a measurement pass duplicates the whole 4D input to disk. `-gz`/`-odt` are inert in this mode, and `-relative` MUST be the last operation (rejected otherwise): a later `-save` would defeat the no-image contract, and any later op is wasted work. The sub-option loop stops at `argc`, so `nifti_moco_wrap` peeks `argv[argc]` and rejects `-relative`/`-ref`/`-1Dfile` sitting in the output-name slot — without that peek `niimath in -moco -relative` ran a FULL correction and wrote `-relative.nii.gz` at exit 0 (found by the reconciliation audit, pinned in `release_smoke.py`). The base of each pair is the **ORIGINAL** predecessor, never a corrected one: that keeps the pairs independent (parallel, thread-count invariant) and makes the numbers raw frame-to-frame motion rather than residual drift. Row 0 is all zeros. One file is published, through an exclusive temporary: the text `.1D` at `%12.8f` (same column order/convention as `-1Dfile`, more precision — the historical `%8.4f` layout is frozen for AFNI compatibility and is NOT changed). The PR also wrote a `<path>.bin` float64 companion; it was DELETED in the reconciliation audit as an unrequested binary sidecar duplicating the text (the smoke test now asserts it is NOT written). **Costs ~10× the ordinary mode per volume** — the weight, six derivative images and normal equations are rebuilt per pair because the base moves.
  - **The estimator is shared, not duplicated:** `moco_base_setup()` (weight + derivatives + normal equations for one base) and `moco_fit_one()` (the measured repeated-linearization loop) are called by BOTH modes, so they cannot drift apart. That extraction is behaviour-preserving — verified byte-identical at `-O0`; at `-O3` the repo-wide `-ffast-math` reassociates differently across the new call boundary, moving a handful of near-zero background voxels by ~1e-13 (parameters unchanged to 8 decimals). Do not re-inline it to chase byte-parity with pre-`-relative` builds.
  - **`-ref <n|image>` selects the base**, defaulting to volume 0. **The index-vs-filename test is `moco_volume_index()`: all-decimal-digits, never a filesystem probe** — so the meaning of `-moco -ref 7` cannot depend on whether a file called `7` exists on this machine (`./7` names the file). The same audit deleted the PR's `.1D.bin` companion and `moco_read_ref`'s header preflight (a third layer over `nii_reject_oversize_aux`, which the tree already says not to add per-op), and moved the `no_image_out` test above the `-odt` conversion so `-relative -odt char` cannot fail AFTER its `.1D` is published. `-relative` costs ~10x the ordinary mode per volume, which is the price of rebuilding the base every pair.

Brain extraction is deliberately NOT replaced: both pipelines call FSL `bet` and share its output, which is what makes every measured difference attributable to these two ops.
  - **The apply stage is 1D LINEAR along the unwarp axis, not a 3D pull** — an impulse displaced half a voxel returns as exactly two taps of 0.5, which no wider kernel can do. So `-fugue` does **not** reuse `medic_unwarp`'s `md_pull` (3D Lanczos-3, millimetre map, arbitrary world direction); sharing them would mean a mode flag switching kernel, dimensionality and units at once. The consequence is that `-fugue` runs **in place**, one line at a time through a thread-local line buffer, needing no second copy of the image, which is where both the speed and the halved memory come from. `md_pull` is Lanczos-**5**, not 3 — `medic.c`'s `MD_LANCZOS_R` and the `-unwarp` help line are the authority.
  - **A zero fieldmap means NO DATA, not zero shift.** The shift field is extrapolated along each line parallel to the unwarp axis before resampling: replicate the nearest supported value beyond the ends, 0 for a line with no supported voxel, support threshold 1e-6 rad/s. Omitting this is not an edge refinement — it changes about a third of the voxels and is the difference between agreeing with the reference and not. Note `fugue --saveshift` writes the **un**-extrapolated map and is NOT what the reference applies; a ramp input recovers the effective map exactly and is the probe to use.
  - **`fsl_prepare_fieldmap SIEMENS` applies NO regularisation** — no median filter, no despiking, no smoothing, no erosion (measured: a single-voxel spike passes through intact). The demedian takes the **UPPER** of the two central values (`sorted[n/2]`), not their average; on a mask that splits into two equal populations the averaging median is wrong by half the field's range, and `release_smoke.py` mutation-catches that off-by-one.
  - **The one post-processing step, 2π branch-outlier correction, lives in `fmap.c` and MUST stay out of `romeo.c`.** ROMEO leaves isolated voxels a full 2π out where PRELUDE does not (measured by distance from their own in-mask 6-neighbour median), and each becomes a large local shift error. `fm_debranch` re-projects them; every change is an integer multiple of 2π/ΔTE, so it cannot alter a genuine field value. It runs **after** `romeo_unwrap_frame()` returns — the correction is not applied inside `romeo.c`, so `-romeo` and `--medic` keep a faithful ROMEO, which MEDIC's traceability against a reference implementation depends on. `-no-debranch` recovers the raw field for parity work.
  - **`-no-debranch` is parsed with the `ac <= argc` peek**, not `ac < argc`: it is an optional TRAILING sub-option, so it can legally sit either before the output name or (by user error) in it, and stopping at `ac < argc` would write a file called `-no-debranch` at exit 0. Contrast `-skullstrip`'s legacy operands, which can only sit strictly before the output and correctly use `ac + 1 < argc`.
  - **gzip dominates a `.nii.gz` pipeline, not the arithmetic — so every timing claim must state the FILE FORMAT, the zlib linked and the thread count, or it is meaningless.** `make` links system `-lz` while CMake release builds link zlib-ng, and that alone is worth ~3x on a compressed write. With gzip removed from both sides (`FSLOUTPUTTYPE=NIFTI` / `-gz 0`) the op is several times faster than the reference even single-threaded and in half the memory, which is the honest comparison of the tools; the compressed-pipeline ratio is much smaller and is what a BIDS user experiences. Both live in the manifest; quote one, and say which.
  - **`fm_read_f32` is shared by both ops and takes its operation name and file role as arguments.** It used to route through a `FM_ERR` macro that hard-coded `"-fugue: "` and the noun `"fieldmap"`, so a `-fmapprep` user with a bad MAGNITUDE was told that `-fugue` could not read their `fieldmap` — an operation absent from their command line and the wrong file entirely. Do not reintroduce a shared helper that names one op.
  - **The resample's OpenMP region must not branch on a thread-local allocation result.** Both parallel regions allocate a per-thread buffer; the second one's `#pragma omp for` originally sat inside `if (!local_oom)`, so one thread failing its `malloc` while another succeeded put the team on DIFFERENT worksharing regions — undefined behaviour, in practice a hang at the implicit barrier, and it defeated the documented fail-closed contract. The fix is an `omp atomic write` to the SHARED flag, an `omp barrier`, then a team-wide test. Reachable only when the unwarp axis exceeds the 512-element stack buffer and memory is exhausted, so it had almost certainly never fired — but a hang is worse than an error.
  - **`-fugue` is all-or-nothing; `-fmapprep` is not.** The team-wide barrier makes the resample either fully run or not run at all, so `-fugue` leaves `nim` exactly as it arrived on every failure path. `-fmapprep` rescales the phase to radians IN PLACE before calling ROMEO, so a failure at or after the unwrap leaves `nim->data` overwritten — no output is written either way, which is safe under the op loop's free-without-saving contract, but a caller outside that loop must not reuse `nim`.
  - **`NaN != 0.0` is TRUE, and that was a fail-open.** `fm_debranch` decides whether to move a voxel with `if (k > 0.0 || k < 0.0)`, not `if (k != 0.0)`. With an absurdly small ΔTE the rad/s scaling overflows float32 to ±Inf, `Inf - Inf` makes `k` NaN, and the `!=` form took the move branch and wrote NaN over **every** masked voxel at **exit 0** — the one fail-open path in the file, in an op file whose stated rule is that a corrupted image is never written. A finiteness check on the scaled field now backs it up. Do not "simplify" either test.
  - **Byte-identical across thread counts, but NOT bit-identical across builds.** The interior-gap fill is FMA-contracted under the tree's `-ffast-math`, so a different compiler moves roughly 1 voxel in 2400 by ~1 ULP of the shift. Within one build it is byte-stable run to run and across `-p`.

The incident-face divisor now comes from the adjacency degree (`nbr_off`), which is equivalent on a closed mesh and cannot fail. **Keep the division:** it cannot change the direction but it does change the rounding — dropping it moved three of the five validation masks.

The only protection was a clamp nested inside `if (bvec.c000 > 0.0f)`, which a degenerate second-pass octant cliplevel skips entirely. ## Memory Management

- **Use plain `malloc`/`calloc`/`free` everywhere.** Do NOT reintroduce `_mm_malloc`/`_mm_free` or `arm_malloc.h` — the 64-byte alignment was never load-bearing (SSE-only 128-bit unaligned loads; malloc's 16-byte alignment already prevents cache-line splits; memory-bandwidth-bound).
- **`nim->data` ownership invariant:** any buffer assigned to `nim->data` MUST come from plain `malloc`/`calloc`, because `nifti_image_free()` and core.c's datatype conversion release it with plain `free()`. On MSVC `_mm_malloc` → `_aligned_malloc`, which `free()` cannot release — plain `free()` on it corrupts the heap (STATUS_HEAP_CORRUPTION 0xC0000374 at teardown). Use **`nii_calloc(count, size)`** (core.c/core.h) for `nim->data`: a fail-closed allocator running `count`×`size` through checked-multiply `nii_mul_size()` and `exit(EXIT_FAILURE)` on overflow/NULL. **`nii_malloc(count, size)`** is the UN-zeroed sibling (same check + exit, plain `malloc`) for a `nim->data` buffer the caller FULLY overwrites before any read (datatype-conversion output loops); use `nii_calloc` if any voxel could be left unwritten (RGB/complex convert buffers stay `calloc`). Callers still pre-compute overflow-prone products with `nii_mul_size()`.
- Kernel arrays: 4-int-per-voxel layout (offset, x, y, weight); plain `malloc`.
- NIfTI images: managed by `nifti_image_free()`.
- MarchingCubes.c: constructor/destructor (`MarchingCubes()`/`FreeMarchingCubes()`) with `clean_all()`.

## Huge image support (> INT_MAX voxels, issue #67)

The core calculator processes images whose 3D `nx·ny·nz` or total 4D `nvox` exceeds `INT_MAX` (≈2.15 G voxels ≈8.6 GB float32) instead of rejecting them.

- **`nvox_t` (core.h)** is the voxel count/index type: **signed** `int64_t` by default (neighborhood/kernel/reverse loops need negative intermediates that unsigned `size_t` would wrap), or `int32_t` under `-DFORCE_INT32_MAX`. `size_t` stays for byte-size allocation only.
- **Scope.** Converted (nvox_t/`size_t`-safe): scalar & image binary ops, per-voxel unary math, temporal reductions (`nifti_dim_reduce`), robust-range percentile, Gaussian smoothing. Everything else — kernel morphology `-fmean`/`-ero`/`-dilF`, `-edge`/`-index`/`-rank`/`-pval`, EDT/tfce/resize/subsamp, allineate/deface/mesh/dtifit/qc/bwlabel/bmp/fdr — keeps int indexing and is **guarded** (rejected on huge input).
- **Fail-closed admission.** A huge image runs only if its op is an exact `strcmp` member of `kHugeSafeOps[]`. `nii_admit_file_before_load()` gates before the payload read (resolving the real first op past output/`-odt`, the RGB ×3/×4 effective count, pass-through/conversion-only); `nii_admit_current_op()` re-checks at the top of every op-loop iteration against the CURRENT image (catches `-restart`, a binary op adopting a huge operand, RGB expansion). stdin/`.nii.zst` skip the pre-read gate and are caught post-load. `nii_reject_oversize_aux()` header-rejects an oversized auxiliary (reslice mask/base, deface template/mask, `-allineate -weight`, bitmap) before its load — EXCEPT a `.nii.zst` auxiliary (no bounded header-only path; caught post-load — accepted limitation). Robust-range/Otsu reject an intensity span their histogram cannot represent (avoids undefined `(int)NaN`). **To promote a guarded op: make its kernel `nvox_t`-clean AND add a `test/huge_smoke.py` case.**
- **`nii_nvox_classify()` (core.c)** is the single geometry validator → {invalid, INT-safe, huge}; `nii_nvox3d_int`/`nii_nvox3d` are its narrow/wide adapters.
- **`-DFORCE_INT32_MAX` on every 32-bit/wasm build (MUST).** wasm32 has a 4 GB ceiling; the `tiny`/`wasm`/`wasm-wasi`/`wasm-emcc-core` Makefile targets and CMake `tiny`/32-bit set it; every huge image is rejected there. Core ops are byte-identical to the pre-#67 build at ≤INT_MAX sizes.
- **Testing.** `test/huge_smoke.py <binary>` — opt-in/manual (~9 GB RAM; not in CI): sparse >INT_MAX NIfTIs. Allocation-free reject cases run in `make test` via `release_smoke.py`.
- **Reach goals (deferred).** Re-add `-Tstd/-Tmedian/-Tperc/-Tar1` to `kHugeSafeOps` (only a huge_smoke oracle missing); convert the neighborhood/morphology kernels. Non-goals: registration/mesh/tfce/resize; streaming `.nii.zst` + >2 GB Win64 offsets.

## Known Remaining Issues

1. **NULL checks / fail-closed allocation.** `coreFLT.c`'s OpenMP worker scratch is DONE for `nifti_tfce`, `nifti_tfceS`, `nifti_detrend_linear`, `nifti_bptf`, `nifti_sobel`, plus `make_kernel_gauss`, `nifti_unsharp` and the `-rank`/`-ranknorm` branches of `nifti_unary` — all fail closed via `int oom` + `reduction(| : oom)` + check-and-`continue`, matching the six siblings that already did (`:552` EDT, `:2546` dim-reduce, `:4468` resize, `:4940`/`:4969` edge1, `nifti_fillh`). `-detrend` and `-bptf` were allocating once per VOXEL and are now per-thread (measurably FASTER); `nifti_sobel`'s `imgdir` was allocated unconditionally but read only under `if (isBinary)`. **The caller contract is what makes this simple:** the op loop's `goto fail` frees `nim` WITHOUT calling `nifti_save`, so returning non-zero is sufficient — never add snapshot/restore.
   **THE TRAP THAT COST A ROUND, and it is invisible in source review: never declare a variable BELOW a `goto` that targets your cleanup label.** `nifti_bptf`'s low-pass pointers were declared after the high-pass block's `goto bptf_done`, so those jumps skipped their initialisers. That is legal C but leaves them INDETERMINATE, `bptf_done` then `free()`s them, and **clang treats the path as UB-unreachable and DELETES the guards you just added**. Verified by disassembly (no compare, no NULL test emitted for the high-pass group while the structurally identical low-pass group WAS emitted) and at runtime: `-bptf 400000000 -1` allocated **17.9 GB and exited 0** instead of being rejected. After hoisting the declarations above every goto: 0 GB, exit 1, correct message, and 36/36 byte-identical on valid input. Source review passed this twice; only codegen inspection caught it.
   **Two more classes were swept at the same time.** Double→int conversions must be guarded on the DOUBLE, before the cast — `(int)(hp_sigma * 3)` ran before its own range test, the same `(int)NaN` hazard as the tfce pair. And **twelve multi-argument ops had no `argc` guard**, so a truncated command line walked off the end of `argv`: `niimath in.nii -tfce 2 out` SIGSEGV'd in `strtod` (verified, signal 11), as did `-tfceS`, `-resize` and `-close`. `-roi` alone had the check. `NII_NEED_ARGS(n)` now guards all thirteen; keep it on any new multi-argument op.
   Verified across all of it: 36/36 byte-identical outputs (9 op variants x float32/float64 x `-p 1`/`-p 8`), serial-UBSan clean including full `release_smoke`, malloc diagnostics clean, 0 leaked bytes, and `exercise_openmp_scratch_ops` now covers these ops — they had NO in-repo coverage before, which is how eight unchecked allocations survived the sweep that fixed their siblings. That test is mutation-checked.
   **STILL OPEN:** `nifti_tfce` (`coreFLT.c:1913`) computes `nvol = nim->nvox / nvox3D` with no `nvox3D != 0` guard; `nifti_sobel` and `kernel3D_dilall` have the same missing divisor/`void`-helper shapes; `make_kernel_gauss`'s double-to-`int` conversions (`coreFLT.c:2842-2844`) are unguarded. Line numbers drift — grep the identifier, not the line.

3. **Whole-program `-ffast-math` (all build systems).** Make, CMake (non-MSVC `CMAKE_C_FLAGS`), notarize.sh, and wasm compile the entire program `-ffast-math -fno-finite-math-only`; MSVC stays strict. **One standing exception:** `romeo.c` is compiled strict-FP (`-fno-fast-math -ffp-contract=off`; MSVC `/fp:precise`) in every build system and linked as a separate object (see the romeo.c entry). Registration must round like the standalone/fslmaths goldens (shared `nifti_io` mat44 helpers run during the fit); scoping it to registration TUs made CMake/notarize/wasm diverge. Also covers core ops, GPL `-spm_coreg`, dtifit/tensor — re-validate the SPM golden and dtifit/tensor if you touch those. `-fno-finite-math-only` preserves NaN/Inf detection; fast-math-sensitive finiteness checks use magnitude guards (e.g. `v >= -DBL_MAX && v <= DBL_MAX`).
4. **Prebuilt-object flag stamp.** `allineate.o`/`powell_newuoa.o`/`coreg_fast.o` depend on a flag-signature stamp (`.al_obj_flags` = `CNAME|CFLAGS|AFLAGS`) so `make` → `make OMP=0 all` relinks cleanly with no `make -B` — else a stale object fails to link on `__kmpc_*`/`omp_*`. Extend `AL_OBJ_SIG` for a new object-affecting flag outside `CFLAGS`. `romeo.o` has its OWN independent stamp (`.romeo_obj_flags` = `CNAME|CFLAGS|ROMEOFLAGS|ROMEO_STRICT_FP`, Makefile `ROMEO_OBJ_SIG`) because it must rebuild on a flag change even in an `AL=0` build where `.al_obj_flags` is unused; and the non-default targets MUST write `romeo_<target>.o`, never `romeo.o`, or `make all` finds an instrumented object newer than the source with an unchanged stamp and fails to link.
5. **Output-write failures propagate.** `nifti_image_write_status` returns 0/1 (open, short header/data write, compressor/close/pclose errors incl. disk-full at close); `void nifti_image_write` remains a compatibility wrapper. `nifti_save` uses the status API; main dispatch, pass-through, and intermediate `-save` sites propagate it; multi-output `--dtifit`/`-tensor_decomp` OR every status. Preserve — a failed/partial write must report failure, not exit 0.
6. **`nifti_io.c` upstream debt** — LLP64 builds still use `long` in the internal seek wrapper, limiting >2 GiB Windows offsets; a future upstream sync should move that to the platform's 64-bit seek API. Crafted payload-size multiplication, NIfTI-2 header probing, stdin polling, and piped-input cleanup are already hardened locally; preserve those on upgrade.
7. **Registration mislabels metre/micron coordinates as mm.** `al_image_xform`/`al_image_xform_or_pixdim` (allineate.c) return raw NIfTI sform/qform/pixdim coordinates in the header's `xyz_units`, but the registration schedules (translation guards, blur mm), the fast engine bounds, and `-savemat` (`"units":"mm"`) all treat them as world-mm. A legal metre (or micron) image thus gets a 1000× (or 0.001×) physical schedule and a false-unit saved matrix; deferred only because practical exposure is ~nil (neuroimaging NIfTIs are mm). **The fix is a COORDINATED change, not a one-line seam scale:** reface already normalizes independently via `reface_voxvol_mm3(…, xyz_units)`, so scaling the transform at the seam would DOUBLE-normalize the privacy-critical reface coverage gate — the seam normalization and the reface `reface_voxvol_mm3` de-normalization must land together, be mirrored to `codex/allineate` (both the shared seam and the standalone's own `do_reface`), and ship with a mm/metre/micron equivalence test (the `release_smoke.py` `nifti_header(scale=, xyz_units=)` helper already supports it). mm images must stay byte-identical (factor 1.0).

8. **A featureless base fabricates motion at exit 0 (`-moco`, pre-existing; `-ref <image>` widens the exposure).** The `chol6` probe in `moco_base_setup` rejects only an EXACT zero pivot. A constant reference on the input grid (all 7.0, 24x24x20x3 fixture) passes it — the derivative images are non-zero only at the FOV edge, so `NE` is tiny but not singular — and the fit then chases the boundary: measured 51 deg of fabricated yaw, max |out−in| 55 on a 0..100 range, plausible-looking `.1D`, no warning, exit 0. `gfac` stays inside (0.125, 8) and the cost never rises past `MOCO_COST_RISE` because the cost surface is flat. A constant VOLUME 0 does the same on master, so this is not a regression, but `-ref <image>` makes an arbitrary user file the base (a mask or a wrong-grid-mate mean image is a realistic mistake), whereas an all-zero or all-NaN reference IS caught. The fix is a conditioning gate on `NE` (min/max Cholesky pivot ratio) or a "final cost not materially below identity cost → `fitted = 0`" test; the threshold must be measured against `moco_bench` before it ships, which is why the audit recorded it rather than guessing. Related nit: published `.1D` files inherit mode 0600 from the `O_EXCL` temporary rather than the umask default; pre-existing, a nuisance in group-shared directories.

9. **The same-grid predicate exists four times, in four spellings, and only three of them are NaN-safe — factor into `core.c` as `nii_same_grid()`.** The "do these two images share a voxel grid?" test lives in `md_same_grid` (medic.c, 4 call sites), open-coded twice in `fmap.c`, once in `qc.c`, and once more in `moco.c` (`-moco -ref <image>`, `moco.c:634`, written in the fail-closed `!(disp <= 0.001f)` form). Under whole-program `-ffast-math` the spelling decides the failure mode, and `max_displacement_mm` returns NaN for a malformed transform:
   * `qc.c` — `!(d >= 0.0f && d <= 0.001f)` → NaN **rejects**. Fail-closed.
   * `medic.c` — `return dims_equal && d <= 0.001f;` → NaN makes it 0, "not same grid" → **rejects**. Fail-closed, by luck of phrasing rather than by design.
   * `fmap.c` — was `if (dims_differ || d > 0.001f) reject;` → `NaN > 0.001f` is **FALSE**, so it **ACCEPTED** a pair whose geometry could not be measured. **Proven, not theorised:** a fieldmap byte-patched to an all-NaN sform was accepted and 768 KB of output written at **exit 0**. Fixed to `!(d <= 0.001f)` and covered in `release_smoke.py`.
   * `moco.c` — `!(disp <= 0.001f)` → NaN **rejects**. Fail-closed, and written that way deliberately after the `fmap.c` incident.
   The divergence existed only because the predicate was copied, and the copy that got it wrong was the newest at the time. That is the argument for factoring: move `qc.c`'s explicit magnitude-guard form to `core.c` as `nii_same_grid(a, b)` and update all eight call sites, so the next copy cannot pick a different spelling. `medic.c`, `qc.c` and `moco.c` are NOT shared with the standalone allineate project (see the Shared-code invariant), so unlike `allineate.c` they can be edited freely.
   **What NOT to fold in at the same time:** `fm_read_f32` (fmap.c) and `md_read_f32` (medic.c) are near-identical float32 readers, but unifying them needs three pure-policy parameters (file-role noun, op name for messages, 3D-only vs 4D-allowed) to serve only two callers, and would put the function in `core.c`, which links into `tiny`/`wasi`/`nano` builds where neither feature exists. Leave duplicated until a third caller appears; the value there is the INVARIANTS (the post-load re-check, the `scl_slope != 1.0` trap), not the lines. Likewise do NOT dedupe `fm_select_kth` against `romeo.c`'s identical `rm_select_kth_f`: removing `static` from a function inside the tree's one strict-FP object changes clang's inlining, and AGENTS.md already records that exact hazard costing every `-skullstrip` mask (`ss_deform_range_faithful`, Dice 0.982-0.992). Six quickselects already coexist here; a local copy per module is the house pattern.

## Optimization Constraints

- Voxel ops are lean, SIMD-optimized, mostly memory-bandwidth limited. OpenMP is **not the primary optimization target** for core ops (typical usage runs one subject per thread across many subjects). zlib-ng (CMake release baseline, `ZLIB_IMPLEMENTATION=zlib-ng`, ZLIB_COMPAT) gives ~2× `.nii.gz` I/O over stock zlib (correct on MSVC where Cloudflare is not). The Emscripten `wasm` target links it via `WASM_ZLIB`.
- **Allineate reproducibility:** `-allineate` is byte-reproducible **across thread counts** (nt=1/2/4/8) — preserved by the `mfac` thread-local re-apply rule. It is **NOT bit-reproducible across builds**: NEWUOA + `-ffast-math` means a codegen change can flip the optimizer to a neighboring equally-valid optimum (sub-voxel parameter shift, ~1% in a few edge voxels). Quality unchanged (cost and base-correlation match to 4+ digits) — do NOT treat `-allineate` output as a byte-stable golden across versions. `gpl-build.yml` gates registration by QUALITY (correlation floor + improvement-over-baseline via `reg_quality.py`, fails closed on empty/constant/non-finite), not a byte diff. `-deface`/`-spm_deface` reslice via `nii_reslice_affine` (not the fused path) and stay byte-stable.

### WASM performance pitfalls (two hard-won rules)
1. **No `qsort`+comparator on large or per-voxel arrays in WASM-targeted code.** emscripten/musl `qsort` calls the comparator via `call_indirect` per comparison (~100× slower than native — can make the WASM build appear to hang). Use comparator-free: **quickselect** for a single value (`al_select_rank`, `select_kth_flt`, `uf_select`), **insertion sort** for genuinely small fixed N only (NOT a per-voxel neighborhood — O(n²) per voxel), or **heapsort** for a full order on large arrays (`heapsort_sortIdx`). The only remaining `qsort` is `qsort_floatint` on ~46-element lists.
2. **WASM allineate MUST be compiled `-ffast-math` (matching native)**, or the cost-function reduction rounds differently and NEWUOA/Powell converges to a worse optimum (`-deface` masked 37% vs 60% native). The `wasm:` target and its prebuilt `al_wasm.o`/`pn_wasm.o`/`cf_wasm.o` use whole-program `-ffast-math -fno-finite-math-only`. (`-msimd128` adds only ~3% — not worth the golden-match risk.)

## Code Conventions
- C99 with extensive `#ifdef` for conditional compilation.
- Template pattern: coreFLT.c compiled as both float32 and float64 via macro inclusion.
- Naming: `nifti_*` for NIfTI operations, `nii_*` for internal helpers.
- Explicit SIMD (Intel intrinsics via `immintrin.h`) only on `__x86_64__`; ARM/WASM use scalar fallbacks (clang `-O3` auto-vectorizes to NEON just as fast; memory-bandwidth bound). No `sse2neon.h` shim.
- Error returns: `EXIT_SUCCESS`/`EXIT_FAILURE`.

## Documentation style

Applies to every README and any future `docs/` page. Structure comes from the Diataxis framework (the `diataxis-docs` skill, if installed): explanation, how-to, reference and tutorial sections are kept separate and typed. `AGENTS.md`, `CLAUDE.md` and `noncompliant.md` are agent-facing and exempt from the prose rules below, but not from the line-wrapping rules.

- Short sentences, 20 words or fewer. Active voice, present tense.
- Plain words: use, start, help, before.
- One paragraph per line. No hard wrapping, no em dashes. Use newlines only for genuine structure: between paragraphs, headings, list items, table rows and code-fence boundaries, and for new lines of code inside fences.
- Cut "simply", "just", "note that", "it is important to".
- When editing an existing `.md` file with hard-wrapped paragraphs, unwrap them to one line per paragraph.
- Before delivering, list any sentence you left over 25 words.
- CLI strings inside code spans keep their original spelling; American spelling in prose.
