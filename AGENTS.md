This file provides guidance for AI agents when working with code in this repository.

## Project Overview

niimath is an open-source clone of FSL's `fslmaths` — a general-purpose NIfTI image calculator for neuroimaging. It extends fslmaths with mesh generation (nii2mesh), extra filters, defacing (`-deface`), affine registration (`-allineate`), anatomical QC (`--qc`), zstd compression (.nii.zst), and cross-platform support (Linux, macOS, Windows, WebAssembly).

**Repository:** `rordenlab/niimath` (BSD-2-Clause license)

## Building

### Quick build (Makefile, recommended for development)
```bash
cd src && make          # Standard optimized build (OpenMP enabled by default)
make debug              # Debug build (-g, no optimization)
make ubsan              # UndefinedBehaviorSanitizer (lightweight; retains OpenMP)
make sanitize           # AddressSanitizer (serial on Apple Clang; no leak detection on macOS)
make verbose            # All warnings
make static             # Static binary
```

### Prerequisites
- **macOS**: `brew install libomp zstd`
- **Linux**: `apt install libzstd-dev` (OpenMP built-in with gcc)

### Build variants
```bash
make tiny               # Minimal terminal build (emulates WASM constraints)
make nano               # Without mesh (nii2mesh)
MESH=0 make             # Disable mesh support
AL=0 make               # Disable allineate registration
DTIFIT=0 make           # Disable dtifit
QC=0 make               # Disable anatomical QC (--qc)
GPL=1 make              # Enable optional GPL -spm_coreg (needs git submodule update --init src/GPL)
QWARP=1 make            # Enable -qwarp nonlinear registration; OFF by default; needs allineate (not with AL=0)
ZSTD=0 make             # Disable zstd (.nii.zst)
OMP=0 make              # Single-threaded build
MC=1 make               # New MarchingCubes algorithm (handles ambiguities)
STB=1 make              # STB image library instead of libspng for bitmaps
make wasm               # Emscripten/WebAssembly
make wasm-wasi          # Experimental zlib-free WASI compute backend (needs Zig)
make wasm-emcc-core     # Feature-matched zlib-free Emscripten build (WASI benchmark baseline)
```
zlib: CMake release builds default to zlib-ng (`ZLIB_IMPLEMENTATION=zlib-ng`); plain make uses system `-lz` (`ZLIBNG_ROOT=<path>` links compat zlib-ng without CMake; wasm uses `WASM_ZLIB`).

### CMake build
```bash
mkdir build && cd build && cmake .. && make     # top-level SuperBuild
cmake -DUSE_OPENMP=OFF -DENABLE_QC=OFF ..        # toggles (forwarded by SuperBuild)
```

### Key compile-time flags
- `NII2MESH` / `DNII2MESH` — mesh conversion
- `USE_CLASSIC_CUBES` — oldcubes.h (classic) vs MarchingCubes.h
- `HAVE_FORMATS` — GIfTI, OBJ, VTK, STL mesh output
- `HAVE_BMP` — bitmap/PNG creation
- `HAVE_BUTTERWORTH` — bandpass temporal filtering
- `HAVE_TENSOR` — tensor decomposition
- `HAVE_DTIFIT` — linear diffusion tensor fit (`--dtifit`); needs `HAVE_TENSOR`
- `HAVE_QC` — anatomical QC (`--qc`); no tensor/mesh deps
- `HAVE_CONFORM` — image conforming to standard space
- `HAVE_ALLINEATE` — affine registration + defacing (allineate.c + powell_newuoa.c + coreg_fast.c + reface.c); release builds use whole-program `-ffast-math` + OpenMP. `reface.c` always compiled in an allineate build (no separate flag).
- `HAVE_QWARP` — `-qwarp` nonlinear registration (qwarp.c, attributed AFNI 3dQwarp port); OFF by default; `QWARP=1 make`; requires allineate/NEWUOA (not with `AL=0`).
- `HAVE_GPL` — optional GPL `-spm_coreg`/`-spm_deface`; OFF by default so builds stay BSD-2. `-spm_coreg` is canonical (`-spmcoreg` a silent alias). Sources in `niimath_gpl` submodule (`src/GPL`); `GPL=1 make` / `cmake -DENABLE_GPL=ON` / `GPL=1 make wasm` (needs `git submodule update --init src/GPL`). A `GPL=1` binary is a GPL-2 combined work (version string ends ` GPL` vs ` BSD`).
- `AL_LPC_MICHO` — adds lpc+ZZ/lpa+ZZ combined cost variant (default: pure lpc/lpa)
- `HAVE_ZSTD` — .nii.zst support (auto-detected; `FSLOUTPUTTYPE=NIFTI_ZST` to write)
- `FSLSTYLE` — FSL-compatible behavior mode

## Source Architecture

### Core computational pipeline
- **niimath.c** — CLI entry point; dispatches to `main32()`/`main64()` by `-dt`. `--dtifit`/`--qc` are self-contained subcommands dispatched before the op loop. Huge-image (>INT_MAX voxel) gate (issue #67): `main32`/`main64` admit a huge working image only for whitelisted ops (fail-closed) — see **Huge image support**.
- **coreFLT.c** (6k lines) — main computational engine, compiled twice via template pattern:
  - **core32.c** — `#define DT32` + include → float32 (SSE 4-wide on x86_64; scalar ARM/WASM)
  - **core64.c** — include without DT32 → float64 (SSE 2-wide on x86_64; scalar ARM/WASM)
  - **Filter kernels.** Gaussian smoothing (`smooth_gauss_blur1d`, used by `-s`/`-dog`/unsharp/registration) uses `blur_row`: a contiguous full-symmetric kernel (`kc[i]`, not `k[abs(i)]`), lane-parallel so clang auto-vectorizes (NEON; SIMD128 in `-msimd128` wasm). `-fmean`/`-fmeanu`, `-dilF`/`-eroF`, binary `-ero` recover kernel extents once, keep checked scalar gathers on borders, evaluate eight adjacent interior outputs per tap for contiguous SIMD loads. O(k³) with independent per-output state, preserving each op's local NaN/±Inf behavior. A separable box-filter experiment was removed (shared running sums / monotonic deques changed those semantics; archived in `noncompliant.md`) — do NOT restore without explicit non-finite conformance tests.
  - **`-dilate <thr> <dx>`** (distance-based grow, `nifti_dilate`, distinct from kernel `-dilF`): binarizes at `thr`, grows the mask by `dx` mm — voxels within `dx` of the surface set to at least `thr` via `fmax(iso, imgIn[i])` (matching `-close`'s fill, so a grown voxel survives a re-threshold at `iso`; `fmax(1.0,..)` is wrong for `iso>1`), beyond-`dx` voxels unchanged (grow-only).
- **core.c** — shared utilities: datatype conversion, kernel creation, Otsu thresholding, resampling filters, NIfTI I/O helpers. **`max_displacement_mm()` gotcha:** returns max corner displacement between two images' world transforms; gates the `-add`/binary-op and `--compare` orientation warnings (0.5 mm) and the `--qc` grid check (0.001 mm). It measures true 3D Euclidean distance AND normalises each transform to mm via `xyz_units` (`xyz_units_to_mm`) so metre/micron headers compare correctly; touch only with that unit scaling in mind.
- **unifize.c** — bias field correction (`-unifize`; adapted from AFNI 3dUnifize, public domain).
- **allineate.c** (~3.9k lines) — affine registration, defacing, skull-stripping. **Shared byte-identically with the standalone allineate project — canonical source; sync any change both ways** (see Shared-code invariant). Cost via `-cost` (Hellinger default, lpc/lpa/ls; `-DAL_LPC_MICHO` adds lpc+ZZ/lpa+ZZ); DOF via `-warp`; interpolation via `-interp`/`-final`. Twopass coarse-to-fine with a full-resolution AFNI-faithful random-startup coarse search and OpenMP-parallel candidate refinement using thread-local histogram/warp/workspace buffers (adapted from AFNI 3dAllineate, public domain) — this thread-local-cost-eval pattern is the template for any spm_coreg OpenMP work. `al_register()` is shared by `nii_allineate()`/`nii_deface()`; `nii_reslice_affine` + `nii_apply_deface_mask` are factored out and reused by `nii_deface` and GPL `-spm_coreg`/`-spm_deface` (interpolation lives once in BSD).
  - **`-deface` is the single mask-based removal command** — the supplied mask, not the command, determines what is removed (brain mask skull-strips, face mask defaces). Defaults to the fast engine (`-cost fast`, like `-allineate`); `-cost hel`/`lpc`/`lpa`/`ls` selects the ordinary AFNI-style engine; `-warp`/`-interp`/`-source_automask`/`-dark_automask` force the ordinary engine (rejected with an explicit `-cost fast`). Fast-deface removed-region Dice vs `-cost hel` ≈ 0.985–0.999 at ~15× speed — broad agreement, NOT byte-stable across builds.
  - **Registration direction (MUST):** register the SUBJECT onto the TEMPLATE (`al_register(input, tmpl)` ordinary; `coreg_fast_estimate(input, tmpl)` fast — base=template, the well-posed direction), then INVERT to pull the template-space mask onto the subject grid: ordinary via `GA_setup_affine`→`nifti_mat44_inverse`→`nii_reslice_affine`; fast passes `nifti_mat44_inverse(res.fixed_to_moving)` to `nii_apply_affine(mask, input, …)`. Registering a brain-only template ONTO a full-head subject (base=subject) converges to a mislocated transform and masks the wrong region — do NOT do it.
  - **`nii_deface` rejects 4D input** (`al_dims_ok`): the face mask covers one volume, so 4D would leave faces in volumes 2..N (privacy failure). **`-allineate`, by contrast, auto-crops a genuine 4D moving image to volume 0** (== `-crop 0 1`, with a warning) in `nifti_allineate_wrap` (after the `-applymat` early-return, so applymat still rejects 4D); a >4D vector/tensor moving image is rejected.
  - **`-fill auto|zero|nan`** (`-allineate` output reslice only, gated at parse time by `AL_CAP_FILL`; **rejected for `-deface`**, whose fill stays the image minimum for mask safety): `auto` (default) zero-fills unless the source's darkest finite voxel is <0 (CT/HU air ≈ -1000), then fills with that minimum so out-of-FOV reads as air not soft tissue (positive-only MRI output stays byte-identical to historical); `zero` always 0; `nan` NaN. Resolved by shared `al_resolve_fillv()` / `al_image_fillv()` (unscaled float32 scanned in place; scaled/non-float32 takes a converting `nii_to_float` copy so AUTO sees negative HU in raw int16 CT), both magnitude-guarded (TU is `-ffast-math`). Fused-warp path (`nii_allineate`/`al_scalar_warpone`) writes 0 then `al_fill_fused_oob()` rewrites only out-of-FOV voxels via the kernel's exact FOV predicate (no-op when fillv==0); `nii_apply_affine` paths (fast, `-master`, `-applymat`) pass the resolved fill directly. Options in `al_opts` (`allineate.h`).
- **coreg_fast.c/.h** — fast affine coreg engine (`-cost fast`/`fastx` → adaptive HEL/CR default; `-cost fasthel` → Hellinger/MI; `-cost fastcr` → correlation-ratio). Clean-room, NOT AFNI/GPL. **Shared with the standalone allineate project** (sync both ways). `coreg_fast_estimate()` does not mutate inputs — returns a world-mm FIXED→MOVING `mat44`; caller applies once. Cost reductions use fixed `CF_CR_NCHUNK=64` disjoint chunks in fixed order → deterministic per team size.
  - **Build gotcha:** coreFLT.c references `coreg_fast_estimate` unconditionally under `HAVE_ALLINEATE`, so every allineate-enabled build MUST link it (native `coreg_fast.o`, wasm `cf_wasm.o`, CMake `ADDITIONAL_SRCS`, notarize `AL_SRCS`). Blurs its pyramid via exported `nifti_smooth_gauss_f32`/`_f64`; multi-volume smoothing passes per-volume dims — **do NOT introduce shared `nx`/`ny`/`nz` here (4D OpenMP race).**
  - **Partial-FOV cost:** HEL/CR form statistics from the image INTERSECTION — out-of-FOV moving samples are excluded (`if(!ok) continue`), NOT filled with `m_bg` (else a partial-coverage moving image distorts toward scale/shear). A floor (`nin < 0.10*ns || nin < 16 → CF_PENALTY`) rejects degenerate tiny overlap; exclusion is inside each fixed chunk so determinism holds; LS keeps the `m_bg` fill.
  - **Initialization:** default/`-cmass` scores the supplied affine and exact-COM starts once at 8 mm, maximizing `(1-cost)×covered_fixed_foreground`, then runs only the winning descent; `-com` forces a recentered header, `-nocmass` forces the supplied affine. Translation guard ±128 mm.
  - **Contract:** fixed 12-DOF schedule; fail-closed rejects `-warp`/`-interp`/`-source_automask`/`-dark_automask`/`-zoom`. The `-com`/`-sym`/`-symd`/`-symb` header seeds ARE honored (dispatch applies them to the moving header before the branch, so `-cost fast -sym` is accepted). `-cost` last-one-wins; both-form-codes-zero input uses the shared pixdim-centered fallback.
  - **Reslice fill safety:** cubic reslicing clamps only in-FOV voxels (`nii_reslice_affine` inline; `al_scalar_warpone` via `al_clip_fused_cubic_infov`) so a positive-only source's out-of-FOV fill stays 0 — clamping it up to source min is a defacing mask-safety hazard.
  - **`-weight <img>` (AFNI-style graded base-space weight, BOTH engines):** optional base(fixed)-space region image (`coreg_fast_opts.weight`; ordinary `al_opts.weight` filename; parsed through shared `al_parse_subopts` under `AL_CAP_WEIGHT` — so `-allineate`/`-reface` accept it, `-deface` rejects it at parse time) whose dims AND world frame must match the base. Normalized to `[0,1]` (÷ max), GRADED per base voxel (weight 0 excluded, near 1 dominates); it is NOT a hard/exclusion mask. **Ordinary engine** (`al_load_user_weight`/`al_scalar_setup`): user weight REPLACES the manufactured autoweight and stays GRADED for EVERY cost including box-mode histogram costs — we never binarize a user `-weight` (only the manufactured autoweight is boxed). **Fast engine:** normalizes over the WHOLE fixed grid, applies the weight ONLY at the finest (2 mm, `lv==2`) level — 8 mm rigid capture, 4 mm global-scale bracket, and seed selection stay UNWEIGHTED/whole-head so a brain-concentrated weight cannot hijack global-scale SELECTION (else a scalp-shrink basin). HEL/CR scale-invariant so max-normalization makes the fit invariant to global weight scaling; **rejected with LS.** **Keep the out-of-ROI head attenuated (nonzero), not zeroed** — masking the cost to the ROI alone leaves global isotropic scale underdetermined (ill-conditioned scalp-shrink collapse). Negatives/NaN/+Inf clamp to 0 at full resolution before the blur; fast engine rejects a weight with no positive support over the fixed foreground (`wmax==0`); weight is sampled by fixed VOXEL INDEX (never resampled) so the 8-corner frame check uses a TIGHT header-rounding tolerance (~1/20 voxel), rejecting even a sub-half-voxel origin shift.
  - **niimath `-allineate` dispatch (`nifti_allineate_wrap`):** `-weight` honored by BOTH engines (ordinary loads via `al_load_user_weight`, fast into `cfo.weight`); preflighted for oversize (both), rejected for stdin (`-`) and with `-applymat`. `-reface` honors it too. When `-weight` is given and the DEFAULT fast engine fails, it DOES fall back to the ordinary Hellinger engine and the fallback HONORS the weight; an explicit `-cost fast`/`fastcr` never falls back. Provenance recorded in `-savemat` JSON (`"weight"` key, omitted when unweighted); unweighted leaves every fast cost ×1.0 → bit-identical to before.
- **Fast-engine multi-start / NMS invariants.** `cf_make_samples()` clears previous arrays/counts/accumulator before rebuilding; any degeneracy or partial-alloc failure leaves an empty consistent state, aborts every remaining strategy, skips winner polish, leaves `*result` unchanged (prevents a later hard-zero strategy combining stale `ns` with partial arrays). Standalone C-API harness fault-injects the 2nd allocation on sample-build call 4. Exploratory angular NMS repeatedly picks the global lowest cost (enumeration order breaks ties) and accepts only candidates ≥20° from every retained basin; non-positive/non-finite separation fails closed. Keep the bounded comparator-free scan for WASM.
- **powell_newuoa.c** (~2.8k lines) — Powell NEWUOA derivative-free optimizer (f2c translation). **Shared with the standalone allineate project.** Thread-safe statics use `AL_THREAD_LOCAL` (`al_thread_local.h`); `powell_newuoa_free_threadlocal()` releases the per-thread `pn_w`, called from `al_register` teardown.
  - **KEY gotcha — `mfac`/`afac` (NEWUOA sampling factors, `powell_set_mfac`) are thread-local**, so a main-thread `powell_set_mfac()` does NOT configure OpenMP workers. Every parallel `powell_newuoa()` loop MUST capture factors via `powell_get_mfac()` before the region, re-apply `powell_set_mfac()` inside the body, and restore the worker's prior factors afterward — else workers use stale `npt`, results become thread-count-dependent, or caller config leaks into persistent workers.
  - Direct-call `ndim` and sampling factors checked with `size_t` before NEWUOA's quadratic f2c workspace expressions; oversized shape returns `-8` before allocation/callback. **Fail-closed OOM:** `pn_w` alloc failure returns `-7` (never calls `newuoa_` with NULL); propagates — `al_scalar_optim()` returns it (`-3` on its own `wpar` calloc failure), `al_register()` aborts via `goto al_cleanup` (no "Registration complete", no result), and parallel candidate loops mark a failed optim `AL_BIGVAL`. Cost path also fail-closed: `GA_get_warped_values()` returns 1 on thread-local buffer OOM, `GA_scalar_fitter()` returns `AL_BIGVAL` rather than scoring a stale `avm`; `al_scalar_setup()` leaves `stup->setup=0` on image-buffer OOM, which the three `al_register` sites verify (`stup.setup != AL_SMAGIC → goto al_cleanup`). An optimizer/setup OOM is a clean error exit, never a silent unrefined registration.
- **reface.c/.h** — **`-reface <tmpl> <shell> <weight>`: anonymization by face replacement** (clean-room emulation of AFNI `afni_refacer2 -mode_reface`; no AFNI source copied). Dispatched from coreFLT.c (`nifti_reface_wrap`, DT32 only). Registers the SUBJECT (moving) onto the TEMPLATE (fixed, same well-posed direction as `-deface`) with EITHER engine, back-projects the signed template-space `shell` onto the ORIGINAL subject grid (NN, so -/0/+ labels survive; via `nii_apply_affine` with the inverse matrix), despeckles (`reface_isola` = AFNI `3dcalc -isola`), then composites in place (`reface_apply`): shell>0 → shell × brightness-match `ifac = mean(subject over shell>0 & subject≠0) / mean(shell over shell>0)`; shell==0 → `max(subject,0)`; shell<0 → 0; then a normalized Gaussian blur (FWHM 2.666 mm) INSIDE the shell>0 mask (niimath's own `nifti_smooth_gauss_f32`, NOT AFNI's GPL `3dBlurInMask`). Output stays on the subject grid.
  - **`weight` is REQUIRED** (3rd positional arg, reused as the registration `-weight`). niimath FAILS CLOSED for privacy (refuses to write output) if <10% of the shell face volume mapped into the subject FOV. Coverage fraction uses each image's `|det(coded transform)|` physical voxel volume (`reface_voxvol_mm3`, `xyz_units`-normalized), NOT the pixdim product. **This coverage gate (metric + <10% threshold) is duplicated, non-shared, in the standalone allineate's `do_reface` (main.c) — keep the two semantically byte-aligned when either changes.** `reface_apply` is fail-atomic (bad/mismatched/non-float input, empty overlap, non-finite `ifac`, alloc/blur failure → nonzero, `*result=NULL`, `nim` unchanged) and serial/bit-identical at `-p 1` vs `-p N`. **Shared byte-identically with the standalone**; `reface.o` in `ALOBJS` (no separate flag).
- **qwarp.c/.h** — **`-qwarp <base>`: nonlinear (deformable) registration** — ATTRIBUTED public-domain PORT of AFNI `3dQwarp -blur 0 3` (Robert W. Cox / NIMH, pinned AFNI rev 506e48403), NOT clean-room. AFNI GPL/MCW utilities on this path (`edt_blur.c`, `edt_buildmask.c`, `cs_qmed.c`) are NOT ported — supplied by niimath's own BSD/public-domain code; nothing taken from any GPL AFNI file or `src/GPL/`. Optimizer is Powell NEWUOA. Scope: the nonlinear STAGE ONLY (`qwarp_run`) — `moving` must ALREADY be unifized + skull-stripped + affine-aligned + share the stationary grid (equal dims, agreeing voxel→world; validated tightly, fails hard otherwise). Input and padded volumes must fit both `INT_MAX` and `AL_SIZE_MAX/sizeof(float)`. Equivalent (not bit-identical) to AFNI (Pearson 0.98–0.996). Serial-safe but non-reentrant (NEWUOA process-global context — do not overlap `qwarp_run()` across host threads); OpenMP inside. Dispatched from coreFLT.c (`nifti_qwarp_wrap`, DT32) as an ORDINARY chain op taking a single `<base>` (further ops may follow; NOT terminal). `QWARP=1` only, OFF by default, REQUIRES allineate (not `AL=0`). `QW_VERB=1` per-level trace. **Shared byte-identically with the standalone.**

### Supporting modules
- **dtifit.c** — `--dtifit`: linear diffusion tensor fit emulating FSL `dtifit`. Self-contained TU dispatched early in `main()`, FSL-identical flags (`-k/-m/-r/-b/-o`, `-xflip 0|1|auto`). 7-param log-linear OLS (fit math from AFNI 3dDWItoDT linear path, public domain), reuses `EIG_tsfunc` (tensor.c) for FA/MD/L*/V*. Emulates FSL's determinant-based bvec x-flip. Writes `<base>_{FA,MD,L1,L2,L3,V1,V2,V3,S0,MO,tensor}`; `--wls`/`--kurt` error clearly. **Gotchas:** tensor buffer must use NIfTI planar (volume-major) layout; validate V* with `|cos angle|` not Pearson r (eigenvector sign arbitrary).
- **qc.c** — `--qc <t1> --seg <seg> --csf <i[,j..]> --wm <i[,j..]> [--erode 0|1] [--out qc.tsv]`: MRIQC-style anatomical IQMs from a T1 + hard integer segmentation, written as a wide TSV. Self-contained TU dispatched early in `main()` (guarded by `HAVE_QC`); no tensor/mesh deps; ships native + WASM. Labels: `0`=non-brain (excluded); `--csf`/`--wm` disjoint nonzero sets; every other nonzero label is GM. Validates exact finite integer labels (seg read as float64 to avoid >2^24 aliasing), rejects non-3D/oversized, requires matching dims + spatial transforms. Only air-free metrics: CJV, cnr_noair, snr_{csf,wm,gm,total}, wm2max, efc_brain, icvs_{csf,gm,wm} + vol_*_mm3, summary_{tissue}_{mean,stdv,median,mad,p05,p95,k,n}; omits air/N4/soft-PVM metrics. **Gotchas:** (1) hard-segmentation variant, not a numerical MRIQC clone. Formula plumbing follows MRIQC: CJV uses median + **normalised MAD** (`median(|x−med|)/0.6744897501960817`); CNR/SNR use median + population **stdv**; SNR applies `sqrt(n/(n−1))`. (2) `cnr_noair` drops MRIQC's `σ_bg²` → biased high, not comparable to MRIQC norms (renamed to flag it). (3) `efc_brain` excludes zero voxels from its support. (4) Erosion affects intensity stats only, falls back to raw mask below `QC_MIN_VOX=100`; ICV and mm³ always use RAW counts. (5) `summary_*_n` print as exact integers (`%ld`). (6) Comparator-free quickselect (no `qsort` in the WASM hot path). `release_smoke.py` checks formulas, TSV schema, label validation, unit normalization, large counts, erosion fallback.
- **src/GPL/ (niimath_gpl submodule)** — Optional GPL-2 SPM coregistration, `GPL=1` (`HAVE_GPL`) only. A normal clone fetches zero GPL bytes; `git submodule update --init src/GPL` required (else `$(error)`). Two chain ops via `spmcoreg_niimath.c`: `-spm_coreg <ref>`, `-spm_deface <tmpl> <mask>`. **The license split is the design point:** the GPL module computes ONLY the 6-param rigid transform (`coreg_estimate`; ported SPM `spm_coreg`, in-memory `Vol` adapter, zero file I/O), while BSD code applies it — `nii_reslice_affine` + `nii_apply_deface_mask` (allineate.c, so reslice/`-spm_deface` need `HAVE_ALLINEATE`). `-estimate` is pure BSD header math. The only GPL-aware line in the BSD tree is the gated `extern` hook in `coreFLT.c` (+ `!HAVE_GPL` stub). **`powell.c` (GPL, SPM direction-set Powell) ≠ BSD `powell_newuoa.c` (NEWUOA) — not interchangeable; the SPM golden match depends on it.** Its `SC_TLOCAL` aliases the same `AL_THREAD_LOCAL` header; do not reintroduce a GPL-local `__thread` spelling.
  - **OpenMP gotchas:** (1) per-eval joint-histogram build (`coreg_hist2_cached`, `hist2.c`): each thread fills its own slice of a per-pass `Hist2Scratch`, reduced in fixed thread order (guarded `bs->n > 100000 && nt > 1`). **Chunk by the ACTUAL team size (`omp_get_num_threads()` inside the region), never the requested `hs->nt`** — the runtime can launch fewer threads, so chunking by the requested count silently drops IDs' samples (garbage). (2) histogram smoothing (`smooth_hist_into`) is a real `#pragma omp for` → bit-identical to serial. **Do NOT parallelize the `cost_on` log2 reductions** (NMI denominator etc.): that perturbation hits the final cost directly and shifts the optimum >1 mm / ~1° with thread count — breaks the SPM golden match. One-time pre-smoothing (`conv_axis_parallel`, `smooth.c`) is bit-identical parallel.
  - **WASM** (`GPL=1 make wasm`): needs `-s STACK_SIZE=4194304` (the cost function's 512 KB on-stack joint histogram overflows emcc's 64 KB default); worker OOM caught by an `SC_TLOCAL` setjmp/longjmp guard in `coreg_run()`.
  - **Packaging note:** the published `@niivue/niimath` npm package is now BSD-only (no GPL wasm, no `./gpl` export, no GPL license files, `license: "BSD-2-Clause"`). The GPL C sources, the `GPL=1`/`HAVE_GPL` build option, `-spm_coreg`/`-spm_deface`, and the `makeWasmGpl` script REMAIN for local/historical use (off by default).

### AFNI-fidelity note (allineate coarse search)
The coarse random+grid search (`al_scalar_ransetup`, port of AFNI `mri_genalign_scalar_ransetup`) is deliberately AFNI-faithful, matching values verbatim: `PARAM_MAXTRIAL=29`, `NKEEP=3*PARAM_MAXTRIAL+1=88`, the `nrand≥NKEEP+13=101` floor, `DEFAULT_TBEST=5`/`DEFAULT_TBEST_LPA=17`, and the `vol_src>1.3*vol_base→tbest=PARAM_MAXTRIAL` largeness branch. This cost IS AFNI fidelity — do NOT shrink `NKEEP`/`nrand` for the default case. `PARAM_MAXTRIAL+2` sizes the candidate arrays; max `tfdone` is `tbest+1=30`, so 31 has headroom. ## Memory Management

- **Use plain `malloc`/`calloc`/`free` everywhere.** Do NOT reintroduce `_mm_malloc`/`_mm_free` or `arm_malloc.h` — the 64-byte alignment was never load-bearing (SSE-only 128-bit unaligned loads; malloc's 16-byte alignment already prevents cache-line splits; memory-bandwidth-bound).
- **`nim->data` ownership invariant:** any buffer assigned to `nim->data` MUST come from plain `malloc`/`calloc`, because `nifti_image_free()` and core.c's datatype conversion release it with plain `free()`. On MSVC `_mm_malloc` → `_aligned_malloc`, which `free()` cannot release — plain `free()` on it corrupts the heap (STATUS_HEAP_CORRUPTION 0xC0000374 at teardown). Use **`nii_calloc(count, size)`** (core.c/core.h) for `nim->data`: a fail-closed allocator running `count`×`size` through checked-multiply `nii_mul_size()` and `exit(EXIT_FAILURE)` on overflow/NULL. **`nii_malloc(count, size)`** is the UN-zeroed sibling (same check + exit, plain `malloc`) for a `nim->data` buffer the caller FULLY overwrites before any read (datatype-conversion output loops); use `nii_calloc` if any voxel could be left unwritten (RGB/complex convert buffers stay `calloc`). Callers still pre-compute overflow-prone products with `nii_mul_size()`.
- Kernel arrays: 4-int-per-voxel layout (offset, x, y, weight); plain `malloc`.
- NIfTI images: managed by `nifti_image_free()`.
- MarchingCubes.c: constructor/destructor (`MarchingCubes()`/`FreeMarchingCubes()`) with `clean_all()`.

## Huge image support (> INT_MAX voxels, issue #67)

The core calculator processes images whose 3D `nx·ny·nz` or total 4D `nvox` exceeds `INT_MAX` (≈2.15 G voxels ≈8.6 GB float32) instead of rejecting them.

- **`nvox_t` (core.h)** is the voxel count/index type: **signed** `int64_t` by default (neighborhood/kernel/reverse loops need negative intermediates that unsigned `size_t` would wrap), or `int32_t` under `-DFORCE_INT32_MAX`. `size_t` stays for byte-size allocation only.
- **Scope.** Converted (nvox_t/`size_t`-safe): scalar & image binary ops, per-voxel unary math, temporal reductions (`nifti_dim_reduce`), robust-range percentile, Gaussian smoothing. Everything else — kernel morphology `-fmean`/`-ero`/`-dilF`, `-edge`/`-index`/`-rank`/`-pval`, EDT/tfce/resize/subsamp, allineate/deface/mesh/dtifit/qc/bwlabel/bmp/fdr — keeps int indexing and is **guarded** (rejected on huge input).
- **Fail-closed admission.** A huge image runs only if its op is an exact `strcmp` member of `kHugeSafeOps[]`. `nii_admit_file_before_load()` gates before the payload read (resolving the real first op past output/`-odt`, the RGB ×3/×4 effective count, pass-through/conversion-only); `nii_admit_current_op()` re-checks at the top of every op-loop iteration against the CURRENT image (catches `-restart`, a binary op adopting a huge operand, RGB expansion). stdin/`.nii.zst` skip the pre-read gate and are caught post-load. `nii_reject_oversize_aux()` header-rejects an oversized auxiliary (reslice mask/base, deface template/mask, `-allineate -weight`, bitmap) before its load — EXCEPT a `.nii.zst` auxiliary (no bounded header-only path; caught post-load — accepted limitation). Robust-range/Otsu reject an intensity span their histogram cannot represent (avoids undefined `(int)NaN`). **To promote a guarded op: make its kernel `nvox_t`-clean AND add a `test/huge_smoke.py` case.**
- **`nii_nvox_classify()` (core.c)** is the single geometry validator → {invalid, INT-safe, huge}; `nii_nvox3d_int`/`nii_nvox3d` are its narrow/wide adapters.
- **`-DFORCE_INT32_MAX` on every 32-bit/wasm build (MUST).** wasm32 has a 4 GB ceiling; the `tiny`/`wasm`/`wasm-wasi`/`wasm-emcc-core` Makefile targets and CMake `tiny`/32-bit set it; every huge image is rejected there. Core ops are byte-identical to the pre-#67 build at ≤INT_MAX sizes.
- **Testing.** `test/huge_smoke.py <binary>` — opt-in/manual (~9 GB RAM; not in CI): sparse >INT_MAX NIfTIs. Allocation-free reject cases run in `make test` via `release_smoke.py`.
- **Reach goals (deferred).** (1) Re-add `-Tstd/-Tmedian/-Tperc/-Tar1` to `kHugeSafeOps` (scratch already hoisted per actual OpenMP worker; only a huge_smoke oracle missing). (2) Convert the neighborhood/morphology kernels. Non-goals: registration/mesh/tfce/resize; streaming `.nii.zst` + >2 GB Win64 offsets. `-uthrP` uses the established 1000-bin robust-range approximation (FSL-exact on discrete data) — a separate compatibility decision.

## Known Remaining Issues

1. **NULL checks** — ~26 unchecked malloc/calloc calls remain in MarchingCubes.c (6), oldcubes.c (3), quadric.c (17); meshify.c largely fixed.
2. **Build feature-list drift** — the feature source/define inventory is duplicated across `src/Makefile` (incl. the zlib-free `WASI_SRCS`/`wasm-emcc-core` lists), `src/CMakeLists.txt`, `src/notarize.sh`, and `SuperBuild/SuperBuild.cmake` (which forwards each feature's option to `src/CMakeLists.txt` — a new feature needs its `ENABLE_*` option declared+forwarded here; `OPENMP_XCODE` MUST default to `${USE_OPENMP}` so the Apple universal build's `-DOPENMP_XCODE=OFF` still disables OpenMP). Adding a feature requires touching all of them (a new compute-feature TU also belongs in `WASI_SRCS` and the `wasm-emcc-core` list).
3. **Whole-program `-ffast-math` (all build systems).** Make, CMake (non-MSVC `CMAKE_C_FLAGS`), notarize.sh, and wasm compile the entire program `-ffast-math -fno-finite-math-only`; MSVC stays strict. Registration must round like the standalone/fslmaths goldens (shared `nifti_io` mat44 helpers run during the fit); scoping it to registration TUs made CMake/notarize/wasm diverge. Also covers core ops, GPL `-spm_coreg`, dtifit/tensor — re-validate the SPM golden and dtifit/tensor if you touch those. `-fno-finite-math-only` preserves NaN/Inf detection; fast-math-sensitive finiteness checks use magnitude guards (e.g. `v >= -DBL_MAX && v <= DBL_MAX`).
4. **Prebuilt-object flag stamp.** `allineate.o`/`powell_newuoa.o`/`coreg_fast.o` depend on a flag-signature stamp (`.al_obj_flags` = `CNAME|CFLAGS|AFLAGS`) so `make` → `make OMP=0 all` relinks cleanly with no `make -B` — else a stale object fails to link on `__kmpc_*`/`omp_*`. Extend `AL_OBJ_SIG` for a new object-affecting flag outside `CFLAGS`.
5. **Output-write failures propagate.** `nifti_image_write_status` returns 0/1 (open, short header/data write, compressor/close/pclose errors incl. disk-full at close); `void nifti_image_write` remains a compatibility wrapper. `nifti_save` uses the status API; main dispatch, pass-through, and intermediate `-save` sites propagate it; multi-output `--dtifit`/`-tensor_decomp` OR every status. Preserve — a failed/partial write must report failure, not exit 0.
6. **`nifti_io.c` upstream debt** — LLP64 builds still use `long` in the internal seek wrapper, limiting >2 GiB Windows offsets; a future upstream sync should move that to the platform's 64-bit seek API. Crafted payload-size multiplication, NIfTI-2 header probing, stdin polling, and piped-input cleanup are already hardened locally; preserve those on upgrade.
7. **Registration mislabels metre/micron coordinates as mm.** `al_image_xform`/`al_image_xform_or_pixdim` (allineate.c) return raw NIfTI sform/qform/pixdim coordinates in the header's `xyz_units`, but the registration schedules (translation guards, blur mm), the fast engine bounds, and `-savemat` (`"units":"mm"`) all treat them as world-mm. A legal metre (or micron) image thus gets a 1000× (or 0.001×) physical schedule and a false-unit saved matrix. Practical exposure is ~nil (neuroimaging NIfTIs are mm), which is why this is deferred, NOT that it's unimportant. **The fix is a COORDINATED change, not a one-line seam scale:** reface already normalizes independently via `reface_voxvol_mm3(…, xyz_units)`, so scaling the transform at the seam would DOUBLE-normalize the privacy-critical reface coverage gate — the seam normalization and the reface `reface_voxvol_mm3` de-normalization must land together, be mirrored to `codex/allineate` (both the shared seam and the standalone's own `do_reface`), and ship with a mm/metre/micron equivalence test (the `release_smoke.py` `nifti_header(scale=, xyz_units=)` helper already supports it). mm images must stay byte-identical (factor 1.0).

## Optimization Constraints

- Voxel ops are lean, SIMD-optimized, mostly memory-bandwidth limited. OpenMP is **not the primary optimization target** for core ops (typical usage runs one subject per thread across many subjects). zlib-ng (CMake release baseline, `ZLIB_IMPLEMENTATION=zlib-ng`, ZLIB_COMPAT) gives ~2× `.nii.gz` I/O over stock zlib (correct on MSVC where Cloudflare is not). The Emscripten `wasm` target links it via `WASM_ZLIB`.
- **Allineate reproducibility:** `-allineate` is byte-reproducible **across thread counts** (nt=1/2/4/8) — preserved by the `mfac` thread-local re-apply rule. It is **NOT bit-reproducible across builds**: NEWUOA + `-ffast-math` means a codegen change can flip the optimizer to a neighboring equally-valid optimum (sub-voxel parameter shift, ~1% in a few edge voxels). Quality unchanged (cost and base-correlation match to 4+ digits) — do NOT treat `-allineate` output as a byte-stable golden across versions. `gpl-build.yml` gates registration by QUALITY (correlation floor + improvement-over-baseline via `reg_quality.py`, fails closed on empty/constant/non-finite), not a byte diff. `-deface`/`-spm_deface` reslice via `nii_reslice_affine` (not the fused path) and stay byte-stable.

### WASM performance pitfalls (two hard-won rules)
1. **No `qsort`+comparator on large or per-voxel arrays in WASM-targeted code.** emscripten/musl `qsort` calls the comparator via `call_indirect` per comparison (~100× slower than native — can make the WASM build appear to hang). Use comparator-free: **quickselect** for a single value (`al_select_rank`, `select_kth_flt`, `uf_select`), **insertion sort** for genuinely small fixed N only (NOT a per-voxel neighborhood — O(n²) per voxel), or **heapsort** for a full order on large arrays (`heapsort_sortIdx`). The only remaining `qsort` is `qsort_floatint` on ~46-element lists.
2. **WASM allineate MUST be compiled `-ffast-math` (matching native)**, or the cost-function reduction rounds differently and NEWUOA/Powell converges to a worse optimum (`-deface` masked 37% vs 60% native). The `wasm:` target and its prebuilt `al_wasm.o`/`pn_wasm.o`/`cf_wasm.o` use whole-program `-ffast-math -fno-finite-math-only`. (`-msimd128` adds only ~3% — not worth the golden-match risk.)

## Code Conventions
- C99 with extensive `#ifdef` for conditional compilation.
- Template pattern: coreFLT.c compiled as both float32 and float64 via macro inclusion.
- Naming: `nifti_*` for NIfTI operations, `nii_*` for internal helpers.
- Explicit SIMD (Intel intrinsics via `immintrin.h`) only on `__x86_64__`; ARM/WASM use scalar fallbacks (clang `-O3` auto-vectorizes to NEON just as fast; memory-bandwidth bound). No `sse2neon.h` shim.
- Error returns: `EXIT_SUCCESS`/`EXIT_FAILURE`.
